Stream a Call's audio through an authenticated, call-scoped media WebSocket.

## Before you start

[Accept the Call](/calls/answer) before creating media. A user app uses WebRTC; an agent backend uses the WebSocket transport described here. Keep its model session and playback state in a runtime keyed by `call.id`.

## Connect the media stream

Create the agent's connection with its ordinary Agent Token:

<CodeGroup>
```typescript TypeScript SDK
const { connection } = await relay.calls.connections.create(callId, {
  transport: "websocket",
});
```

```bash cURL
curl -sS -X POST \
  "https://api.staging.relayapp.im/v1/calls/$CALL_ID/connections" \
  -H "Authorization: Bearer $RELAY_AGENT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"transport":"websocket"}'
```
</CodeGroup>

The `201` response supplies an ephemeral Relay grant:

```json Agent connection
{
  "connection": {
    "id": "01995978-1000-7000-8000-000000000005",
    "call_id": "01995978-1000-7000-8000-000000000001",
    "transport": "websocket",
    "url": "wss://api.staging.relayapp.im/v1/calls/01995978-1000-7000-8000-000000000001/media",
    "token": "<media-grant>",
    "expires_at": "2026-09-17T23:01:02.000Z",
    "audio_format": {"encoding": "pcm_s16le", "sample_rate": 48000, "channels": 2}
  }
}
```

Open the returned URL with `Authorization: Bearer <media-grant>`. The grant is scoped to one Call, Contact, and connection, expires after 60 seconds, and is consumed by a successful upgrade. Relay checks current call permission and the connection's Agent Token before upgrading.

```http WebSocket upgrade
GET /v1/calls/01995978-1000-7000-8000-000000000001/media HTTP/1.1
Host: api.staging.relayapp.im
Upgrade: websocket
Connection: Upgrade
Authorization: Bearer <media-grant>
Sec-WebSocket-Version: 13
Sec-WebSocket-Key: <client-generated-key>
```

Use the grant only in the header, keep it out of logs, and use the returned URL without query parameters. SFU credentials remain inside Relay.

## Read the frames

The socket carries JSON text control frames and binary audio frames.

| Direction | Frame | Meaning |
| --- | --- | --- |
| Relay → agent | `start` | Confirms Call, connection, and audio format |
| Relay → agent | `ready` | Both audio directions are attached |
| Either direction | Binary PCM | Audio bytes in the negotiated format |
| Agent → Relay | `clear` | Discards pending generated speech |
| Relay → agent | `ended` | Terminal reason, followed by a normal socket close |

```json Start
{"type":"start","call_id":"01995978-1000-7000-8000-000000000001","connection_id":"01995978-1000-7000-8000-000000000005","audio_format":{"encoding":"pcm_s16le","sample_rate":48000,"channels":2}}
```

```json Ready
{"type":"ready"}
```

Wait for `ready` before sending audio. Report your side's readiness once its audio path is ready; the user app reports its own side separately:

<CodeGroup>
```typescript TypeScript SDK
const { call } = await relay.calls.connected(callId);
```

```bash cURL
curl -sS -X POST \
  "https://api.staging.relayapp.im/v1/calls/$CALL_ID/connected" \
  -H "Authorization: Bearer $RELAY_AGENT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{}'
```
</CodeGroup>

```http Readiness response
HTTP/1.1 200 OK
Content-Type: application/json
```

The body is a [Call snapshot](/api-reference/resources/calls/overview). It remains `connecting` until both sides have acknowledged ready media.

## Send bounded audio

**Send raw PCM bytes, not base64, JSON audio, or a provider envelope.**

| Property | Value |
| --- | --- |
| Encoding | Signed 16-bit little-endian PCM, `pcm_s16le` |
| Sample rate | 48,000 Hz |
| Channels | 2, interleaved stereo |
| Sample alignment | Non-empty frames with byte length divisible by 4 |
| Maximum agent binary frame | 32 KiB, 32,768 bytes |
| Relay output pacing | One 20 ms frame of 3,840 bytes per tick |
| Maximum pending output | 500 ms, 96,000 bytes |

Convert your model's audio to this format in your backend. Pace output at playback speed rather than sending an entire utterance at once. Relay zero-pads a final partial playback frame; invalid audio or an overflowing queue fails the call.

On interruption, cancel the current model response, discard your own unsent chunks, and send:

```json Clear pending speech
{"type":"clear"}
```

`clear` discards Relay's pending playback. It cannot retract audio already sent. Keep listening to incoming audio while generated output is cleared.

## End and release resources

Either member can hang up:

<CodeGroup>
```typescript TypeScript SDK
const { call } = await relay.calls.end(callId);
```

```bash cURL
curl -sS -X POST \
  "https://api.staging.relayapp.im/v1/calls/$CALL_ID/end" \
  -H "Authorization: Bearer $RELAY_AGENT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{}'
```
</CodeGroup>

```http Hangup response
HTTP/1.1 200 OK
Content-Type: application/json
```

The response contains the ended Call. Ringing hangup uses `canceled`; an accepted call uses `completed`. Repeated terminal actions retain the existing state and reason.

```json Ended
{"type":"ended","reason":"completed"}
```

On `ended`, `call.ended`, socket close, or a setup failure, cancel model work, stop playback and timers, clear local buffers, and close both connections. Relay closes its media resources when the call ends. Blocks, contact removal, and Agent Token revocation also end affected calls.

## When it fails

| Status or signal | Action |
| --- | --- |
| `401` | Check the control Agent Token or the media grant's expiry, use, and token authority |
| `403` | Stop setup: a block or relationship change removed call permission |
| `409` | Read the Call; readiness or peer-track setup may still be pending, or the call has ended |
| `503` | Retry temporary media failures only while setup remains valid |
| `ended`, close, or error | Release the per-call runtime and model session |

For WebRTC, [subscribe](/api-reference/calls/receive-the-other-sides-audio) returns `409` until the other audio track is ready. Retry during setup, then submit the answer through [renegotiate](/api-reference/calls/finish-audio-negotiation). Keep recovery bounded by the Call's [setup leases](/calls#lifecycle), rather than permanent polling.
