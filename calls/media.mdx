Stream a Call's audio through an authenticated, call-scoped audio WebSocket.

## Before you start

[Join the call room](/calls/answer#join-the-call-room) before opening audio. A user app uses WebRTC; an agent backend uses the WebSocket transport described here. Keep its model session and playback state in a runtime keyed by `call.id`.

## Open the audio socket

The grant arrives inside the room's `roomState` frame, in the `media` field, on the agent's socket only:

```json roomState.media
{
  "url": "wss://api.staging.relayapp.im/v1/calls/01995978-1000-7000-8000-000000000001/media",
  "token": "<media-grant>",
  "expires_at": "2026-09-17T23:01:02.000Z",
  "audio_format": {"encoding": "pcm_s16le", "sample_rate": 48000, "channels": 2}
}
```

Open `url` with `Authorization: Bearer <media-grant>`. The grant is scoped to one Call and Contact, expires at `expires_at`, and is consumed by a successful upgrade. Relay checks current call permission before upgrading.

<CodeGroup>
```typescript TypeScript SDK
import WebSocket from "ws";

let audio: WebSocket | undefined;
const room = relay.calls.room(callId);
room.on("roomState", (state) => {
  if (!state.media || audio) return;
  audio = new WebSocket(state.media.url, {
    headers: { Authorization: `Bearer ${state.media.token}` },
  });
});
```

```bash cURL
curl -sS -i --no-buffer "$MEDIA_URL" \
  -H "Authorization: Bearer $MEDIA_GRANT" \
  -H 'Connection: Upgrade' -H 'Upgrade: websocket' \
  -H 'Sec-WebSocket-Version: 13' \
  -H "Sec-WebSocket-Key: $(openssl rand -base64 16)"
```
</CodeGroup>

```http WebSocket upgrade
GET /v1/calls/01995978-1000-7000-8000-000000000001/media HTTP/1.1
Host: api.staging.relayapp.im
Upgrade: websocket
Connection: Upgrade
Authorization: Bearer <media-grant>
Sec-WebSocket-Version: 13
Sec-WebSocket-Key: <client-generated-key>
```

Use the grant only in the header, keep it out of logs, and use `url` without query parameters. SFU credentials remain inside Relay.

## Read the frames

The socket carries JSON text control frames and binary audio frames.

| Direction | Frame | Meaning |
| --- | --- | --- |
| Relay → agent | `start` | Confirms Call, connection, and audio format |
| Relay → agent | `ready` | Both audio directions are attached |
| Either direction | Binary PCM | Audio bytes in the negotiated format |
| Agent → Relay | `clear` | Discards pending generated speech |
| Relay → agent | `ended` | Terminal reason, followed by a normal socket close |

```json Start
{"type":"start","call_id":"01995978-1000-7000-8000-000000000001","connection_id":"01995978-1000-7000-8000-000000000005","audio_format":{"encoding":"pcm_s16le","sample_rate":48000,"channels":2}}
```

```json Ready
{"type":"ready"}
```

Wait for `ready` before sending audio. Then report your side over the room socket; the user app reports its own side separately:

<CodeGroup>
```typescript TypeScript SDK
await room.connected();
```

```json Room frame
{"type":"connected"}
```
</CodeGroup>

The room answers with `roomState`. The Call stays `connecting` until both sides have sent `connected`, then reads `active` with `connected_at` set.

## Send bounded audio

**Send raw PCM bytes, not base64, JSON audio, or a provider envelope.**

| Property | Value |
| --- | --- |
| Encoding | Signed 16-bit little-endian PCM, `pcm_s16le` |
| Sample rate | 48,000 Hz |
| Channels | 2, interleaved stereo |
| Sample alignment | Non-empty frames with byte length divisible by 4 |
| Maximum agent binary frame | 32 KiB, 32,768 bytes |
| Relay output pacing | One 20 ms frame of 3,840 bytes per tick |
| Maximum pending output | 500 ms, 96,000 bytes |

Convert your model's audio to this format in your backend. Pace output at playback speed rather than sending an entire utterance at once. Relay zero-pads a final partial playback frame; invalid audio or an overflowing queue fails the call.

On interruption, cancel the current model response, discard your own unsent chunks, and send:

```json Clear pending speech
{"type":"clear"}
```

`clear` discards Relay's pending playback. It cannot retract audio already sent. Keep listening to incoming audio while generated output is cleared.

## End and release resources

Either member can hang up, over the room socket or the REST route:

<CodeGroup>
```typescript TypeScript SDK
await room.end();
// Without a room socket: await relay.calls.end(callId);
```

```bash cURL
curl -sS -X POST \
  "https://api.staging.relayapp.im/v1/calls/$CALL_ID/end" \
  -H "Authorization: Bearer $RELAY_AGENT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{}'
```
</CodeGroup>

The room sends `ended` on every socket and closes them. Ringing hangup by the caller uses `canceled`; an accepted call uses `completed`. Repeated terminal actions retain the existing state and reason.

```json Ended
{"type":"ended","reason":"completed"}
```

On `ended`, `call.ended`, socket close, or a setup failure, cancel model work, stop playback and timers, clear local buffers, and close the room, audio, and model connections. Relay closes its media resources when the call ends. Blocks, contact removal, and Agent Token revocation also end affected calls.

## When it fails

| Status or signal | Action |
| --- | --- |
| `401` | Check the media grant's expiry and use, or the Agent Token on the room socket |
| `403` | Stop setup: a block or relationship change removed call permission |
| `error` frame `media_unavailable` | Relay could not create the audio path; the call ends `failed` |
| `ended`, close, or error | Release the per-call runtime and model session |

Keep recovery bounded by the Call's [setup leases](/calls#lifecycle). The room closes the socket after every terminal `ended`, so a reconnect after that answers `410`.
