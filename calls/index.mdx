A person calls your agent from the Relay app, and your agent answers by joining the call's room. Relay sends `call.created` on the webhook or WebSocket your agent already uses for messages, and carries the voice and camera over WebRTC. Your backend runs the agent; it registers nothing for calls.

```mermaid
sequenceDiagram
  participant P as Person (Relay app)
  participant R as Relay
  participant A as Your agent
  P->>R: Calls your agent
  R->>A: call.created, status ringing
  A->>R: Joins the call room (this answers)
  R->>A: call.updated, status in-progress
  P-->>A: Voice and camera over WebRTC
  A-->>P: Voice and video over WebRTC
  A->>R: Ends the call, or the person hangs up
  R->>A: call.ended, status completed
```

## Answer a call

When `call.created` arrives with `status: "ringing"`, join the room for `call.id` within 32 seconds. Joining is the answer: the call becomes `in-progress`. A call nobody joins ends `no-answer`.

Each package below joins the room and runs the WebRTC connection for you, so your code never handles SDP, ICE or TURN credentials. Choose the one that matches your agent's runtime.

    ```python
    import os

    from pipecat.frames.frames import TTSSpeakFrame
    from pipecat.pipeline.pipeline import Pipeline
    from pipecat.pipeline.worker import PipelineWorker
    from pipecat.workers.runner import WorkerRunner
    from relaymessenger_pipecat import RelayParams, RelayTransport


    async def answer(call_id: str) -> None:
        transport = RelayTransport(
            api_key=os.environ["RELAY_AGENT_TOKEN"],
            call_id=call_id,
            base_url="https://api.staging.relayapp.im",
            params=RelayParams(audio_in_enabled=True, audio_out_enabled=True),
        )
        # stt, llm and tts are your Pipecat services.
        worker = PipelineWorker(Pipeline([transport.input(), stt, llm, tts, transport.output()]))

        @transport.event_handler("on_first_participant_joined")
        async def greet(transport, participant_id):
            await worker.queue_frame(TTSSpeakFrame("Hello! How can I help?"))

        @transport.event_handler("on_participant_left")
        async def hang_up(transport, participant_id, reason):
            await worker.cancel()

        runner = WorkerRunner()
        await runner.add_workers(worker)
        await runner.run()
    ```

## Decline a call

To decline a ringing call, end it without joining. A call your agent ends while it rings becomes `no-answer`.

<CodeGroup>
```typescript TypeScript SDK
await relay.calls.end(callId);
```

```bash cURL
curl -sS -X POST "https://api.staging.relayapp.im/v1/calls/$CALL_ID/end" \
  -H "Authorization: Bearer $RELAY_AGENT_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{}'
```

## End a call

End the call for both sides with `end()` on the transport (`transport.end()` in Pipecat), with `relay.calls.end(callId)`, or with `POST /v1/calls/{callId}/end`. An answered call becomes `completed`. `close()` in TypeScript and `aclose()` in Python only clean up locally; the call goes on until someone ends it.

## The call room

The room is a WebSocket at `GET /v1/calls/{callId}/room`, opened with your Agent Token. It carries only signaling: JSON frames with WebRTC session descriptions. Audio and video travel over WebRTC, never through this socket.

1. Send `{"type":"join"}` when the socket opens. Relay answers with `iceServers` and then `roomState`.
2. Send an `offer` that publishes one track named `audio`. Relay answers with `answer`. The first time your camera turns on, send another `offer` that adds a track named `video`.
3. Send `connected` when your peer connection is connected.
4. Relay sends an `offer` for each of the person's tracks. Reply with `answer`.

The [room reference](/api-reference/calls/join-a-call-room) lists every frame. Use one of the packages above unless you run your own WebRTC stack.

## The call in the chat

Relay writes one system message into the chat with `is_system_message: true` and `system_event.type: "call"`. The marker exists from the moment the call is placed; `call.status` carries its state. The event's `actor` is the caller, its `subject` is the callee, and its [`call` object](/api-reference/resources/messages/overview#system-events) carries its current state.

`parts[0].value` is a plain sentence such as "Atlas called you" or "Atlas called you with no answer". The Relay app shows it as a call bubble on the caller's side. Agents receive it like any other system message and should not reply to it.

## The Call object states

`status` uses Twilio's call status words. `ringing` and `in-progress` are live. The other five are terminal and set `ended_at`.

| Status | Meaning |
| --- | --- |
| `ringing` | Relay is waiting for the person or agent being called to join the room. |
| `in-progress` | The person or agent being called joined the room within 32 seconds. |
| `completed` | An answered call ended. |
| `no-answer` | Nobody joined within 32 seconds, or the recipient declined. |
| `canceled` | The caller ended the call while it was ringing. |
| `busy` | The person was already on another call. An agent is never busy. |
| `failed` | Relay could not connect or keep the call. |
