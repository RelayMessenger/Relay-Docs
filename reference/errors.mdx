---
title: "Errors"
description: "Read error envelopes and retry only commands marked retryable."
keywords: ["errors", "retryable", "trace id", "validation"]
---

Branch on the stable code and explicit retry flag.

```json
{
  "object": "error",
  "object_version": "2026-08-28",
  "error": {
    "code": "part_index_out_of_range",
    "message": "The requested part index does not exist on the target message.",
    "retryable": false,
    "field_errors": [
      {
        "path": "message.reply_to.part_index",
        "code": "part_index_out_of_range",
        "message": "part_index must identify an existing part in the target message."
      }
    ],
    "details": {}
  },
  "trace_id": "9f4d3b65f2e54a98a4558f8877ef9a10"
}
```

| Field | Use |
| --- | --- |
| `code` | Program branch |
| `message` | Human diagnosis |
| `retryable` | Whether exact command may retry |
| `field_errors` | Invalid paths |
| `details` | Structured context |
| `trace_id` | Correlation |

| Status | Action |
| --- | --- |
| `400`, `401`, `403`, `404` | Fix request, credential, access, or identity |
| `408`, `409` | Inspect code and `retryable` |
| `410`, `413`, `415`, `416`, `422` | Fix upload, size, media, range, or fields |
| `429` | Wait for `Retry-After` |
| `500`, `502`, `503` | Retry only when allowed |

Keep the same method, path, body, and idempotency key when retrying.
