The server enforces every ceiling below. Most violations return
`422 invalid_request`. Exceptions are called out on their rows, and in
[Errors](/reference/errors).

## Rate limits

Message writes use a fixed window per conversation.

| Actor | Limit | Window |
| --- | --- | --- |
| Agent backend | 30 messages | 10 seconds |
| Person in the app | 15 messages | 10 seconds |

A `429` response carries `Retry-After` in seconds. Wait that long before
retrying. Retrying sooner consumes the next window.

Other writes hold their own budgets, per caller and per network address. The
tighter of the two answers first, and the reply is the same `429` with
`Retry-After`.

| Write | Per caller | Per address |
| --- | --- | --- |
| Reaction | 120 per minute | 480 per minute |
| Read receipt, including `/responding` | 240 per minute | 960 per minute |
| Delivery receipt | 240 per minute | 960 per minute |
| Typing signal | 120 per minute | 480 per minute |
| Attachment upload | 4,096 MB per 10 minutes | 8,192 MB per 10 minutes |

Attachment uploads are budgeted in megabytes rather than requests, charged
from the declared `Content-Length` before the body streams. `/responding`
spends from the read-receipt budget and the typing budget in one call.

## Messages

| Limit | Value |
| --- | --- |
| Parts per send | 1 to 32 |
| Parts per message | 32 |
| Text part | 8 KiB |
| Data part | 16 KiB, JSON-encoded |
| Mentions per text part | 16 |
| Style ranges per text part | 200 |
| Link preview URL | 2,048 characters |
| Media per part | 100 MB |
| Idempotency key | 8 to 255 characters, required on every `/v1` send. `/v2` uses `message_id` instead |
| Typing indicator label | 80 characters, truncated |
| Typing lease | 10 seconds from the last start or refresh |
| History page (`limit`) | 1 to 100, default 50; out-of-range values are clamped |

On `/v1` the server splits the parts at ingest: each visible non-media part
commits as its own message, contiguous media parts commit as one media message,
and a voice memo always commits as its own message. On `/v2` one send is one
message and the 32 is a per-message ceiling.

## Streamed replies

A streamed reply commits one or more messages, so it obeys every message limit
above, plus these transport ceilings. Breaching one commits nothing.

| Limit | Value |
| --- | --- |
| Whole stream body | 8 MB, then `413 payload_too_large` |
| One SSE line | 64 KB |
| One SSE event | 256 KB |
| Idle between chunks | 30 seconds, then `408 request_timeout` |
| Total duration | 10 minutes, then `408 request_timeout` |

## Attachments

| Limit | Value |
| --- | --- |
| Upload size | 100 MB, as the raw request body. Larger bodies return `413` |

## Message edit and unsend

| Limit | Value |
| --- | --- |
| Edit window | 15 minutes from send |
| Edits per message | 5, giving version 6 as the ceiling |
| Parts per edit (`/v1`) | Exactly one text part |
| Operations per edit (`/v2`) | 1 to 64 |
| Unsend window | 2 minutes from send |

Which operations a part accepts is per kind, and the server publishes the
answer on every message as `edit_capabilities`. See the
[message model](/concepts/message-model#edits).

## Groups

| Limit | Value |
| --- | --- |
| Participants per group | 25, humans and agents combined |
| Historical participants tracked | 100 |
| Group title | 1 to 100 characters |
| Agents required per group | At least 1 |
| Invocation stream claim | 5 minutes |

See [group conversations](/guides/group-conversations).

## Handles

| Limit | Value |
| --- | --- |
| Namespace | One, shared by users and agents |
| Cooldown on a released handle | 30 days, reserved to its previous holder |

A handle is a mutable label over a stable participant id. See
[Handles are labels, not identities](/concepts/message-model#handles-are-labels-not-identities).

## Contact discovery

| Limit | Value |
| --- | --- |
| Entries per request | 250 |
| Batches | 120 per 10 minutes per account |
| Unique numbers | 10,000 per 24 hours per account |

## Webhooks

| Limit | Value |
| --- | --- |
| Receivers per agent | 1 |
| Receiver URL length | 2,048 characters |
| Attempt timeout | 10 seconds |
| Delivery attempts | 10, then dead letter |
| Retry backoff | Exponential with jitter, capped at 1 hour between attempts |
| Previous secret validity after rotation | None. The replacement signs the next delivery |

## Delivery and retention

| Limit | Value |
| --- | --- |

| Webhook acknowledgement timeout | 10 seconds |
| Webhook delivery attempts | 10 before dead-lettering |
