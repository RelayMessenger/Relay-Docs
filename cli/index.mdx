Connect and manage an agent from your terminal.

## Before you start

- Use Node.js `22.22.3` or newer.
- Use an interactive terminal when a command asks for input.

## Install

```bash
npm install --global relaymessenger@staging
relaymessenger --help
```

```bash
npx relaymessenger@staging --help
```

The Relay CLI saves agent profiles on this computer and gives you commands for connection, diagnostics, and the API.

No environment variables are needed; RELAY_AGENT_TOKEN is honored in scripts only.

### Run the examples

```bash
relaymessenger connect codex
relaymessenger watch
relaymessenger agents create --json
```

| Runtime | Target | What Connect sets up |
| --- | --- | --- |
| Claude Code | `claude-code` | Relay channel and a launch-and-reply check |
| Codex | `codex` | Relay MCP server registration |
| Cursor | `cursor` | Relay MCP server configuration |
| OpenCode | `opencode` | Relay MCP server configuration |
| Cline | `cline` | Relay MCP server configuration |
| VS Code | `vscode` | Relay MCP server configuration |
| Gemini CLI | `gemini-cli` | Relay MCP server registration |
| Claude Desktop | `claude-desktop` | Relay MCP server configuration |
| Hermes | `hermes` | Relay channel plugin and credentials |
| OpenClaw | `openclaw` | Relay channel plugin and credentials |

Connect proves an answer only for Claude Code today. The other nine targets finish with `Relay is ready for X`; start the runtime and verify a reply yourself.

## What you get back

Captured with `relaymessenger@0.1.6-staging.6`. Help output describes the command; it does not prove a live reply.

```text captured-output
Usage: relaymessenger [options] [command]

Relay: give the agent on your computer a phone number.

Examples:
  relaymessenger connect codex          connect Codex to a new Relay agent
  relaymessenger watch                  see messages arrive and the agent reply
  relaymessenger agents create --json   create an agent from a script

Get started:
  connect [options] [agent]      connect a coding agent to Relay, new or by token, and prove it answers
Every day:
  watch [handle]                 see messages arrive and the agent reply, live
  doctor [options]               check every saved agent and this computer, and say what to fix

Everything else:
```

## When it fails

| Exit | Meaning |
| --- | --- |
| 0 | Command succeeded. |
| 1 | Failure outside classes 2 through 4. |
| 2 | Unknown option, required input unavailable, or terminal required. |
| 3 | Named resource does not exist. |
| 4 | Required token is missing or rejected. |

With `--json`, command failures use an object on stderr with `error`, `code`, and `next_step`. The agents list command also carries failures in individual result entries.
