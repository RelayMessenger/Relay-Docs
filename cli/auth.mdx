Use `relay login` for normal CLI sign-in. It opens Relay Console's device browser flow and stores the session on this computer.

```bash
relay login
relay whoami
```

On a first sign-in, Relay asks for your Personal organization name and namespace. The namespace is selectable, and Relay derives an initial value from the organization name. You can also pass `--organization-name`, `--namespace`, and the optional `--website` in a non-interactive run.

```bash
relay login --organization-name "Acme" --namespace acme --website https://acme.example
```

Credentials are stored in Relay's private local configuration. The CLI reports `token: "stored"` instead of printing a credential. `relay logout` removes the saved Agent Token profile; it does not delete the Agent.

## Import an existing Agent Token

Use the hidden compatibility command only when an Agent already exists and you already have its token.

```bash
printf '%s\n' "$RELAY_AGENT_TOKEN" | relay auth login --with-token
relay auth status
```

The token is read from stdin and saved privately. The imported-token path can use `RELAY_AGENT_TOKEN`; normal `relay login` does not require that variable.

## Local runtime development

Use `relay connect` when you are connecting a runtime on this computer. A Console-created Agent is saved with its runtime credential locally, then `connect` configures the selected local integration. A deployed Agent that is owned and run by Relay Console does not need a local runtime connection.
