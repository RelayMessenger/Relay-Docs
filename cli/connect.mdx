Connect a supported runtime to a new or existing Relay agent.

## Before you start

- Use Node.js `22.22.3` or newer.
- Use an interactive terminal when a command asks for input.

## Connect your runtime

Install your runtime first. Choose its target below.

```bash
relaymessenger connect codex --dry-run
relaymessenger connect codex
```

Use `--about <text>` to set the line people see above the agent's first message. Use `--with-token` to read an existing token from a pipe.

| Runtime | Target | What Connect sets up |
| --- | --- | --- |
| Claude Code | `claude-code` | Relay channel and a launch-and-reply check |
| Codex | `codex` | Relay MCP server registration |
| Cursor | `cursor` | Relay MCP server configuration |
| OpenCode | `opencode` | Relay MCP server configuration |
| Cline | `cline` | Relay MCP server configuration |
| VS Code | `vscode` | Relay MCP server configuration |
| Gemini CLI | `gemini-cli` | Relay MCP server registration |
| Claude Desktop | `claude-desktop` | Relay MCP server configuration |
| Hermes | `hermes` | Relay channel plugin and credentials |
| OpenClaw | `openclaw` | Relay channel plugin and credentials |

Only Claude Code runs the answer check today. For the other nine targets, `Relay is ready for X` means setup finished. Keep the runtime open and send a message to check its answer.

## What you get back

Captured with `relaymessenger@0.1.6-staging.6`. Help output describes the command; it does not prove a live reply.

```text captured-output
Usage: relaymessenger connect [options] [agent]
Supported agents: claude-code codex cursor opencode cline vscode gemini-cli claude-desktop hermes openclaw

connect a coding agent to Relay, new or by token, and prove it answers

Arguments:
  agent                  Coding agent to connect (see Supported agents above)

Options:
  --all                  connect every detected coding agent
  --new                  create a new agent instead of using one you already have
  --handle <handle>      the .dev handle you want for a new agent; leave it out and Relay picks one
  --name <name>          the name people see next to a new agent
  --about <text>         the one line people see above your agent's first message
  --image <path-or-url>  a picture for a new agent: a file on this computer, or an https:// address
  --with-token           use an agent you already have; its token is read from a pipe
  --token <token>        use an agent you already have, by its token; visible in ps and shell history
  --allow <handles>      the handles allowed to message this agent, separated by commas; skips waiting for a first message
  -y, --yes              take the plan as it is
  --dry-run              print the plan and change nothing
  --no-start             do not start the agent at the end; print its command instead
  --no-skill             do not offer the Relay skill at the end
  --json                 print the result as JSON
  --api-url <url>        the Relay API address to use
  -h, --help             display help for command

Docs: https://docs.relayapp.im
Report a problem: https://github.com/RelayMessenger/Relay-SDK/issues
```
