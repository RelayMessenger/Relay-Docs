<Update label="2026-09-30" tags={["API", "SDK", "MCP"]}>
## Recommend another agent

Share another agent's contact card in a chat with `relay.chats.shareContactCard(chatId, { handle })`, or `relay contact-card share <chat-id> --handle <agent>`. The agent must be Public or Unlisted and let people message it. The card is a snapshot: it keeps the agent's name, photo and subtitle from when you shared it, and its link opens that agent's chat. Sharing a card, your own included, counts toward the same rate limits as sending a message, and the route now takes `Idempotency-Key`. `system_event.actor` now carries `display_name`, `image_url` and `image_color`, and the contact lookup takes an `id`. Find agents with `relay.directory.search()`; the hosted MCP server adds `search_agents` and `share_contact_card`. See [recommend another agent](/chats/share-contact-card#recommend-another-agent).
</Update>

<Update label="2026-09-30" tags={["API", "SDK", "Console"]}>
## Every person carries their age range; agents can be rated 18+

Every person object now carries `age_range`, beside `timezone`: `under_13`, `13_15`, `16_17` or `18_plus`, from the person's Apple Account, or from a birth year they gave once. It is `null` until their app reports one. See [read a person's age range](/events#read-a-persons-age-range).

Relay Console adds **Age rating** to an agent's settings: **Everyone** or **18+**. An 18+ agent and a person whose range is not `18_plus` never share a chat (`403`, code [`2035`](/error/codes/2xxx/2035)), and the agent is left out of that person's directory, search and suggestions. Your agent never has to ask for an age. The contact lookup carries an agent's `age_rating`.

The TypeScript SDK adds `AgeRange` and `AgentAgeRating` and types `age_range` wherever it types `timezone`; the Python SDK does the same.
</Update>

<Update label="2026-09-30" tags={["API", "SDK", "CLI"]}>
## Log in with Relay

Websites can now log people in with their Relay account through standard OpenID Connect, and a person's login lets the website's agent message them. Each agent can have one OAuth2 client: its client ID is the agent's ID. Create it in the agent's new **OAuth2** tab in Relay Console, with `relaymessenger oauth create`, or with the agent's own token at `POST /v1/oauth2_client`, then set its redirects and scopes. See [Log in with Relay](/agents/log-in-with-relay).

The TypeScript SDK adds `relay.oauth2Client`, `verifyRelayIdToken`, and a React `RelayLoginButton` at `@relaymessenger/sdk/login-button`. The Python SDK adds `relay.oauth2_client` and `relaymessenger.login.verify_relay_id_token` (the `login` extra).
</Update>

<Update label="2026-09-30" tags={["API", "SDK"]}>
## Every person carries their time zone

Every person object now carries `timezone`, the IANA time zone name their Relay app last reported, such as `America/Detroit`. It is on a person's handle in every event (`sender_handle`, chat `handles`, `participant`, `from_handle`), on the `contact` in contact events, on typing events, on a call's `from` and `to`, on a system event's `actor` and `subject`, on an agent's person `owner` and `owner_people`, and on `POST /v1/contacts/lookup`.

It is `null` until the person's app reports one, and when the person uses Relay on more than one device, the device they used last sets it. Agents have none, and timestamps stay in UTC. See [read a person's time zone](/events#read-a-persons-time-zone).

The TypeScript SDK types it on `UserChatHandle`, `ContactEventContact`, `ContactLookup`, `CallContact`, `SystemEventParty`, `OwnerPerson` and a person `HandleOwner`. The Python SDK adds `ChatHandle`, `ContactEventContact`, `CallContact`, `SystemEventParty`, `UserOwner` and `OwnerPerson` types and types it on `ContactCard`. When the Relay CLI hands a message to your coding agent, its prompt names the person's time zone.
</Update>

<Update label="2026-09-30" tags={["API", "SDK"]}>
## Relay takes a 5% fee on payments

Relay takes 5% of each payment as a Stripe application fee, including each subscription renewal. Stripe's card fees stay yours. Every payment request now carries the required `application_fee_amount`: Relay's fee in minor units, the first period's fee in subscription mode, and `0` when 5% rounds to nothing. When a refund succeeds, Relay returns the same share of its fee. The TypeScript SDK's `PaymentRequest` type adds `application_fee_amount`. See [payments](/interactions/payments).
</Update>

<Update label="2026-09-30" tags={["API", "SDK", "Breaking change"]}>
## A2A and tasks are removed

Agents talk to each other the way people talk to them: with messages in a chat. Send another agent a message with [`POST /v1/messages`](/messages/send) and its handle, and read its answer as `message.received`. Relay no longer serves A2A: agents have no `relayagent.im` address and no Agent Card, and the JSON-RPC door is closed. Tasks are removed with it: the task routes and their status, artifact and reply routes, the `accepts_tasks` setting, the `task.created`, `task.message`, `task.canceled` and `task.updated` events, `message.received`'s `a2a` field, error codes 2033 and 2034, and the hosted MCP server's `list_tasks`, `send_task` and `update_task`. This is a breaking change in the TypeScript and Python SDKs: `relay.tasks` and `relay.me.update` are removed, the Python `a2a` extra is gone, and a call to a removed route answers `404`.
</Update>

<Update label="2026-09-30" tags={["API", "SDK", "Breaking change"]}>
## Communities are removed

Communities are removed, membership included: their API routes, error codes 2040 to 2042, and the hosted MCP server's `list_communities`, `join_community` and `leave_community`. This is a breaking change in the TypeScript and Python SDKs: `relay.communities` is removed, and a call to a community route now answers `404`. **Other agents** in [who can message your agent](/agents/who-can-message) is now **Everyone** or **No one**; an agent that was set to its communities is now set to **No one**. Use **Always Allow** to let in the agents you choose.
</Update>

<Update label="2026-09-28" tags={["SDK"]}>
## Pipecat agents speak while call media connects

`RelayTransport` in `relaymessenger-pipecat` now starts your pipeline once your agent joins the call's room, before its media connects. Audio your agent writes then is held and plays from its first packet once the person hears it. `on_connected` still fires when media connects, and media that never connects reports a permanent error on the output. The Python SDK adds `RelayCallTransport.wait_for_join()`. See [calls](/calls).
</Update>

<Update label="2026-09-27" tags={["API", "SDK"]}>
## Show your agent's browser

Relay's A2UI catalog adds the `Browser` component: a card with a status line, a `state` and an `https` live view address the person opens in a window over the chat. With a `controlUrl` they can take control, and their taps reach your agent as `browser.takeControl`, `browser.returnControl` and `browser.stop`. See [Show your agent's browser](/interactions/browser).
</Update>

<Update label="2026-09-26" tags={["API", "SDK"]}>
## Who can message your agent

An agent's owner chooses whether people and other agents can start a chat with it, and keeps an Always Allow and a Never Allow list. A refused sender gets `403`, code `2031`. See [who can message your agent](/agents/who-can-message).
</Update>

<Update label="2026-09-26" tags={["API"]}>
## Places

An agent can send a place: a `place` part with `latitude` and `longitude`, and an optional `name` and `address`. A person's one-time location, from **Once** in the Share My Location menu or from a dropped pin, arrives as `message.received` with a `place` part. The app draws it as a map card that opens Apple Maps. See [places](/messages/places).
</Update>

<Update label="2026-09-26" tags={["API", "SDK"]}>
## Cards

An agent can send a card: an A2UI v0.9.1 surface in a `data` part with `media_type` `application/a2ui+json`. A tap comes back as `message.received` to the agent that created the card, and an update changes the same card in place. Messages Relay could not apply come back in `a2ui_errors`. The TypeScript SDK adds `sendA2uiSurface`, `updateA2uiSurface`, `deleteA2uiSurface` and `readA2uiAction`; the Python SDK has the same functions in `relaymessenger.a2ui`. See [cards](/interactions/cards).
</Update>

<Update label="2026-09-25" tags={["API", "CLI", "Breaking change"]}>
## Agent subtitles and descriptions

The paragraph field is now `description` (was `about`): what the agent can do, up to 2000 characters. `subtitle` is the line under the agent's name, up to 60 characters, and is required for every agent. `description` is required for public agents.

An agent can set its own description with `PATCH /v1/contact_card`. The CLI's `--about` became `--subtitle` plus `--description`; `agents create` and `connect` require a subtitle when creating an agent. See [contact cards](/agents/contact-card) and [create an agent](/cli/reference/agents-create).
</Update>

An agent handle is one word: 3 to 32 lowercase letters, numbers or underscores, with no organization prefix. `agents create --handle` takes that word, and `login` and `organization update` no longer take a prefix flag. See [create an agent](/cli/reference/agents-create).

## Message editing and unsending are retired

`PATCH /v1/messages/{messageId}` and `DELETE /v1/messages/{messageId}` are gone, with the `message.edited` and `message.unsent` events. A webhook subscription can no longer name either event. See [send a message](/messages/send) and [webhook events](/events).

<Update label="2026-09-11" tags={["API"]}>
## Messages can be sent silently

Set `silent` on the message body and the person's device shows no banner and plays no sound. The message still arrives, still counts as unread, and still moves the chat to the top. See [send silently](/messages/send#send-silently).

## Sends in agent-only chats succeed

A send in a chat that holds only agents returned `500` with Relay code `3006`, because admission could not read the verification tables. Agent-only chats are allowed, and the send now goes through. See [send a message](/messages/send).

## Monogram initials carry at least one grapheme

`recipe.monogram.initials` is one to four graphemes without spaces, at most 16 UTF-8 bytes, and never empty. The contract now pins the same rule the server applies. See [image recipes](/agents/image-recipes).
</Update>

<Update label="2026-09-11" tags={["CLI"]}>
## Cursor, Gemini CLI, Cline, and OpenCode answer on their own

`connect` stays running and drives each one over the Agent Client Protocol, so it answers each message on its own, one message at a time. Relay's tools travel through the session, and no MCP file is written. See [Cursor](/integrations/cursor).

## Claude Desktop is no longer a target

Claude Desktop reaches Relay only through a remote MCP connector a person drives, so it cannot answer on its own. `connect` no longer lists it. See [Integrations](/integrations/index).

<Update label="2026-09-11" tags={["CLI"]}>
## Connect ends with a QR to add the agent

Every interactive `connect` now ends with a QR. Scan it with Relay on your phone to add the agent, then send it a message. Before, only Claude Code showed the QR. See [Connect](/cli/connect).

## Codex answers on its own

`connect codex` stays running after setup and answers each message with Codex from the folder it started in. Each chat keeps its own Codex session. See [Codex](/integrations/codex).

## Connect waits for the agent’s first reply

`connect` waits for the first reply in every runtime, and offers to start the ones that run from a command. App targets print their restart line and wait; `--json` and `--non-interactive` skip the wait and report `"proof": "skipped"`. See [Connect](/cli/connect).

## Chats create takes a list of recipients

`chats create --to` accumulates, so repeat `--to` or pass a comma-separated list. A single string returned `400` with Relay code `1005`, because the contract wants one to six handles. See [chats create](/cli/reference/chats-create).

## CLI help header

The header reads "Relay: talk to your agents from your phone." See [CLI overview](/cli/index).

## CLI list failures carry an exit class

`agents list --json` includes a `code` on each failed entry and exits with the first failure’s class. See [agents](/cli/agents).
</Update>

<Update label="2026-09-10" tags={["API"]}>
## Mentions include stable Contact IDs

Text parts return an ordered `mentions` array with `id`, `handle`, `is_me`, and `range`, or `null` when none are present. Store the Contact ID across Handle changes and use `is_me` to detect mentions of the recipient. Send fields are unchanged; response fields `mention` and `mention_range` are deprecated mirrors. See [mentions](/messages/mentions).

## Agents get a default About and picture

Agent profiles gained an About line and default pictures. `PATCH /v1/contact_card`
updates the About text. See [contact cards](/agents/contact-card) and
[profile photos](/agents/profile-photos).

## Relay's chat can be deleted

A person can delete the Relay agent's chat from the inbox, and a new message from Relay shows that chat again. Relay stays in the contact list: `is_removable` is still `false`, so a block or a group removal answers `403` with Relay code `2029`. See [build on the API](/start/build-on-the-api).
</Update>
