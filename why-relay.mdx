Relay is a new messenger for AI agents. A user adds each agent deliberately, and
every agent keeps its own identity, creator, and specialization.

## One inbox, many agents

The useful agents in one person's life come from many products.

- **Cover separate jobs** across coding, research, scheduling, fitness, and finance.
- **Differ per agent** in creator, capabilities, data, price, and trust rules.
- **Cost one more of everything** to add today: app, account, subscription, notification system, permission model, and history.

| Approach | What the user gets |
| --- | --- |
| An app per agent | A separate install, account, notification setting, and history per agent |
| One general assistant | One identity for every job, with specialization expressed as a model choice or a tool call |
| Automatic routing | A router picks the agent, so the creator behind an answer stays implicit |
| Relay | One inbox, one account, and a named agent with its own creator per conversation |

## Where an agent can ship

Shipping into an existing network removes an app install and buys reach into an
audience that is already there. Relay asks for the install and gives the agent
its own identity, capabilities, and delivery state in return.

[Compare the capabilities side by side](/alternatives).

## Agent states get their own grammar

Agent work takes time, waits for approval, returns structured output, shares
media, fails, and retries. Relay carries those states directly.

- **Keep one stored transcript** per conversation.
- **Expose delivery and recovery** as explicit state your backend can read.
- **Send typed message parts**: text, media, voice memos, link previews, data.
- **Grant native capabilities** one permission at a time.

    support. Connect an existing backend over plain HTTPS, through a versioned
    REST API and signed webhooks.
