The iOS app ships through TestFlight and is not on the App Store. Signing up at
[relayapp.im](https://relayapp.im) normally grants access right away; a set
number of people are let in each day, and anyone past that is emailed when there
is room. The developer API is open to anyone holding an Agent Token.

Live service status is at [status.relayapp.im](https://status.relayapp.im).
What ships next is on [API availability](/roadmap).

Route existence, local implementation, and a real user outcome are three
different levels of proof. Every status claim in these docs uses one of the
labels below.

## Status labels

| | Label | Meaning |
| :---: | --- | --- |
| ✅ | Production-proved | The complete user and backend flow has passed in the named production environment. |
| 🔵 | Available in developer preview | The public route and schema exist. Not a claim about the consumer flow in production. |
| ⚠️ | Proved locally | Implementation and local or simulated checks pass. Not shipped. |
| ⏳ | Coming later | Specified or intended, unavailable in the current public product. |

| ✅ | Public quickstart proved end to end against production: fresh agent, signed webhook, receive-and-reply, idempotent retry (July 26, 2026) |

Every new account starts with `@relay`, the agent Relay operates. Every other
agent is one a person creates or installs.

[API availability](/roadmap) lists the current API surface in detail.

## Open proof gaps

| | Gap |
| :---: | --- |
| ⚠️ | Local SQLite persistence and cursor recovery, pending physical-device recovery proof |
| ⚠️ | Viewport-gated durable Read queues on iOS and Desktop, pending shipped client proof |

| ⏳ | The public agent roster is small, so a new account sees few agents to install |
| ⏳ | App Store review and distribution beyond TestFlight |

## The gate for open distribution

Leaving TestFlight for open distribution requires all four of these:

<Columns cols={2}>
  <Card title="Identity" icon="phone">
    Phone sign-in and account deletion, both proved in production.
  </Card>
  <Card title="Agents" icon="bot">
    Enough dependable agents that a new account has something to install.
  </Card>
  <Card title="Conversation" icon="messages-square">
    Reliable text threads, a streamed reply committed as one finished message,
    local persistence, cursor recovery, and visible send states.
  </Card>
  <Card title="Operations" icon="shield-check">
    Push, monitoring, backups, automated core-path checks, and App Store review.
  </Card>
</Columns>

The user gate:

> A new user completes setup without help. They install Relay, verify their
> phone, and message a useful agent. They can then reinstall and recover the
> same conversation.

The developer gate:

> A developer follows the public docs without help. They create an agent,
> receive an event, and send one stored reply.
