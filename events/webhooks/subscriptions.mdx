Create a subscription to send an agent’s events to one HTTPS endpoint and manage its event set.

**With one or more saved subscriptions, Relay delivers each event to every
active subscription that includes its type.** Keep every required event type
covered by an active subscription.

## Before you start

Use an [Agent Token](/live/authentication), an HTTPS receiver you control, and event names from the [catalog](/events/reference). The SDK examples use a client configured for `https://api.staging.relayapp.im`.

## Create

<CodeGroup>
```bash cURL
curl -sS -A "relay-docs/1.0" -X POST https://api.staging.relayapp.im/v1/webhook-subscriptions \
  -H "Authorization: Bearer $RELAY_AGENT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "target_url":"https://agent.example/webhooks/relay",
    "subscribed_events":["message.received"]
  }'
```

```typescript TypeScript SDK
const subscription = await relay.webhookSubscriptions.create({
  target_url: "https://agent.example/webhooks/relay",
  subscribed_events: ["message.received"],
});
```
</CodeGroup>

(unverified: these request variants were not both executed; no successful response is asserted 2026-09-10)

Replace the example target with your receiver’s public HTTPS URL. See [destination checks](/events/webhooks/delivery#destination-checks) for delivery-time validation.

## Store the signing secret

A successful create returns HTTP `201`:

```json
{
  "id":"01993d50-34ca-7613-8df2-d3f8cc975d04",
  "target_url":"https://agent.example/webhooks/relay",
  "subscribed_events":["message.received"],
  "is_active":true,
  "signing_secret":"whsec_<base64-key>",
  "created_at":"2026-08-29T06:20:00.000Z",
  "updated_at":"2026-08-29T06:20:00.000Z"
}
```

**Store `signing_secret` from this response.** It is returned only when you create the subscription. Use it to [verify incoming signatures](/events/webhooks/verify-signatures).

## Review list, retrieve, update, or delete

### List, retrieve, update, or delete

| Operation | TypeScript SDK | HTTPS |
| --- | --- | --- |
| List | `relay.webhookSubscriptions.list()` | `GET /v1/webhook-subscriptions` |
| Retrieve | `relay.webhookSubscriptions.retrieve(subscriptionId)` | `GET /v1/webhook-subscriptions/{subscriptionId}` |
| Update | `relay.webhookSubscriptions.update(subscriptionId, body)` | `PUT /v1/webhook-subscriptions/{subscriptionId}` |
| Delete | `relay.webhookSubscriptions.delete(subscriptionId)` | `DELETE /v1/webhook-subscriptions/{subscriptionId}` |

| Update field | Use |
| --- | --- |
| `target_url` | Receiver’s HTTPS URL |
| `subscribed_events` | Event names from the catalog |
| `is_active` | Whether this subscription receives matching events |

Target URLs must be unique per agent.

Delete a subscription by ID:

<CodeGroup>
```bash cURL
curl -sS -A "relay-docs/1.0" -X DELETE \
  "https://api.staging.relayapp.im/v1/webhook-subscriptions/$SUBSCRIPTION_ID" \
  -H "Authorization: Bearer $RELAY_AGENT_TOKEN"
```

```typescript TypeScript SDK
await relay.webhookSubscriptions.delete(subscriptionId);
```
</CodeGroup>

(unverified: these request variants were not both executed; no successful response is asserted 2026-09-10)

A successful delete returns HTTP `204` with no response body.

## Review change delivery paths

### Change delivery paths

| Saved subscription state | Delivery behavior |
| --- | --- |
| One or more subscriptions, including inactive ones | Webhook mode; new events go to active subscriptions covering their type |
| First subscription created | Connected agent sockets close; matching pending events transfer to active webhooks |
| Last subscription deleted | Pending webhook events transfer to WebSocket and wait while the backend is disconnected |

Transferred events retain their original `event_id` and body. Read [WebSocket recovery](/events/websocket/full-sync) for the replay window and recovery procedure.



## What you get back

HTTP `204`. The response body is empty.

## When it fails

Inspect the HTTP status, Relay code, and `trace_id` before retrying.

| Code | HTTP | When | What to do |
| --- | --- | --- | --- |
| [2001](/api-reference/errors#2001) | 404 | Resource is unavailable | Check the ID and token scope. |
| [3006](/api-reference/errors#3006) | 500 | Server rejected the operation unexpectedly | Keep the request ID and check history before retrying the same send key. |
