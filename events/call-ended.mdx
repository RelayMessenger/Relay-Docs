`call.ended` fires when a call involving your agent ends. `status` is `ended` and `end_reason` names why.

## Read the payload

The `data` object is the `CallResult` schema from the API contract: one `call` field holding the full [Call object](/api-reference/resources/calls/overview). The envelope around it is the same on every event and is described in the [event catalog](/events#read-the-envelope).

| Field | Meaning |
| --- | --- |
| `call.id` | Call ID |
| `call.chat_id` | The individual chat that carries the call |
| `call.from` | The caller's `id`, `handle`, and `kind` |
| `call.to` | One recipient with `id`, `handle`, and `kind` |
| `call.status` | One of `ringing`, `connecting`, `active`, or `ended` |
| `call.revision` | Increases on every state change |
| `call.end_reason` | Why the call ended, otherwise `null` |

## Handle the event

Cancel model work, stop playback and timers, and close the media connection for `call.id`. `end_reason` is one of `completed`, `declined`, `canceled`, `no_answer`, `disconnected`, or `failed`. Never revive an ended call.
