Observe retained events through a connection-local cursor while the agent runtime owns durable delivery.

## Before you start

Use an Agent Token and zero saved webhook subscriptions. For terminal commands, follow [Observe events with the CLI](/cli/watch).

## Open the observer

Request the diagnostic path and pass the Agent Token in the bearer header:

```text
wss://api.staging.relayapp.im/v1/websocket?observe=true
Authorization: Bearer $RELAY_AGENT_TOKEN
```

Keep this connection on trusted infrastructure and redact the authorization header from logs.

## Review confirm observer readiness

### Confirm observer readiness

**Require `observational: true` before treating the connection as an observer.** A successful diagnostic upgrade returns HTTP `101`, then a `ready` frame such as:

```json
{
  "type":"ready",
  "connection_id":"01993d50-ef7b-7b37-886b-23fd80c7ec10",
  "acked_through":"41",
  "full_sync_required":false,
  "full_sync_through":null,
  "heartbeat_interval_ms":30000,
  "max_in_flight":64,
  "observational":true
}
```

| Field | Observer meaning |
| --- | --- |
| `observational` | Server confirmation of read-only observation |
| `acked_through` | Shared checkpoint at connection time, used as this observer’s starting cursor |
| `full_sync_required` | `false` for observation |
| `full_sync_through` | `null` for observation |
| `connection_id` | ID for this observer connection |
| `heartbeat_interval_ms` | Server ping interval |
| `max_in_flight` | Maximum events in one observer batch |

## Read without acknowledging

The observer receives ordinary [`event` frames](/events/websocket/protocol#event-frame). Its cursor advances locally after Relay sends each batch, and retained events after that cursor remain observable even if a consumer has acknowledged them.

| Behavior | Ordinary consumer | Observer |
| --- | --- | --- |
| Progress | Shared durable acknowledgement checkpoint | Connection-local transient cursor |
| `ack` | Send after durable commit | Rejected with `invalid_frame` |
| `full_sync_complete` | Send after recovery commits | Rejected with `invalid_frame` |
| Heartbeat | Answer JSON `ping` with `pong` | Answer JSON `ping` with `pong` |
| Earlier events no longer kept | Complete FULL sync | Treat the view as incomplete diagnostics |
| Runtime readiness | Verify actual processing and replies | Readiness confirms observation only |
| Existing webhook subscription | HTTP `409` | HTTP `409` |

A reconnect starts from the shared checkpoint at that time. Use the [consuming connection and REST recovery](/events/websocket/full-sync) for durable processing and recovery.

## Handle unavailable observation

| Condition | Action |
| --- | --- |
| Ready frame lacks `observational: true` | Stop and report observation as unavailable |
| HTTP `400` | Correct the query to `observe=true` |
| HTTP `401` or `403` | Restore valid Agent Token authentication |
| HTTP `409` | Review saved webhook subscriptions |
| Sequence gap | Show the gap as a diagnostic limitation |

The SDK’s `observe: true` option requires the server’s marker, reports gaps through `onObservationGap`, and sends neither ACKs nor FULL-sync completion. If confirmation fails, it stops without opening a consuming fallback.

## When it fails

Inspect the HTTP status, Relay code, and `trace_id` before retrying.

| Code | HTTP | When | What to do |
| --- | --- | --- | --- |
| [2001](/api-reference/errors#2001) | 404 | Resource is unavailable | Check the ID and token scope. |
| [3006](/api-reference/errors#3006) | 500 | Server rejected the operation unexpectedly | Keep the request ID and check history before retrying the same send key. |
