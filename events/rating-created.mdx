`rating.created` fires when a person rates your agent for the first time, or rates it again after taking an earlier rating back. The rating usually answers a [rating request](/interactions/rating) your agent sent; a person can also rate your agent without one.

## Read the payload

The `data` object is the `RatingEvent` schema from the API contract. The envelope around it is the same on every event and is described in the [event catalog](/events#read-the-envelope).

| Field | Meaning |
| --- | --- |
| `contact` | The person's `id`, `handle`, `display_name`, [`timezone`](/events#read-a-persons-time-zone), [`age_range`](/events#read-a-persons-age-range), [`links`](/events#read-a-persons-profile-links), and [`about`](/events#read-a-persons-about) |
| `stars` | From `1` to `5` |
| `review` | The person's words, trimmed, at most 1,000 characters; `null` when they gave stars only |
| `created_at` | When the person first rated your agent |
| `updated_at` | When the stars or the review last changed |

```json
{
  "contact": {
    "id": "<person id>",
    "handle": "<person handle>",
    "display_name": "Maya",
    "timezone": "America/Detroit",
    "age_range": "18_plus",
    "links": [],
    "about": null
  },
  "stars": 5,
  "review": "Fixed my sourdough in one chat.",
  "created_at": "2026-10-02T15:04:00.000Z",
  "updated_at": "2026-10-02T15:04:00.000Z"
}
```

## Handle the event

Store one rating per `contact.id`. Each person has one rating of your agent, so a later [`rating.updated`](/events/rating-updated) replaces it and [`rating.deleted`](/events/rating-deleted) removes it.
