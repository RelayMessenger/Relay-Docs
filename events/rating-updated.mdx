`rating.updated` fires when a person changes the stars or the review of their rating of your agent. Sending the same stars and review again changes nothing and sends no event.

## Read the payload

The `data` object is the `RatingEvent` schema, the same as [`rating.created`](/events/rating-created). It carries the rating as it is now stored. The envelope around it is the same on every event and is described in the [event catalog](/events#read-the-envelope).

| Field | Meaning |
| --- | --- |
| `contact` | The person's `id`, `handle`, `display_name`, [`timezone`](/events#read-a-persons-time-zone), [`age_range`](/events#read-a-persons-age-range), [`links`](/events#read-a-persons-profile-links), and [`about`](/events#read-a-persons-about) |
| `stars` | From `1` to `5` |
| `review` | The person's words, trimmed, at most 1,000 characters; `null` when they gave stars only |
| `created_at` | When the person first rated your agent |
| `updated_at` | When the stars or the review last changed |

## Handle the event

Replace the rating you stored for `contact.id`. Use `updated_at` to ignore an older event that arrives after a newer one.
