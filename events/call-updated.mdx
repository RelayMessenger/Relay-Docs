`call.updated` fires when a call involving your agent changes state without ending, for example from `ringing` to `connecting` or from `connecting` to `active`.

## Read the payload

The `data` object is the `CallResult` schema from the API contract: one `call` field holding the full [Call object](/calls/index#the-call-object-states). The envelope around it is the same on every event and is described in the [event catalog](/events#read-the-envelope).

| Field | Meaning |
| --- | --- |
| `call.id` | Call ID |
| `call.chat_id` | The individual chat that carries the call |
| `call.from` | The caller's `id`, `handle`, and `kind` |
| `call.to` | One recipient with `id`, `handle`, and `kind` |
| `call.status` | One of `ringing`, `connecting`, `active`, or `ended` |
| `call.revision` | Increases on every state change |
| `call.end_reason` | Why the call ended, otherwise `null` |

## Handle the event

Keep the snapshot with the highest `revision` for each `call.id` and drop older or duplicate envelopes. When `status` becomes `active`, both sides have reported connected media.
