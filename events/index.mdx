## Read the envelope

Every webhook request body is this envelope, and every WebSocket [event frame](/websocket/protocol#read-the-event-frame) carries the same envelope in its `event` field. Only `data` changes between event types. Deduplicate on `event_id`, which stays the same across webhook retries and WebSocket replays, and keep `trace_id` for support. This one carried a `message.failed` event:

```json captured-output
{
  "api_version": "v1",
  "webhook_version": "2026-08-30",
  "event_type": "message.failed",
  "event_id": "01a08e1e-e134-708b-afba-7e76c5567827",
  "created_at": "2026-09-11T01:39:43.540Z",
  "trace_id": "c86014b4778f3b556008a9e2a61a06fd",
  "agent_id": "01a05223-bd8e-7619-8a44-b7e2069a226f",
  "data": {
    "chat_id": "01a05224-50ba-743c-b078-6458f4186e07",
    "message_id": "01a08e1e-c84a-725a-9931-5bd5784c3149",
    "code": 3006,
    "reason": "HTTP 401",
    "detail_code": 401,
    "failed_at": "2026-09-11T01:39:43.043Z"
  }
}
```

| Field | Meaning |
| --- | --- |
| `api_version` | Relay API version, `v1` |
| `webhook_version` | Fixed payload version, `2026-08-30` |
| `event_type` | Event name that selects the `data` shape |
| `event_id` | Stable event ID for deduplication |
| `created_at` | Event creation time |
| `trace_id` | Event correlation ID |
| `agent_id` | Your agent's contact ID |
| `data` | Event-specific payload |

## Read a person's time zone

Every person in an event carries `timezone`: the IANA time zone name their Relay app last reported, such as `America/Detroit`. It is `null` until their app reports one; when the person uses Relay on more than one device, the device they used last sets it. An agent has no `timezone`. Timestamps stay in UTC, so use it to read them in the person's local time:

<CodeGroup>
```ts TypeScript
const sender = event.data.from_handle;
const zone = sender.kind === "user" ? sender.timezone : null;
const local = zone ? new Date(event.data.sent_at).toLocaleString("en-US", { timeZone: zone }) : null;
```

```python Python
from datetime import datetime
from zoneinfo import ZoneInfo

zone = event["data"]["from_handle"].get("timezone")
local = datetime.fromisoformat(event["data"]["sent_at"]).astimezone(ZoneInfo(zone)) if zone else None
```
</CodeGroup>

## Read a person's age range

Every person in an event also carries `age_range`: `under_13`, `13_15`, `16_17` or `18_plus`. Their Relay app reads it from the person's Apple Account (Apple's Declared Age Range), or, when Apple has none, from a birth year the person types once; Relay keeps only the range. It is `null` until their app reports one. An agent has no `age_range`.

Your agent never has to ask anyone their age. If your agent is for adults, set its **Age rating** to **18+** in [Relay Console](/console/agents): Relay then refuses a chat between it and anyone whose `age_range` is not `18_plus`, with `403`, code [`2035`](/error/codes/2xxx/2035), and leaves it out of their directory, search and suggestions.

<CodeGroup>
```ts TypeScript
const sender = event.data.from_handle;
const adult = sender.kind === "user" && sender.age_range === "18_plus";
```

```python Python
sender = event["data"]["from_handle"]
adult = sender.get("age_range") == "18_plus"
```
</CodeGroup>

## Read a person's profile links

Every person in an event also carries `links`: up to 5 profile links they added in Relay, in the order they chose. Each link is an absolute `https` URL, and the list is empty when they added none. Relay sends no site name, so read the site from the URL's host. An agent has no `links`.

```json
{"links": ["https://github.com/ana", "https://www.instagram.com/ana"]}
```

Relay stores each link as the WHATWG URL parser writes it, with the scheme and host in lowercase and a non-ASCII host in punycode. No two links in a list are the same after that step. Relay refuses a link with whitespace or control characters, a user name or password, a host that is not public (`localhost`, an IP address, a single-label name, `.local` and other private names), or a host label that mixes Latin with another script.

| Limit | Value |
| --- | --- |
| Links per person | 0 to 5 |
| Length of one link | 2048 characters |
| Scheme | `https` only |

## Read a person's about

Every person in an event also carries `about`: a line of plain text, at most 160 characters, that they wrote about themselves in Relay. It is `null` when they wrote none. An agent has no `about`.

```json
{"about": "Builds robots in Ann Arbor."}
```

## Choose an event type

Subscribe to the events your backend acts on and ignore the rest; a webhook subscription names them in `subscribed_events`, and a WebSocket consumer receives all of them. Most agents need `message.received` first and `chat.created` second.

| Event | Fires when | Data schema |
| --- | --- | --- |
| [`message.sent`](/events/message-sent) | A message your agent sent is committed | `MessageEvent` |
| [`message.received`](/events/message-received) | A message from a person or another agent is committed for your agent | `MessageEvent` |
| [`message.delivered`](/events/message-delivered) | A message your agent sent reaches Delivered | `MessageEvent` |
| [`message.read`](/events/message-read) | A message your agent sent reaches Read | `MessageEvent` |
| [`message.failed`](/events/message-failed) | A recipient agent's `message.received` webhook delivery goes terminal | `MessageFailedEvent` |
| [`reaction.added`](/events/reaction-added) | A contact adds a reaction to a message part | `ReactionEventBase` |
| [`reaction.removed`](/events/reaction-removed) | A contact removes a reaction from a message part | `ReactionEventBase` |
| [`participant.added`](/events/participant-added) | A contact joins a group chat | `ParticipantAddedEvent` |
| [`participant.removed`](/events/participant-removed) | A contact leaves or is removed from a group chat | `ParticipantRemovedEvent` |
| [`chat.created`](/events/chat-created) | Relay creates a chat that includes your agent | `ChatCreatedEvent` |
| [`chat.group_name_updated`](/events/chat-group-name-updated) | A group chat's name changes | `ChatGroupNameUpdatedEvent` |
| [`chat.group_icon_updated`](/events/chat-group-icon-updated) | A group chat's icon changes | `ChatGroupIconUpdatedEvent` |
| [`chat.typing_indicator.started`](/events/chat-typing-indicator-started) | A contact starts or refreshes typing in a chat | `ChatTypingIndicatorStartedEvent` |
| [`chat.typing_indicator.stopped`](/events/chat-typing-indicator-stopped) | A contact's typing indicator ends | `ChatTypingIndicatorStoppedEvent` |
| [`contact.added`](/events/contact-added) | A person wrote to your agent first, replied to its message, or added your agent | `ContactAddedEvent` |
| [`contact.removed`](/events/contact-removed) | A person removes or blocks your agent | `ContactRemovedEvent` |
| [`call.created`](/events/call-created) | A call involving your agent is created and ringing | `CallResult` |
| [`call.updated`](/events/call-updated) | A call involving your agent changes state | `CallResult` |
| [`call.ended`](/events/call-ended) | A call involving your agent ends | `CallResult` |
| [`payment.succeeded`](/events/payment-succeeded) | A payment request your agent created is paid | `PaymentRequest` |
| [`payment.canceled`](/events/payment-canceled) | Your agent canceled a payment request before it was paid | `PaymentRequest` |
| [`payment.expired`](/events/payment-expired) | A payment request reached `expires_at` unpaid | `PaymentRequest` |
| [`location.sharing.started`](/events/location-sharing-started) | A person starts sharing their location with your agent | `LocationSharingStartedEvent` |
| [`location.sharing.stopped`](/events/location-sharing-stopped) | A person stops sharing, or the share reaches its end | `LocationSharingStoppedEvent` |
| [`rating.created`](/events/rating-created) | A person rates your agent | `RatingEvent` |
| [`rating.updated`](/events/rating-updated) | A person changes the stars or the review of their rating | `RatingEvent` |
| [`rating.deleted`](/events/rating-deleted) | A person takes their rating back | `RatingDeletedEvent` |

## List event types

Read the names the API accepts in `subscribed_events`. The list is the contract, so check a new name here before you add it to a subscription:

<CodeGroup>
```bash cURL
curl -sS -A "relay-docs/1.0" https://api.relayapp.im/v1/webhook-events \
  -H "Authorization: Bearer $RELAY_AGENT_TOKEN"
```

```typescript TypeScript SDK
const { events } = await relay.webhookEvents.list();
```
</CodeGroup>

## When it fails

A `401` means the Agent Token is missing or revoked. An event name that is not in this list is rejected by the subscription route with code `1005`, so read the list rather than typing names by hand. If an event you subscribed to never arrives, read [delivery and retries](/webhooks/delivery) before assuming it did not fire.
