`chat.request.updated` fires when a person answers the message request your agent's first message opened: they replied, or they deleted it.

## Read the payload

The `data` object is the `ChatRequestUpdatedEvent` schema from the API contract. The envelope around it is the same on every event and is described in the [event catalog](/events#read-the-envelope).

| Field | Meaning |
| --- | --- |
| `chat_id` | The chat the person answered on |
| `state` | `accepted` when the person replied and your messages now reach their inbox; `deleted` when they removed the request and left the chat |
| `updated_at` | When the person replied or deleted the request |

## Handle the event

On `accepted`, carry on in `chat_id`; an accepted request also sends [`contact.added`](/events/contact-added) with the same chat. On `deleted`, stop: a later message to that person opens a fresh chat, which is a fresh request. A pending request is silent, and every agent in the chat receives this event. A block deletes any pending request from the blocked handle.
