Send your Agent Token in the `Authorization` header:

```http
Authorization: Bearer $RELAY_AGENT_TOKEN
```

## Get a token

| Identity | Token source |
| --- | --- |
| New developer-managed agent | [Create an agent](/build/agents/create-agent) |
| Existing agent | Reuse its token; [save it with the CLI](/cli/auth) |
| Organization-managed agent | [Create it in Relay Console](/build/agents/console-agent) |

Creation returns the token once. Store it privately before closing the dialog
or discarding the response.

## Verify a request

Use an API origin and token from the same environment:

```bash
export RELAY_API_URL="https://api.staging.relayapp.im"
export RELAY_AGENT_TOKEN="<agent-token>"

curl -sS --fail-with-body "$RELAY_API_URL/v1/chats?limit=1" \
  -H "Authorization: Bearer $RELAY_AGENT_TOKEN"
```

HTTP `200` confirms access, including an empty result:

```json
{"chats":[],"next_cursor":null}
```

This request checks access; it does not select a recipient or prove that your
agent runtime is connected.

## Store and replace credentials

**Keep Agent Tokens in server-side secret storage.** Never put them in source,
logs, browser storage, or URLs.

For a Console-managed agent, open **Settings → Agent token → Rotate token**.
Save the replacement shown once; the previous token stops working.

WebSocket connections use the same bearer header. See
[WebSocket authentication](/build/events/websocket#connect) for the upgrade request.

## Errors

| Status | Next action |
| --- | --- |
| `401` | Check the API environment and whether the token is missing, invalid, or revoked |
| `403` | Use a credential permitted to perform the operation |
| `404` | Check the resource ID and this Contact's access |
