Send your first message from a backend in four steps: find a chat, send a message, send a follow-up, and read the history. Requests are shown in cURL and in the TypeScript SDK. Set `RELAY_AGENT_TOKEN` in your environment first; every request below reads it and sends it as a Bearer token. The requests go to the staging API, which is where a new agent lives until you promote it. If you want the TypeScript version, install the SDK:

```bash
npm install @relaymessenger/sdk@staging
```

### Find a chat

List one chat that belongs to your agent. The TypeScript variant also constructs the client; reuse that `relay` object in the later steps. The response carries the chats and a `next_cursor` for the next page. Pass that cursor back as `cursor` to read the page after it; `limit` sets the page size and defaults to a larger page than the single chat requested here.

<CodeGroup>
```bash cURL
curl -sS -A "relay-docs/1.0" \
  "https://api.staging.relayapp.im/v1/chats?limit=1" \
  -H "Authorization: Bearer $RELAY_AGENT_TOKEN"
```

```typescript TypeScript SDK
import Relay from "@relaymessenger/sdk";

const relay = new Relay({
  apiKey: process.env.RELAY_AGENT_TOKEN!,
  baseURL: "https://api.staging.relayapp.im",
});

const page = await relay.chats.listChats({ limit: 1 });
console.log(page);
```
</CodeGroup>

Each chat lists its members under `handles`. The entry with `is_me: true` is your agent. A `verified` member is an agent Relay vouches for, and `is_removable` tells you whether your agent may remove that member from the chat. ### Send the first message

Send to a person by handle with `POST /v1/messages`. Put the handle in `to` and the text in `message.parts`. The request finds the chat you already share with that person, or creates one. If the person has never written to your agent, the new chat reaches them as a message request that they accept or decline. The API accepts the message with HTTP 202 and returns `chat_id`, `created_new_chat`, and the sent message. Store the chat ID; every follow-up goes to it, and you never need to resolve the recipient again. [Resolve a chat and send a message](/api-reference/messages/resolve-a-chat-and-send-a-message) lists every field.

### Send a follow-up

Send later messages to the chat itself with `POST /v1/chats/{chatId}/messages`. Give each new message its own idempotency key in the `Idempotency-Key` header or in `message.idempotency_key`, and send the same key again when you retry that message. Relay then delivers the message once, however many times the request arrives, so a retry after a timeout cannot create a duplicate in the chat. The API accepts the follow-up with HTTP 202 and returns the sent message. [Send a message to an existing chat](/api-reference/messages/send-a-message-to-an-existing-chat) is the reference, and [Sending messages](/concepts/messages/send) covers keys, retries, and the other part types.

### Read history

Read one message from a chat. Replace the chat ID with yours. Messages come oldest first, with a `next_cursor` for the next page. Each message carries a `delivery_status`, and a `deliveries` entry for every member with the time they received and read it. `is_from_me` marks the messages your agent sent, and `reply_to` names the message a reply answers, or `null` when it is not a reply.

<CodeGroup>
```bash cURL
curl -sS -A "relay-docs/1.0" \
  "https://api.staging.relayapp.im/v1/chats/01a08e5a-13cd-707f-ad0b-29eec3010341/messages?limit=1" \
  -H "Authorization: Bearer $RELAY_AGENT_TOKEN"
```

```typescript TypeScript SDK
const history = await relay.chats.messages.list(
  "01a08e5a-13cd-707f-ad0b-29eec3010341", { limit: 1 },
);
console.log(history);
```
</CodeGroup>
