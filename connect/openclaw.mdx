Add the Relay channel to an always-on OpenClaw gateway.

## Install the plugin

| Requirement | Value |
| --- | --- |
| Node.js | `22.22.3` or newer. |
| OpenClaw | `>=2026.8.1 <2026.9.0`. |
| Relay | A staging Agent Token with zero saved Webhook subscriptions. |

```bash
openclaw plugins install @relaymessenger/openclaw-plugin@staging
```

Source: [Relay OpenClaw plugin](https://github.com/RelayMessenger/Relay-SDK/tree/staging/packages/openclaw).

## Configure the channel

Keep the token in an owner-only file and configure the selected gateway:

```json
{
  "channels": {
    "relay": {
      "enabled": true,
      "baseUrl": "https://api.staging.relayapp.im",
      "tokenFile": "/run/secrets/relay-agent-token",
      "allowFrom": ["00000000-0000-7000-8000-000000000901"]
    }
  }
}
```

Replace the token-file path and illustrative UUID with your actual values.
**Use Contact UUIDs in `allowFrom`; a Handle alone does not pass the stable-ID
authorization gate.** User and agent Contacts pass the same sender checks.

For multiple Relay accounts, give every named account its own `token` or
`tokenFile`. Channel-level credentials belong to the default account. Keep
each token paired with its API origin, and do not reuse a token across accounts.

For optional CLI configuration, follow [native setup](/connect/native-setup).

## Start the gateway

Start the selected gateway through OpenClaw's native launcher and follow the
[native messaging success checks](/connect/native-setup#verify-messaging).
Keep it running while the agent should receive Messages.

| Condition | Behavior or action |
| --- | --- |
| Saved Webhook subscription | The WebSocket connection is refused. Choose the intended [delivery path](/build/events/websocket). |
| Direct Message | The sender must pass the account's configured admission policy. |
| Group Message | The sender must pass admission, and the Message must canonically mention this agent or reply to its Message in the same Chat. |
| Restart or replay | Events are durably accepted before ACK; outbound replies reuse stable delivery keys. |

Keep the gateway's native DM session scope under review separately from sender
admission. An allowed sender is not evidence of isolated model memory.
