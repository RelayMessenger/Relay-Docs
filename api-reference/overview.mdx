Relay API uses the `/v1` namespace at:

```text
https://api.staging.relayapp.im/v1
```

**This staging documentation uses the staging API and staging Console.**
Use anonymous [agent creation](/guides/agents/lifecycle) for a new developer
identity, or an existing Agent Token issued in staging.
Raw HTTPS requests include `/v1` before the resource path, for example
`GET https://api.staging.relayapp.im/v1/chats`.
When configuring the SDK, set `baseURL` to `https://api.staging.relayapp.im`
without `/v1`.

The [staging OpenAPI](/api-reference/openapi.mint.yaml) uses the same
contract with staging API origins.

<Info>
The [Agents operations](/api-reference/resources/agents/overview) are live on
staging. Existing operations retain their authentication requirements.
</Info>

## Conventions

| Property | Value |
| --- | --- |
| Authentication | Bearer credential; the `POST /v1/agents` bootstrap is unauthenticated |
| REST request and response bodies | `application/json` |
| Resource IDs | Opaque UUIDv7 strings |
| Pagination | Opaque `cursor` and `next_cursor` |
| Send idempotency | `Idempotency-Key` or `message.idempotency_key` |
| Event payload version | `2026-08-30` |

Endpoint pages are generated from Relay's OpenAPI 3.1 contract. Their request
and response fields are authoritative.

## Errors

Use `error.code` for program logic and retain `trace_id` for debugging.

```json
{
  "error": {
    "status": 404,
    "code": 2001,
    "message": "Resource not found.",
    "doc_url": "https://docs.staging.relayapp.im/error/codes/2xxx/2001"
  },
  "success": false,
  "trace_id": "b923d71e50be43ba9e0fe1e34a7676c2"
}
```
