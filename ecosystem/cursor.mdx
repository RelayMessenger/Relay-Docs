## Install locally

The plugin ships inside Relay-SDK, so it installs from a plain checkout. No
separate packaging repository exists.

The current generated distribution version is `1.0.0`. Clone Relay-SDK, then
link the plugin directory, not the repository root:

```bash
git clone --branch staging \
  https://github.com/RelayMessenger/Relay-SDK.git

ln -s /absolute/path/to/Relay-SDK/plugins/relay ~/.cursor/plugins/local/relay
```

The installed path is:

```text
~/.cursor/plugins/local/relay
```

Reload Cursor, open **Customize**, and confirm that the Relay skill and docs
MCP server are present.

A Cursor team or enterprise administrator can instead import Relay-SDK from
**Dashboard**, **Plugins**, **Team Marketplaces**, which reads the root
catalog above.

## Use the package

The package contains:

- the Relay Skill and self-contained locked references;
- hosted Relay docs MCP configuration;
- a tested `@relaymessenger/sdk@0.3.0-staging.8` Message-send example;
- source and generated-file provenance from the Relay Skill.

The generated files come from the canonical Relay Skill and
[distribution tooling](https://github.com/RelayMessenger/Relay-SDK/tree/staging/tooling/skills-distributions).
Update the source Skill, then regenerate the plugin tree.

## Prepare hosted proof

Run the package's strict hosted-search test only after this docs candidate is
pushed and the hosted staging index refreshes:

```bash
RELAY_DOCS_MCP_URL=https://docs.staging.relayapp.im/mcp npm run test:live
```

The test requires search results for `/v1/websocket`,
`/v1/webhook-subscriptions`, and `webhook_version: 2026-08-30`.
Local Docs validation does not claim that hosted result.
