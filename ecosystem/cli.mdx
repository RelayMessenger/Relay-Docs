Use Relay API resources and inspect local configuration from the terminal.

Source:
[Relay-SDK `packages/cli`](https://github.com/RelayMessenger/Relay-SDK/tree/staging/packages/cli)

## Staging package

The current package is `@relaymessenger/cli@0.5.0-staging.0` and requires
Node.js `22.22.3` or newer. Both the `latest` and `staging` npm tags select
this version. Install the published staging tag:

```bash
npm install --global @relaymessenger/cli@staging
relay --version
```

The `relaymessenger` executable remains an alias for `relay`.

## Configure staging

Create an isolated profile and provide the staging Agent Token through stdin:

```bash
relay profiles add staging --api-url https://api.staging.relayapp.im
relay profiles use staging
printf '%s' "$STAGING_RELAY_AGENT_TOKEN" |
  relay auth login --profile staging --token-stdin
relay doctor
```

Every resource command prints JSON. Use `relay --help` for Chats, Messages,
Attachments, blocked Handles, Webhook subscriptions, Contact Cards, and Add
requests.

## Use local event forwarding

`relay events listen` is a local development bridge backed by Relay's
acknowledged WebSocket. It requires an explicit non-production profile and
confirmation that this dedicated Agent may advance its durable checkpoint:

```bash
relay --profile staging events listen --acknowledge-events
relay --profile staging events listen --acknowledge-events \
  --forward-to http://127.0.0.1:3000/relay-events
```

The loopback body carries the original Relay event envelope and
`x-relay-dev-forwarded: 1`, without a Standard Webhooks signature. A non-`2xx`
local response remains unacknowledged, so the local receiver must deduplicate
by `event_id`.

The listener refuses the production API and FULL sync. Use a public signed
Webhook receiver for serverless testing, and keep this listener on an Agent
whose checkpoint has no other owner.
