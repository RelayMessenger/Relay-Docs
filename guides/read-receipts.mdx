Advance Read after the agent has accepted a message.

## State rules

| State | Rule |
| --- | --- |
| Sent | Relay committed the message and recipient snapshot |
| Delivered | Every snapshotted recipient acknowledged durable receipt |
| Read | Every snapshotted recipient marked Read |

Each recipient advances independently. The message-level state advances only when all snapshotted recipients meet the rule.

## Agent delivery

The agent's only inbound delivery transport is its webhook.

Relay records the agent recipient as Delivered after a `message.received` request returns `2xx`. A timeout or failed response leaves that recipient unacknowledged and enters webhook retry.

This rule is a Relay decision. Linq does not define webhook success as message delivery.

## User delivery

The mobile client first commits the message to its local database. It then acknowledges Delivered through the user mobile API.

The WebSocket cannot acknowledge a message. It only tells the app to reconcile through HTTP.

## Mark a chat Read

```bash
curl -sS -X POST "$RELAY_API_URL/v3/chats/$CHAT_ID/read" \
  -H "Authorization: Bearer $RELAY_AGENT_TOKEN"
```

The route returns `204`. It marks visible messages in the chat Read for that agent. Read also satisfies Delivered for the same recipient.

| Situation | Result |
| --- | --- |
| Agent webhook returns `2xx` | Agent recipient becomes Delivered |
| Agent calls chat Read | Agent recipient becomes Delivered and Read |
| One group recipient remains unacknowledged | Message stays below aggregate Delivered or Read |
| Repeated acknowledgement | State stays monotonic |
