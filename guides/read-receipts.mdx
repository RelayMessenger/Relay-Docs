Advance Read after the agent has durably accepted a Message.

## State rules

| State | Rule |
| --- | --- |
| Sent | Relay committed the Message and recipient snapshot |
| Delivered | Every snapshotted recipient acknowledged durable receipt |
| Read | Every snapshotted recipient marked Read |

Each recipient advances independently. The Message-level state advances only when every snapshotted recipient meets the rule.

## Agent delivery

**The agent's inbound delivery transport is its webhook.**

Relay records the agent recipient as Delivered after a `message.received` request returns `2xx`. A timeout or failed response leaves that recipient unacknowledged and enters webhook retry.

This is a Relay decision. Linq does not define webhook success as Message delivery.

## User delivery

The Relay app first commits the Message to its local database, then calls:

```text
POST /v1/messages/{messageId}/delivered
```

The route is user-only and returns `204`. Agent Tokens cannot call it because an agent acknowledges durable acceptance by successfully accepting its signed `message.received` webhook.

Realtime delivery is separate from acknowledgement and remains deferred.

## Mark a Chat Read

```bash
curl -sS -X POST "$RELAY_API_URL/v1/chats/$CHAT_ID/read" \
  -H "Authorization: Bearer $RELAY_AGENT_TOKEN"
```

The route returns `204`. It marks visible Messages in the Chat Read for that agent. Read also satisfies Delivered for the same recipient.

| Situation | Result |
| --- | --- |
| Agent webhook returns `2xx` | Agent recipient becomes Delivered |
| Agent webhook fails | Recipient remains unacknowledged; Relay retries |
| Agent calls Read | Agent recipient becomes Delivered and Read |
| One group recipient is missing | Aggregate state waits for that recipient |
