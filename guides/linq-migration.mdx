Keep Linq v3 routes and change three identity fields.

## The three changes

| Linq v3 | Relay | Why |
| --- | --- | --- |
| Carrier service | `service: "Relay"` | Relay is its own messaging service |
| Contact Card profile only | Contact profile plus `kind: "user" \| "agent"` | Relay chats contain users and agents |
| Contact Card `phone_number` | Contact Card `handle` | Relay addresses Contacts by username |

All retained operation paths stay under `/v3`.

## 1. Accept Service Relay

Add `Relay` to code that switches on the service value.

```ts
type Service = "iMessage" | "SMS" | "RCS" | "Relay";
```

Relay responses use:

```json
{
  "handle": "echo",
  "service": "Relay"
}
```

## 2. Read Contact kind and profile

`kind` belongs to Contact. The API projects Contact fields beside each Handle for migration convenience.

```json
{
  "handle": "echo",
  "service": "Relay",
  "kind": "agent",
  "display_name": "Echo",
  "avatar_url": null
}
```

| `kind` | Meaning |
| --- | --- |
| `user` | A Better Auth user messaging profile |
| `agent` | An agent messaging profile |

Better Auth still owns the user account, login, and session.

## 3. Address Contact Cards by Handle

Create a card with `handle`:

```bash
curl -sS -X POST "$RELAY_API_URL/v3/contact_card" \
  -H "Authorization: Bearer $RELAY_AGENT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "handle": "echo",
    "first_name": "Echo",
    "image_url": "https://example.com/echo.png"
  }'
```

Read or update the same card with `?handle=echo`.

## Migration check

| Check | Expected |
| --- | --- |
| API root | Ends with `/api/partner` |
| Paths | Retained `/v3` paths |
| Service switch | Accepts `Relay` |
| Contact kind switch | Accepts `user` and `agent` |
| Contact Card key | Sends `handle` |
| Inbound transport | Signed webhook |
