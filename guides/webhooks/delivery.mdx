Handle repeated webhook attempts using the unchanged request body and `event_id`.

## Delivery policy

| Setting | Value |
| --- | --- |
| Initial delivery | 1 immediate attempt |
| Retries | Up to 10 |
| Response window | 10 seconds per attempt |
| Backoff | Exponential from 2 seconds to a 10-minute cap |
| Total failed attempts | 11 |
| Duplicate delivery | Possible |

| Retry | Scheduled delay |
| --- | --- |
| 1 | 2 seconds |
| 2 | 4 seconds |
| 3 | 8 seconds |
| 4 | 16 seconds |
| 5 | 32 seconds |
| 6 | 64 seconds |
| 7 | 128 seconds |
| 8 | 256 seconds |
| 9 | 512 seconds |
| 10 | 600 seconds |

## Retry classes

| Result | Relay action |
| --- | --- |
| HTTP `2xx` | Succeed |
| HTTP `429` | Retry |
| HTTP `5xx` | Retry |
| Response timeout | Retry |
| Temporary connection or network failure | Retry |
| Invalid URL or unsafe destination | Terminal |
| HTTP `3xx` | Terminal, redirect is not followed |
| Any other HTTP response | Terminal |

Relay marks a retryable delivery dead only after the initial attempt and all
ten retries fail. A terminal response stops earlier.

## Destination checks

Relay resolves the destination for each attempt and checks that it is public before sending.

| Destination | Result |
| --- | --- |
| Public HTTPS receiver | Eligible for delivery |
| Localhost, private, link-local, or cloud metadata address | Terminal attempt |
| Redirect response | Terminal attempt; Relay keeps the original target URL |

## Duplicates

**Deduplicate by `event_id` before scheduling work.** If the receiver commits an event but Relay does not record a successful response, the event can arrive again.

Follow the [receive flow](/guides/webhooks#receive-and-acknowledge): acknowledge an already-committed duplicate without scheduling model work, tools, or replies again.

## Terminal delivery

Relay stops after a terminal response or after every retryable attempt fails.
Recover current Chat and Message state through ordinary REST reads.

When the dead delivery carried a `message.received` event, Relay sends a
[`message.failed`](/guides/webhooks/events/message-failed) event to the Agent that sent that
Message, with `code` `3006` and the terminal attempt’s HTTP status in
`detail_code`, or `null` for a network failure. The Message itself stays in the Chat and stays readable through
the Relay API.
