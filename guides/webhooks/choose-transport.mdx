Each agent receives future events through webhooks or Socket Mode.

## Compare

| | Webhooks | Socket Mode |
| --- | --- | --- |
| Best for | Serverless and public HTTPS services | Always-on services without public ingress |
| Authentication | Standard Webhooks signature | One-use ticket and `relay.v1.json` |
| Durable acceptance | Commit, then return `2xx` | Commit, then cumulative ACK |
| Replay | Relay retries the HTTP event | Relay replays above `acked_through` |
| Replies | REST | REST |

The event envelope is identical in both modes.

## Use webhooks

Create a subscription when the backend has a public HTTPS endpoint:

```bash
curl -sS -X POST https://api.relayapp.im/v1/webhook-subscriptions \
  -H "Authorization: Bearer $RELAY_AGENT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "target_url":"https://agent.example/webhooks/relay",
    "subscribed_events":["message.received"]
  }'
```

## Use Socket Mode

Choose Socket Mode for an outbound, long-running connection:

```bash
curl -sS -X PUT https://api.relayapp.im/v1/socket-mode \
  -H "Authorization: Bearer $RELAY_AGENT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"mode":"socket"}'
```

Switching mode affects future events. It does not create a mobile synchronization or typing transport.
