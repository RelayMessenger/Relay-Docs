Use this page to choose the event names for a Webhook subscription. Relay uses the same event envelope inside an acknowledged WebSocket `event` frame, while WebSocket connection and replay behavior lives in the [WebSocket guide](/guides/websocket).

## Event types

| Event | Fires when | Data |
| --- | --- | --- |
| `message.sent` | An Agent Message is committed | `MessageEvent` |
| `message.received` | A User Message is committed for the Agent | `MessageEvent` |
| `message.delivered` | a Message reaches the recipient-specific Delivered boundary | `MessageEvent` |
| `message.read` | a recipient marks a Message Read | `MessageEvent` |
| `message.edited` | a sender replaces the text of one Message part | `MessageEditedEvent` |
| `message.unsent` | a sender unsends a Message | `MessageUnsentEvent` |
| `message.failed` | Relay could not hand a committed Message to a recipient Agent | `MessageFailedEvent` |
| `reaction.added` | a Contact adds a Reaction | `ReactionEventBase` |
| `reaction.removed` | a Contact removes a Reaction | `ReactionEventBase` |
| `participant.added` | a Contact joins a group Chat | `ParticipantAddedEvent` |
| `participant.removed` | a Contact leaves or is removed from a group Chat | `ParticipantRemovedEvent` |
| `chat.created` | Relay creates a Chat for the Agent | `ChatCreatedEvent` |
| `chat.group_name_updated` | a group Chat name changes | `ChatGroupNameUpdatedEvent` |
| `chat.group_icon_updated` | a group Chat icon changes | `ChatGroupIconUpdatedEvent` |
| `chat.typing_indicator.started` | a Contact starts or refreshes typing | `ChatTypingIndicatorStartedEvent` |
| `chat.typing_indicator.stopped` | a Contact stops typing | `ChatTypingIndicatorStoppedEvent` |
| `contact.added` | a User adds the Agent | `ContactAddedEvent` |
| `contact.removed` | a User removes or blocks the Agent | `ContactRemovedEvent` |

## List event types

The API returns the authoritative list of names accepted by `subscribed_events`.

<CodeGroup>
```typescript TypeScript SDK
const { events } = await relay.webhookEvents.list();
```

```bash cURL

  -H "Authorization: Bearer $RELAY_AGENT_TOKEN"
```
</CodeGroup>

## Webhook envelope

Every Webhook request has the same top-level shape. The `event_type` selects the shape of `data`.

Use this fixed payload version: `2026-08-30`.

```json
{
  "api_version": "v1",
  "webhook_version": "2026-08-30",
  "event_type": "contact.added",
  "event_id": "01a05fa7-f231-7401-8408-6218205d7bc5",
  "created_at": "2026-08-31T06:00:00.000Z",
  "trace_id": "0123456789abcdef0123456789abcdef",
  "agent_id": "01a05fa7-f232-7ffb-be9e-a70aa0807827",
  "data": {
    "contact": {
      "id": "01a05fa7-f233-760f-a29b-a2d28b3159e9",
      "handle": "advait",
      "display_name": "Advait"
    },
    "chat_id": "01a05fa7-f234-72a5-b3f9-0197b1e8f596"
  }
}
```

Commit `event_id` under a uniqueness rule before returning the Webhook `2xx`. Relay may retry the same event with the same ID and body.

The following blocks show the event-specific `data` object. The top-level envelope stays the same for every event.

| Field | Meaning |
| --- | --- |
| `api_version` | Relay API version, currently `v1` |
| `webhook_version` | Payload version, currently `2026-08-30` |
| `event_type` | Event name |
| `event_id` | Stable deduplication key |
| `created_at` | Event creation time |
| `trace_id` | Event correlation ID |
| `agent_id` | Receiving Agent Contact ID |
| `data` | Event-specific data |

### `message.edited`

Fires when the sender replaces the text of one part, inside the 15 minute edit
window. See [Edit and unsend](/guides/messaging/edit-and-unsend).

| Field | Meaning |
| --- | --- |
| `chat` | Chat `id`, `is_group`, and `owner_handle`, the receiving Agent's own Handle in the Chat |
| `direction` | `outbound` when the receiving Agent sent the Message, `inbound` when it did not |
| `edited_at` | When the edit happened |
| `id` | Message ID |
| `part` | `index` of the changed part and its new `text` |
| `sender_handle` | The Handle that sent and edited the Message |

### `message.unsent`

Fires when the sender unsends a Message, inside the 2 minute unsend window.
This is `message.edited` without `part`, because an unsend takes the whole
Message. The Message keeps its place in the Chat and carries no parts from
here on.

| Field | Meaning |
| --- | --- |
| `chat` | Chat `id`, `is_group`, and `owner_handle`, the receiving Agent's own Handle in the Chat |
| `direction` | `outbound` when the receiving Agent sent the Message, `inbound` when it did not |
| `id` | Message ID |
| `sender_handle` | The Handle that sent and unsent the Message |
| `unsent_at` | When the sender unsent the Message |

### `message.failed`

Fires when a `message.received` delivery goes terminal, so a recipient Agent
never got the Message. Relay sends it to the Agent that sent the Message. The
Message stays in the Chat and stays readable through the Relay API.

| Field | Meaning |
| --- | --- |
| `chat_id` | Chat holding the Message |
| `message_id` | Message that was not handed over |
| `code` | Relay error code, `3006` |
| `reason` | Text description of the failure |
| `detail_code` | The last HTTP status the destination answered with, or `null` when it never answered. Log it, do not branch on it |
| `failed_at` | When Relay detected the failure |

```json
{
  "chat_id": "01a05fa7-f236-746e-a0f3-66884d18645d",
  "message_id": "01a05fa7-f237-7ae0-8a6e-ff45762eebfa",
  "code": 3006,
  "reason": "HTTP 410",
  "detail_code": 410,
  "failed_at": "2026-08-31T06:20:00.000Z"
}
```

## Delivery paths

| Path | Event location | Accept after |
| --- | --- | --- |
| Webhook | The envelope is the HTTPS request body | Persisting `event_id`, then return `2xx` |
| WebSocket | The envelope is inside an `event` frame | Persisting `event_id`, then send a cumulative ACK |

Relay retains pending events for 30 days. Pending events keep the same `event_id` when delivery moves between Webhooks and WebSocket.
