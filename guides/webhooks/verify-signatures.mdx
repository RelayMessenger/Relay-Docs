Verify each webhook with the subscription’s signing secret and the exact request body.

## Before you start

Save `signing_secret` from the subscription’s [create response](/guides/webhooks/subscriptions#store-the-signing-secret) as `RELAY_WEBHOOK_SECRET` in your backend.

**Read the raw body before any JSON middleware transforms it.** Changing whitespace changes the signed bytes.

## Verify with the SDK

`unwrap` verifies the request and returns its parsed event envelope:

```typescript TypeScript SDK
import Relay from "@relaymessenger/sdk";

const relay = new Relay({
  apiKey: process.env.RELAY_AGENT_TOKEN!,
  baseURL: "https://api.staging.relayapp.im",
  webhookSecret: process.env.RELAY_WEBHOOK_SECRET!,
});

const rawBody = await request.text();
const event = relay.webhooks.unwrap(rawBody, {
  headers: request.headers,
});
```

| SDK input or method | Use |
| --- | --- |
| `rawBody` | Unmodified request body as a string or Buffer |
| `headers` | Request `Headers`, or a record with the lowercase webhook header names |
| `webhookSecret` | Default signing secret configured on the client |
| `key` | Optional per-call secret in `unwrap(rawBody, { headers, key })` or `verify(rawBody, { headers, key })` |
| `relay.webhooks.verify` | Verify without returning a parsed event |
| `relay.webhooks.unwrap` | Verify, then parse the JSON envelope |

## Signature format

Relay signs requests with Standard Webhooks:

| Header | Value |
| --- | --- |
| `webhook-id` | Stable event ID |
| `webhook-timestamp` | Attempt timestamp as Unix seconds |
| `webhook-signature` | `v1,<base64-signature>` |

The signing input joins the ID and timestamp with periods, followed by the raw body:

```text
webhook-id.webhook-timestamp.raw-body
```

Relay removes the `whsec_` prefix from the secret, base64-decodes the key, and computes HMAC-SHA256 over that input. The signature is the base64-encoded result.

Retries reuse the event ID and body and sign them with the attempt’s timestamp. Deduplicate by `event_id`, not by the signature.

## Handle verification failures

| Failure | Receiver action |
| --- | --- |
| Missing required header or invalid signature | Reject before storing or processing the event |
| Missing signing secret | Restore the secret from your backend’s secret store |
| Signature passes but JSON parsing fails | Reject the body rather than accepting a job |

The [receiver example](/guides/webhooks#receive-and-acknowledge) returns `401` when verification or parsing fails. [Delivery policy](/guides/webhooks/delivery#retry-classes) treats that response as terminal.
