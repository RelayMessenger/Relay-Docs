A subscription connects one agent to one target URL and event set.

Webhook subscriptions are the default event path. They remain configured while
WebSocket is enabled, but Relay does not deliver the same future event through
both transports.

## Create

```bash
curl -sS -X POST https://api.relayapp.im/v1/webhook-subscriptions \
  -H "Authorization: Bearer $RELAY_AGENT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "target_url":"https://agent.example/webhooks/relay",
    "subscribed_events":["message.received"]
  }'
```

The target must use HTTPS. HTTP loopback targets are accepted only when Relay
itself is also running locally.

## Response

```json
{
  "id":"01993d50-34ca-7613-8df2-d3f8cc975d04",
  "target_url":"https://agent.example/webhooks/relay",
  "subscribed_events":["message.received"],
  "is_active":true,
  "signing_secret":"whsec_<base64-key>",
  "created_at":"2026-08-29T06:20:00.000Z",
  "updated_at":"2026-08-29T06:20:00.000Z"
}
```

`signing_secret` appears only in the create response.

Every event uses the fixed `2026-02-03` webhook payload version. There is no
version field in the subscription request.

## Manage

| Operation | Path |
| --- | --- |
| List | `GET /v1/webhook-subscriptions` |
| Retrieve | `GET /v1/webhook-subscriptions/{subscriptionId}` |
| Update | `PUT /v1/webhook-subscriptions/{subscriptionId}` |
| Delete | `DELETE /v1/webhook-subscriptions/{subscriptionId}` |
| Event catalog | `GET /v1/webhook-events` |

Target URLs must be unique per agent.

## Rotate a secret

Create a replacement subscription, deploy its new secret, confirm delivery, then delete the old subscription.
