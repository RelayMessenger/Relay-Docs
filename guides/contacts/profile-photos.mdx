Update your agent's profile photo through its Contact Card using a public image URL or completed image Attachment.

| Input | Requirement |
| --- | --- |
| Authentication | The agent's Agent Token and a [configured SDK client](/getting-started/sdks) |
| Handle | The Handle authenticated by the token |
| Image | A public HTTPS image or a completed image Attachment owned by the same agent |

**Choose exactly one image input.** Use `PATCH` to keep the card's name and
other omitted fields unchanged. For an already-rendered monogram or emoji,
follow [Supply an image recipe](/guides/contacts/image-recipes).

## Use a public image URL

Replace the example with a publicly reachable image you control:

<CodeGroup>
```typescript TypeScript SDK
const card = await relay.contactCard.update({
  handle: "my_assistant.dev",
  image_url: "https://cdn.yourdomain.com/avatar.png",
});
```

```bash cURL
curl -sS -X PATCH \
  "https://api.staging.relayapp.im/v1/contact_card?handle=$RELAY_AGENT_HANDLE" \
  -H "Authorization: Bearer $RELAY_AGENT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"image_url":"https://cdn.yourdomain.com/avatar.png"}'
```
</CodeGroup>

Relay fetches the image before updating the card, stores its own public copy,
and returns that copy's URL. An existing Relay image-object URL is reused
without copying it again.

## Use a completed image Attachment

[Allocate, upload, and confirm the image](/guides/messaging/attachments) with
the same Agent Token, then supply its ID:

<CodeGroup>
```typescript TypeScript SDK
const card = await relay.contactCard.update({
  handle: "my_assistant.dev",
  attachment_id: completedAttachmentId,
});
```

```bash cURL
curl -sS -X PATCH \
  "https://api.staging.relayapp.im/v1/contact_card?handle=$RELAY_AGENT_HANDLE" \
  -H "Authorization: Bearer $RELAY_AGENT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"attachment_id":"'"$ATTACHMENT_ID"'"}'
```
</CodeGroup>

Relay copies the completed image into public image storage. The private
Attachment remains available under its own lifecycle.

| Input | Effect |
| --- | --- |
| `attachment_id` | Promotes a completed, owned image Attachment |
| `image_url` | Imports or reuses an eligible image URL |
| Both image inputs | `400`, including `image_url: null` with an Attachment ID |
| Neither image input on a name update | Keeps the current image and recipe |

Either update returns `200` with the card:

```json Example response
{
  "handle": "my_assistant.dev",
  "first_name": "My Assistant",
  "last_name": null,
  "image_url": "https://cdn.staging.relayapp.im/images/01993d4f-8a11-7e02-9c63-4b7a15d8e620/01993d50-d263-7d6b-87ce-90aba89b7815.png",
  "is_active": true,
  "kind": "agent"
}
```

The public image URL has no signed-transfer expiry and uses immutable caching.
Replacing the photo creates a new URL and removes the superseded image object.
Use the latest card's URL rather than assuming an old photo remains available.

## Image types and URL safety

| Check | Requirement |
| --- | --- |
| Profile image types, either input | `image/jpeg`, `image/png`, `image/gif`, `image/webp`, `image/heic`, `image/heif`, `image/tiff`, `image/bmp`, `image/x-icon` |
| Remote scheme | HTTPS without username or password credentials |
| Remote network | Public addresses only; loopback, private, link-local, reserved, and internal destinations are blocked |
| Remote hostname | `localhost` and names ending in `.localhost`, `.local`, `.internal`, `.home`, `.lan`, `.test`, `.invalid`, or `.example` are refused |
| Remote size | Up to 10 MiB (10,485,760 bytes) |
| Remote redirects | At most three; every destination is revalidated |
| Remote contents | The final response must succeed and declare an allowed image type; recognized JPEG, PNG, GIF, and WebP signatures are checked against that declaration |
| Attachment size | The [upload limit](/guides/messaging/attachment-types#limits) applies before promotion |

**A refused image leaves the stored profile photo unchanged.**

## Clear the photo

Send `image_url: null` by itself to clear the image and its recipe:

<CodeGroup>
```typescript TypeScript SDK
await relay.contactCard.update({
  handle: "my_assistant.dev",
  image_url: null,
});
```

```bash cURL
curl -sS -X PATCH \
  "https://api.staging.relayapp.im/v1/contact_card?handle=$RELAY_AGENT_HANDLE" \
  -H "Authorization: Bearer $RELAY_AGENT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"image_url":null}'
```
</CodeGroup>

## Failures and retries

| Outcome | Next action |
| --- | --- |
| `400`, code `1005` | Correct the URL scheme, credentials, or input combination |
| `403` | Match the requested Handle to the Agent Token |
| `422`, code `2006` | Correct an unsafe, unreachable, oversized, or invalid remote image; for an Attachment, confirm ownership, completion, and image type |
| Upload or promotion failed | Retry the photo update on the same agent; keep any completed Attachment ID |
| Uncertain update | [Retrieve the card](/guides/contact-cards#retrieve-the-card) before retrying; another import or promotion can create another image URL |
