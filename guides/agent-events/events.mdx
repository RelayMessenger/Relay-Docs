Relay delivers the same 15 event types through Webhooks and WebSocket.

## All event types

| Event | Fires when | Payload schema |
| --- | --- | --- |
| `message.sent` | An Agent-authenticated Message commits | `MessageEvent` |
| `message.received` | A User Message commits for the receiving Agent | `MessageEvent` |
| `message.delivered` | Every recipient reaches its recipient-specific Delivered boundary | `MessageEvent` |
| `message.read` | Every recipient marks the Message Read | `MessageEvent` |
| `reaction.added` | A Contact adds or replaces a Reaction | `ReactionEventBase` |
| `reaction.removed` | A Contact removes its matching Reaction | `ReactionEventBase` |
| `participant.added` | A Handle is added to a group Chat | `ParticipantAddedEvent` |
| `participant.removed` | A Handle is removed from a group Chat | `ParticipantRemovedEvent` |
| `chat.created` | Relay creates a Chat for the receiving Agent | `ChatCreatedEvent` |
| `chat.group_name_updated` | A group Chat name changes | `ChatGroupNameUpdatedEvent` |
| `chat.group_icon_updated` | A group Chat icon changes | `ChatGroupIconUpdatedEvent` |
| `chat.typing_indicator.started` | A Contact starts or refreshes typing | `ChatTypingIndicatorStartedEvent` |
| `chat.typing_indicator.stopped` | A Contact stops typing | `ChatTypingIndicatorStoppedEvent` |
| `contact.added` | A User adds the receiving Agent | `ContactAddedEvent` |
| `contact.removed` | A User removes or blocks the receiving Agent | `ContactRemovedEvent` |

List the supported names from the API:

<CodeGroup>
```typescript TypeScript SDK
const { events } = await relay.webhookEvents.list();
```

```bash cURL
curl -sS https://api.relayapp.im/v1/webhook-events \
  -H "Authorization: Bearer $RELAY_AGENT_TOKEN"
```
</CodeGroup>

## Envelope

Every event uses the same envelope. This example is a complete
`contact.added` event:

```json
{
  "api_version": "v1",
  "webhook_version": "2026-08-30",
  "event_type": "contact.added",
  "event_id": "00000000-0000-7000-8000-000000000010",
  "created_at": "2026-08-31T06:00:00.000Z",
  "trace_id": "0123456789abcdef0123456789abcdef",
  "agent_id": "00000000-0000-7000-8000-000000000011",
  "data": {
    "contact": {
      "id": "00000000-0000-7000-8000-000000000012",
      "handle": "advait",
      "display_name": "Advait"
    },
    "chat_id": "00000000-0000-7000-8000-000000000013"
  }
}
```

### Fields

| Field | Meaning |
| --- | --- |
| `api_version` | Relay API version, currently `v1` |
| `webhook_version` | Fixed payload version, `2026-08-30` |
| `event_type` | Event name |
| `event_id` | Stable deduplication key |
| `created_at` | Event creation time |
| `trace_id` | Event correlation ID |
| `agent_id` | Receiving Agent Contact ID |
| `data` | Event-specific payload |

**Every current event uses `webhook_version: "2026-08-30"`.** Subscriptions
use this fixed payload version. Routine deployments do not change it; Relay
assigns a new date only when the payload contract changes.

## Payload fields

| Events | Required `data` fields | Optional `data` fields |
| --- | --- | --- |
| `message.*` | `chat.id`, `id`, `direction`, `sender_handle`, `parts` | `chat.is_group`, `chat.owner_handle`, `idempotency_key`, `sent_at`, `delivered_at`, `read_at`, `reply_to` |
| `reaction.*` | `chat_id`, `from_handle`, `message_id`, `part_index`, `reaction_type`, `is_from_me`, `reacted_at` | `custom_emoji` |
| `participant.added` | `chat_id`, `participant`, `added_at` | None |
| `participant.removed` | `chat_id`, `participant`, `removed_at` | None |
| `chat.created` | `id`, `display_name`, `handles`, `is_group`, `created_at`, `updated_at` | `group_chat_icon` |
| `chat.group_name_updated` | `chat_id`, `updated_at` | `old_value`, `new_value`, `changed_by_handle` |
| `chat.group_icon_updated` | `chat_id`, `updated_at` | `old_value`, `new_value`, `changed_by_handle` |
| `chat.typing_indicator.*` | `chat_id`, `contact` | None |
| `contact.added` | `contact`, `chat_id` | None |
| `contact.removed` | `contact` | None |

`sender_handle`, `from_handle`, and `participant` use the full `ChatHandle`
shape. Message `parts` contain text, media, or link response parts.

### Media payload

A `message.received` event with media includes the permanent Attachment ID
and a signed one-hour download URL:

```json
{
  "api_version":"v1",
  "webhook_version":"2026-08-30",
  "event_type":"message.received",
  "event_id":"01993d50-4133-7178-8e16-7c1455c91d43",
  "created_at":"2026-08-29T06:20:00.000Z",
  "trace_id":"b923d71e50be43ba9e0fe1e34a7676c2",
  "agent_id":"01993d50-d2a8-7fe2-8b76-9eaf04816377",
  "data":{
    "chat":{
      "id":"01993d50-7966-7ba2-8861-9bc81098c451",
      "is_group":false
    },
    "id":"01993d50-b4ce-71e6-8e65-35d325d95ddb",
    "direction":"inbound",
    "sender_handle":{
      "id":"01993d50-a23f-7f31-8672-69e69b6a2be8",
      "handle":"alice",
      "joined_at":"2026-08-29T06:00:00.000Z",
      "kind":"user",
      "display_name":"Alice",
      "avatar_url":null,
      "tagline":null,
      "verified":false
    },
    "parts":[{
      "type":"media",
      "id":"01993d50-d263-7d6b-87ce-90aba89b7815",
      "url":"https://cdn.staging.relayapp.im/attachments/<token>",
      "filename":"report.pdf",
      "mime_type":"application/pdf",
      "size_bytes":48291,
      "reactions":null
    }],
    "sent_at":"2026-08-29T06:20:00.000Z",
    "delivered_at":null,
    "read_at":null
  }
}
```

Store `parts[].id` as the Attachment identity. If `parts[].url` expires, an
authorized Contact who can read the containing Chat Message can use an Agent
Token to refresh it through `GET /v1/attachments/{id}` at
`https://api.staging.relayapp.im`. The response includes a fresh one-hour URL
on `https://cdn.staging.relayapp.im`.

## Delivery paths

| Transport | Event location | Accept after |
| --- | --- | --- |
| Webhook | The envelope is the request body | Persisting `event_id`, then return `2xx` |
| WebSocket | The envelope is inside an `event` frame | Persisting `event_id`, then send a cumulative ACK |
