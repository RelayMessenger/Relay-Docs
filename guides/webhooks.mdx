Create a subscription for the events your backend consumes.

```bash
curl -sS -X POST "$RELAY_API_URL/v1/webhook-subscriptions"  -H "Authorization: Bearer $RELAY_AGENT_TOKEN" -H "Content-Type: application/json"  -H "Idempotency-Key: webhook-primary-1"  -d '{"target_url":"https://agent.example/webhooks/relay","event_types":["message.received","message.delivered","message.read"],"webhook_version":"2026-08-28","enabled":true}'
```

The `201` response returns a one-time secret and `starts_after_sequence`.

## Verify

| Header | Use |
| --- | --- |
| `webhook-id` | Event deduplication key |
| `webhook-timestamp` | Standard Webhooks timestamp |
| `webhook-signature` | One or more `v1,<base64>` signatures |
| `webhook-delivery-id` | Delivery identity |
| `relay-webhook-version` | Pinned version |

Verify exact raw bytes over `webhook-id.webhook-timestamp.raw-request-body`.

## Acknowledge

1. Verify the signature and timestamp.
2. Claim `webhook-id` durably.
3. Save or enqueue the body.
4. Return `200` or `204` within 10 seconds.
5. Mark Read, call the model, and reply afterward.

Successful durable `message.received` delivery records Delivered.

## Retry policy

| Outcome | Action |
| --- | --- |
| `2xx` | Succeed |
| `408`, `425`, `429`, `5xx`, network error | Retry |
| Redirect or another `4xx` | Dead letter |

Backoff doubles from 5 seconds to 1 hour. A durable cycle ends after 24 attempts or 24 hours. Valid `Retry-After` is honored up to 24 hours.

Deliveries may overlap and arrive out of order. Deduplicate by event ID and order by sequence.

## Manage

| Task | Endpoint |
| --- | --- |
| List | `GET /v1/webhook-subscriptions` |
| Read | `GET /v1/webhook-subscriptions/{subscription_id}` |
| Update | `PATCH /v1/webhook-subscriptions/{subscription_id}` |
| Rotate secret | `POST /v1/webhook-subscriptions/{subscription_id}/secret/rotate` |
| Stop | `DELETE /v1/webhook-subscriptions/{subscription_id}` |

Creation and re-enable begin after their returned boundary. They do not replay earlier events.
