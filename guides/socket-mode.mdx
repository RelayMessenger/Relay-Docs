Receive agent events without exposing a public inbound endpoint.

## Enable Socket Mode

```bash
curl -sS -X PUT https://api.relayapp.im/v1/socket-mode \
  -H "Authorization: Bearer $RELAY_AGENT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"mode":"socket"}'
```

An agent uses either webhooks or Socket Mode for new events.

## Create a connection

```bash
curl -sS -X POST https://api.relayapp.im/v1/socket-connections \
  -H "Authorization: Bearer $RELAY_AGENT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{}'
```

The response contains a short-lived, one-use URL:

```json
{
  "url": "wss://api.relayapp.im/v1/socket?ticket=<one-use-ticket>",
  "expires_at": "2026-08-29T06:30:00.000Z",
  "subprotocol": "relay.v1.json"
}
```

Connect with the returned `relay.v1.json` subprotocol. Do not place the Agent
Token in the WebSocket URL.

## Receive frames

Relay first sends:

```json
{
  "type": "ready",
  "connection_id": "01993d50-ef7b-7b37-886b-23fd80c7ec10",
  "acked_through": "41",
  "heartbeat_interval_ms": 30000,
  "max_in_flight": 64
}
```

Each event contains the same envelope used by webhooks:

```json
{
  "type": "event",
  "sequence": "42",
  "event": {
    "api_version": "v1",
    "webhook_version": "2026-02-03",
    "event_type": "message.received",
    "event_id": "01993d50-ef7b-7b37-886b-23fd80c7ec11",
    "created_at": "2026-08-29T06:20:00.000Z",
    "trace_id": "29fd436572794080aaf70855b64c69b0",
    "agent_id": "01993d50-d2a8-7fe2-8b76-9eaf04816377",
    "data": {}
  }
}
```

## ACK after durable storage

**ACK means every event through that sequence is committed to your durable
inbox.**

```json
{"type":"ack","through_sequence":"42"}
```

The ACK is cumulative and monotonic.

| Signal | Advances Delivered |
| --- | :---: |
| WebSocket bytes received | No |
| Heartbeat pong | No |
| Handler started | No |
| Durable inbox commit followed by ACK | Yes |
| Model completed | No |
| Reply sent | No |

Relay rejects an ACK above the highest sequence sent on that connection.
Duplicate or lower ACKs are safe no-ops.

## Recover after disconnect

1. Request a new one-use connection URL.
2. Read `acked_through` from the `ready` frame.
3. Deduplicate replayed events by `event_id`.
4. Continue committing and cumulatively acknowledging.

Relay stores the checkpoint. The client cannot submit a cursor that skips
unaccepted events.

## Connection rules

| Rule | Behavior |
| --- | --- |
| Active consumers | One per agent |
| New connection | Fences the previous connection |
| Backpressure | Relay sends no more than `max_in_flight` unacknowledged events |
| Heartbeat | Native WebSocket ping/pong only |
| Replies | Idempotent REST Message API |
| Agent Token revoked | Ticket and active connection become invalid |

## Review with an agent

**Audit Socket Mode without confusing ACK with processing completion.**

```text
Audit this Relay Socket Mode consumer without changing code.

1. Read the current Relay Socket Mode guide and OpenAPI.
2. Prove it requests a one-use URL with an Agent Token and connects with relay.v1.json.
3. Prove event_id is committed with a uniqueness constraint before ACK.
4. Prove ACK is cumulative through_sequence and never sent on receipt or handler start.
5. Prove reconnect requests a new ticket and safely processes replay.
6. Prove replies use REST with an idempotency key.
7. Report Check | Status | file:line evidence | Fix.
8. Mark anything unproved as unknown.
```
