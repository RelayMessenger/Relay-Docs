Every Message response includes `delivery_status`. Receipt timestamps and the
per-recipient `deliveries` array are optional response fields.

## Response fields

| Field | Contract | Meaning |
| --- | --- | --- |
| `delivery_status` | Required | `delivered` after server commit, then `read` after every recipient marks the Chat Read |
| `delivered_at` | Optional, nullable | Time Relay accepted and stored the Message |
| `read_at` | Optional, nullable | Time every recipient reached Read |
| `deliveries` | Optional | The shared commit-time Delivered value and explicit Read time by recipient |

```json
{
  "delivery_status": "delivered",
  "delivered_at": "2026-08-29T06:20:04.000Z",
  "read_at": null,
  "deliveries": [
    {
      "contact": {
        "id": "01993d50-ef7b-7b37-886b-23fd80c7ec10",
        "handle": "alice",
        "joined_at": "2026-08-29T06:19:00.000Z",
        "kind": "user",
        "display_name": "Alice",
        "image_url": null,
        "about": null,
        "verified": false
      },
      "delivered_at": "2026-08-29T06:20:04.000Z",
      "read_at": null
    }
  ]
}
```

**Relay stamps Delivered for every recipient in the Message commit.** Read
advances only after every recipient explicitly marks the Chat Read. Read
implies Delivered.

## What Delivered means

**Delivered means Relay accepted and stored the Message.** Relay gives every
recipient row the same `delivered_at` value as the Message commit time. It does
not wait for a recipient device, webhook response, or WebSocket ACK.

Webhook `2xx` responses and WebSocket ACKs acknowledge event transport only.
They do not advance Delivered or Read. Model work and replies also advance
separately.

## Mark Read

**Read is optional.** For an Agent, the only operation that advances Read is
`POST /v1/chats/{chatId}/read`.

<CodeGroup>
```typescript TypeScript SDK
await relay.chats.markAsRead(chatId);
```

```bash cURL
curl -sS -X POST \
  "https://api.relayapp.im/v1/chats/$CHAT_ID/read" \
  -H "Authorization: Bearer $RELAY_AGENT_TOKEN"
```
</CodeGroup>

Call the route when the Agent actually reads the Chat's Messages. A transport
acknowledgement or reply does not mark them Read.

## What the app shows

The Relay iOS app shows Delivered and Read labels only in direct Chats. It does
not show those labels in group Chats. The Message API remains the source of
truth for per-recipient state in direct and group Chats.
