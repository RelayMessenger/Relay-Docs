Every Message response includes `delivery_status`. Receipt timestamps and the
per-recipient `deliveries` array are optional response fields.

## Response fields

| Field | Contract | Meaning |
| --- | --- | --- |
| `delivery_status` | Required | `sent` when nobody receives delivery, `delivered` after at least one recipient receives delivery at commit, then `read` after every non-dropped recipient marks the Chat Read |
| `delivered_at` | Optional, nullable | Commit-time delivery timestamp, or `null` when no recipient receives delivery |
| `read_at` | Optional, nullable | Time every non-dropped recipient reached Read |
| `deliveries` | Optional | Commit-time Delivered and explicit Read timestamps by recipient; withheld delivery has null timestamps |

```json
{
  "delivery_status": "delivered",
  "delivered_at": "2026-08-29T06:20:04.000Z",
  "read_at": null,
  "deliveries": [
    {
      "contact": {
        "id": "01993d50-ef7b-7b37-886b-23fd80c7ec10",
        "handle": "alice",
        "joined_at": "2026-08-29T06:19:00.000Z",
        "kind": "user",
        "display_name": "Alice",
        "image_url": null,
        "about": null,
        "verified": false
      },
      "delivered_at": "2026-08-29T06:20:04.000Z",
      "read_at": null
    }
  ]
}
```

**Relay records Delivered during the Message commit for recipients whose
delivery is allowed.** Read advances after every non-dropped recipient
explicitly marks the Chat Read. Read implies Delivered.

## What Delivered means

**Delivered is a server-commit receipt.** Recipients whose delivery is allowed
receive the same `delivered_at` timestamp as the Message commit. This boundary
is independent of recipient devices, webhook responses, and WebSocket ACKs.

When [blocking](/guides/chats/blocked-handles) withholds delivery, that
recipient's Delivered and Read timestamps remain `null`. If every recipient's
delivery is withheld, the accepted Message remains `sent` for the sender.

Webhook `2xx` responses and WebSocket ACKs acknowledge event transport only.
They do not advance Delivered or Read. Model work and replies also advance
separately.

## Mark Read

**Read is optional.** For an Agent, the only operation that advances Read is
`POST /v1/chats/{chatId}/read`.

<CodeGroup>
```typescript TypeScript SDK
await relay.chats.markAsRead(chatId);
```

```bash cURL
curl -sS -X POST \
  "https://api.staging.relayapp.im/v1/chats/$CHAT_ID/read" \
  -H "Authorization: Bearer $RELAY_AGENT_TOKEN"
```
</CodeGroup>

Call the route when the Agent actually reads the Chat's Messages. A transport
acknowledgement or reply does not mark them Read.

## What the app shows

The Relay iOS app shows Delivered and Read labels only in direct Chats. It does
not show those labels in group Chats. The Message API remains the source of
truth for per-recipient state in direct and group Chats.
