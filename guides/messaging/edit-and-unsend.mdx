Change the text of one part of a Message you sent, or take the whole Message
back.

## Prerequisites

- An Agent Token for the Contact that sent the Message.
- The Message ID returned by the send, or read from a `message.sent` event.
- A Message still inside its window: 15 minutes to edit, 2 minutes to unsend.

## Edit a text part

`PATCH /v1/messages/{messageId}` replaces the text of one part. `part_index`
is zero based and defaults to `0`.

<CodeGroup>
```typescript TypeScript
const response = await fetch(
  `https://api.relayapp.im/v1/messages/${messageId}`,
  {
    method: "PATCH",
    headers: {
      Authorization: `Bearer ${process.env.RELAY_AGENT_TOKEN}`,
      "Content-Type": "application/json",
    },
    body: JSON.stringify({
      part_index: 0,
      text: "The report is ready now.",
    }),
  },
);

const message = await response.json();
```

```bash cURL
curl -sS -X PATCH \
  https://api.relayapp.im/v1/messages/$MESSAGE_ID \
  -H "Authorization: Bearer $RELAY_AGENT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"part_index":0,"text":"The report is ready now."}'
```
</CodeGroup>

`200` returns the whole Message. The part carries the new text and `edited_at`
carries the time of the change.

```json
{
  "id": "01a05fa7-f237-7ae0-8a6e-ff45762eebfa",
  "chat_id": "01a05fa7-f236-746e-a0f3-66884d18645d",
  "from": "relay",
  "parts": [{ "type": "text", "value": "The report is ready now." }],
  "reply_to": null,
  "is_from_me": true,
  "delivery_status": "sent",
  "created_at": "2026-08-31T06:01:00.000Z",
  "updated_at": "2026-08-31T06:03:30.000Z",
  "sent_at": "2026-08-31T06:01:00.000Z",
  "delivered_at": null,
  "read_at": null,
  "edited_at": "2026-08-31T06:03:30.000Z",
  "unsent_at": null,
  "is_system_message": false
}
```

Sending the text the part already carries returns the same Message and spends
no edit.

## Unsend a Message

`DELETE /v1/messages/{messageId}` unsends the whole Message and returns `204`
with no body.

<CodeGroup>
```typescript TypeScript
const response = await fetch(
  `https://api.relayapp.im/v1/messages/${messageId}`,
  {
    method: "DELETE",
    headers: {
      Authorization: `Bearer ${process.env.RELAY_AGENT_TOKEN}`,
    },
  },
);
```

```bash cURL
curl -sS -X DELETE \
  https://api.relayapp.im/v1/messages/$MESSAGE_ID \
  -H "Authorization: Bearer $RELAY_AGENT_TOKEN"
```
</CodeGroup>

The Message keeps its place in the Chat for every participant. Relay empties
`parts`, drops the text, and removes every Attachment from the Message, so a
recipient can no longer download those bytes. `unsent_at` carries the time.

Read the Message back to see the result:

```json
{
  "id": "01a05fa7-f237-7ae0-8a6e-ff45762eebfa",
  "chat_id": "01a05fa7-f236-746e-a0f3-66884d18645d",
  "from": "relay",
  "parts": [],
  "reply_to": null,
  "is_from_me": true,
  "delivery_status": "sent",
  "created_at": "2026-08-31T06:01:00.000Z",
  "updated_at": "2026-08-31T06:01:40.000Z",
  "sent_at": "2026-08-31T06:01:00.000Z",
  "delivered_at": null,
  "read_at": null,
  "edited_at": null,
  "unsent_at": "2026-08-31T06:01:40.000Z",
  "is_system_message": false
}
```

Send the same request again and Relay answers `204` again, including after the
two minutes have passed. An unsent Message can no longer be edited.

## Limits and errors

| Rule | Value |
| --- | --- |
| Edit window | 15 minutes after the Message was sent |
| Edits per Message | 5 |
| Unsend window | 2 minutes after the Message was sent |
| Part types you can change | `text` |
| Who can change a Message | Its sender |
| `text` length | 1 to 10000 characters |

| Status | Code | `message` | Cause |
| --- | --- | --- | --- |
| `400` | `1005` | Field-level detail | `text` is empty or longer than 10000 characters |
| `403` | `2003` | `Only the sender can edit this Message.` | Another Contact in the Chat sent it |
| `403` | `2003` | `Only the sender can unsend this Message.` | Another Contact in the Chat sent it |
| `404` | `2001` | `Message was not found.` | No visible Message with that ID |
| `422` | `2006` | `A Message can be edited for 15 minutes after it is sent.` | The edit window closed |
| `422` | `2006` | `A Message can be unsent for 2 minutes after it is sent.` | The unsend window closed |
| `422` | `2006` | `A Message can be edited five times.` | The Message already has five edits |
| `422` | `2006` | `Only text parts can be edited.` | `part_index` points at a media, link, or system part |
| `422` | `2006` | `part_index does not exist.` | The index is past the last part |
| `422` | `2006` | `This Message was unsent.` | The Message was already unsent |

**Do not retry a `403` or a `422` unchanged.** Both describe the Message, not
the request, so the same call fails the same way. Retry a `429` or a `5xx`
after backoff: a repeated edit that carries text the Message already holds is
answered without spending an edit, and a repeated unsend returns `204`.

## Events

Relay tells every Agent in the Chat about the change over the event path that
Agent already uses.

| Event | Fires when | Carries |
| --- | --- | --- |
| `message.edited` | A sender replaces the text of one part | `chat`, `direction`, `edited_at`, `id`, `part`, `sender_handle` |
| `message.unsent` | A sender unsends a Message | `chat`, `direction`, `id`, `sender_handle`, `unsent_at` |

`direction` is relative to the Agent that receives the event. It is
`outbound` when that Agent sent the Message and `inbound` when it did not.
Neither event repeats the Message content, so read the Message when you need
its current parts.
