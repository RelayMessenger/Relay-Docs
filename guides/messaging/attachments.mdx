Pre-upload files when you need trusted ownership, metadata, reuse, or files larger than 10 MB.

Staging separates API requests from byte transfer:

| Operation | Staging origin | Request | Access |
| --- | --- | --- | --- |
| Allocate or refresh | `https://api.staging.relayapp.im` | `POST /v1/attachments` or `GET /v1/attachments/{id}` | Agent Token |
| Upload | `https://uploads.staging.relayapp.im` | Raw `PUT` to the returned `upload_url` | Signed URL, valid for 15 minutes |
| Download | `https://cdn.staging.relayapp.im` | `GET` or `HEAD` on the returned `download_url` | Signed bearer URL, valid for 15 minutes |

**The `attachment_id` is permanent for the Attachment.** Store the ID and
treat upload and download URLs as short-lived capabilities.

## 1. Create an upload

<CodeGroup>
```typescript TypeScript SDK
const allocation = await relay.attachments.create({
  filename: "report.pdf",
  content_type: "application/pdf",
  size_bytes: bytes.byteLength,
});
```

```bash cURL
curl -sS -X POST https://api.staging.relayapp.im/v1/attachments \
  -H "Authorization: Bearer $RELAY_AGENT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "filename":"report.pdf",
    "content_type":"application/pdf",
    "size_bytes":48291
  }'
```
</CodeGroup>

The response contains an `attachment_id`, signed upload URL, HTTP method, exact required headers, and expiration time.

```json
{
  "attachment_id":"01993d50-d263-7d6b-87ce-90aba89b7815",
  "upload_url":"https://uploads.staging.relayapp.im/attachments/<token>",
  "download_url":"https://cdn.staging.relayapp.im/attachments/<token>",
  "http_method":"PUT",
  "expires_at":"2026-08-29T06:35:00.000Z",
  "required_headers":{
    "Content-Type":"application/pdf",
    "Content-Length":"48291"
  }
}
```

## 2. Upload the raw bytes

<CodeGroup>
```typescript TypeScript SDK
await relay.attachments.upload(allocation, bytes);
```

```bash cURL
curl -sS -X PUT "$UPLOAD_URL" \
  -H "Content-Type: application/pdf" \
  -H "Content-Length: 48291" \
  --data-binary @report.pdf
```
</CodeGroup>

Send the file bytes as the complete request body. Do not base64 encode them or
wrap them in multipart form data. The body length and `Content-Type` must match
the allocation.

The upload URL remains valid until `expires_at`, 15 minutes after allocation.
An interrupted or rejected upload remains `pending`, so retry the same URL
with the complete bytes while it is valid.

## 3. Confirm the upload

Retrieve the Attachment before sending it:

<CodeGroup>
```typescript TypeScript SDK
const attachment = await relay.attachments.retrieve(
  allocation.attachment_id,
);

if (attachment.status !== "complete") {
  throw new Error(`Attachment is ${attachment.status}.`);
}
```

```bash cURL
curl -sS \
  "https://api.staging.relayapp.im/v1/attachments/$ATTACHMENT_ID" \
  -H "Authorization: Bearer $RELAY_AGENT_TOKEN"
```
</CodeGroup>

Each successful retrieval returns the same permanent ID and a fresh
`download_url` that is valid for 15 minutes.

| Status | Meaning |
| --- | --- |
| `pending` | Relay is waiting for the complete upload |
| `complete` | The Attachment can be downloaded and sent |
| `failed` | The upload expired before completion |

Allocate a new Attachment after an upload expires.

## 4. Send the Attachment

<CodeGroup>
```typescript TypeScript SDK
await relay.chats.messages.send(chatId, {
  message: {
    parts: [{
      type: "media",
      attachment_id: allocation.attachment_id,
    }],
  },
});
```

```bash cURL
curl -sS -X POST "https://api.staging.relayapp.im/v1/chats/$CHAT_ID/messages" \
  -H "Authorization: Bearer $RELAY_AGENT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "message":{
      "parts":[{
        "type":"media",
        "attachment_id":"01993d50-d263-7d6b-87ce-90aba89b7815"
      }]
    }
  }'
```
</CodeGroup>

## 5. Download or delete

`retrieve` returns a signed `download_url` on
`https://cdn.staging.relayapp.im`. The URL grants bearer access for 15
minutes, so do not store it as the Attachment identity. Call
`GET https://api.staging.relayapp.im/v1/attachments/{id}` with an Agent Token
to replace an expired URL for an Attachment you allocated.

Downloads support one byte range at a time for audio, video, and resumable
file reads:

```bash
curl -sS "$DOWNLOAD_URL" \
  -H "Range: bytes=0-1048575" \
  --output attachment.part
```

A valid range returns `206` with `Content-Range`. An invalid or multiple range
returns `416`.

Delete an unreferenced Attachment:

<CodeGroup>
```typescript TypeScript SDK
await relay.attachments.delete(attachmentId);
```

```bash cURL
curl -sS -X DELETE \
  "https://api.staging.relayapp.im/v1/attachments/$ATTACHMENT_ID" \
  -H "Authorization: Bearer $RELAY_AGENT_TOKEN"
```
</CodeGroup>

## Import a public media URL

For files up to 10 MB, a `media` part can use a public HTTPS URL instead of a
pre-uploaded Attachment:

<CodeGroup>
```typescript TypeScript SDK
await relay.chats.messages.send(chatId, {
  message: {
    parts: [{
      type: "media",
      url: "https://cdn.yourdomain.com/report.pdf",
    }],
  },
});
```

```bash cURL
curl -sS -X POST "https://api.staging.relayapp.im/v1/chats/$CHAT_ID/messages" \
  -H "Authorization: Bearer $RELAY_AGENT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "message":{
      "parts":[{
        "type":"media",
        "url":"https://cdn.yourdomain.com/report.pdf"
      }]
    }
  }'
```
</CodeGroup>

Relay imports the bytes into an owned Attachment before committing the
Message.

| Check | Rule |
| --- | --- |
| Network | Every DNS answer must be on the public network |
| Redirects | Every hop is revalidated, with at most five redirects |
| Response | Final response must succeed |
| Size | Declared and actual body must each be 1 byte to 10 MB |
| Content type | Response Content-Type must be supported |

**Relay rejects credentials in the URL and blocks loopback, private,
link-local, reserved, and internal destinations.** A redirect cannot bypass
these checks.

## Media metadata

| Field | Applies to |
| --- | --- |
| `duration_ms` | Audio and video |
| `width`, `height` | Image and video |
| `filename` | Every Attachment |
| `content_type` | Every Attachment |
| `size_bytes` | Every Attachment |

Width and height must be supplied together.

## Image formats

Relay accepts JPEG, PNG, GIF, HEIC, TIFF, BMP, and WebP images. It rejects
SVG.

## Limits

| Boundary | Value |
| --- | ---: |
| Allocation size | 1 byte to 100 MB |
| Public HTTPS URL import | Up to 10 MB |
| Public URL media parts per Message | 40 |
| Total parts per Message | 100 |

## Ownership

| Action | Authorized Contact |
| --- | --- |
| Send or reuse | Contact that allocated the Attachment |
| Retrieve metadata and refresh the download URL | Contact that allocated the Attachment |
| Delete | Owner, while no Message or group photo references the Attachment |

Relay returns `404` when the caller does not own the Attachment. A signed
transfer URL grants bearer access until it expires, so keep it out of logs and
refresh it through the authenticated API rather than sharing a stored URL.

Media a user sends to you belongs to that user, so its URL cannot be refreshed.
Read [Receiving Media](/guides/messaging/receiving-media) for the inbound
path.
