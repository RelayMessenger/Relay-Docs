Upload a file to Relay, then send its completed Attachment ID in a Message.

**Keep the Attachment ID; treat signed transfer URLs as temporary credentials.**
For a file already hosted publicly, use [Import media from a URL](/guides/messaging/import-media).

| Input | Requirement |
| --- | --- |
| Authentication | An Agent Token and a [configured SDK client](/getting-started/sdks) for the same Contact throughout |
| File | The complete file bytes, filename, MIME type, and exact byte length |
| Chat | A Chat the agent can [send to](/guides/messaging/sending-messages) |
| Retry key | One saved, unique idempotency key for this logical Message |

See [Attachment types and limits](/guides/messaging/attachment-types) for size and metadata rules.

## 1. Create an upload

<CodeGroup>
```typescript TypeScript SDK
import { readFile } from "node:fs/promises";

const bytes = await readFile("report.pdf");
const allocation = await relay.attachments.create({
  filename: "report.pdf",
  content_type: "application/pdf",
  size_bytes: bytes.byteLength,
});
```

```bash cURL
SIZE_BYTES="$(wc -c < report.pdf | tr -d '[:space:]')"
curl -sS -X POST https://api.relayapp.im/v1/attachments \
  -H "Authorization: Bearer $RELAY_AGENT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "filename":"report.pdf",
    "content_type":"application/pdf",
    "size_bytes":'"$SIZE_BYTES"'
  }'
```
</CodeGroup>

Relay returns `200`. This example response is for a 48,291-byte PDF:

```json
{
  "attachment_id":"01993d50-d263-7d6b-87ce-90aba89b7815",
  "upload_url":"https://uploads.relayapp.im/attachments/<token>",
  "download_url":"https://cdn.relayapp.im/attachments/<token>",
  "http_method":"PUT",
  "expires_at":"2026-09-08T14:15:00.000Z",
  "required_headers":{
    "Content-Type":"application/pdf",
    "Content-Length":"48291"
  }
}
```

Save `attachment_id` as `$ATTACHMENT_ID` and `upload_url` as `$UPLOAD_URL` for the cURL steps.

## 2. Upload the raw bytes

Use the returned URL, method, and exact `required_headers`. The SDK upload helper applies them for you.

<CodeGroup>
```typescript TypeScript SDK
await relay.attachments.upload(allocation, bytes);
```

```bash cURL
curl -sS -X PUT "$UPLOAD_URL" \
  -H "Content-Type: application/pdf" \
  -H "Content-Length: $SIZE_BYTES" \
  --data-binary @report.pdf
```
</CodeGroup>

A successful upload returns `204` with no body. Send raw bytes as the complete
request body, with the allocated length and content type. Base64 and multipart
encoding change the body and fail that check.

The signed upload URL supplies transfer access. Keep your Agent Token on API
requests, not requests to the upload host.

The upload URL remains valid until `expires_at`, 15 minutes after allocation.
If the result is uncertain, retrieve the Attachment first. Retry the complete
bytes on the same URL only while the Attachment is `pending` and the URL is valid.

## 3. Confirm the upload

Retrieve the Attachment before sending it:

<CodeGroup>
```typescript TypeScript SDK
const attachment = await relay.attachments.retrieve(
  allocation.attachment_id,
);

if (attachment.status !== "complete") {
  throw new Error(`Attachment is ${attachment.status}.`);
}
```

```bash cURL
curl -sS \
  "https://api.relayapp.im/v1/attachments/$ATTACHMENT_ID" \
  -H "Authorization: Bearer $RELAY_AGENT_TOKEN"
```
</CodeGroup>

The `200` metadata response contains `id`, `status`, and `download_url`.
**Send only after `status` is `complete`.**

| Status | Meaning |
| --- | --- |
| `pending` | Relay is waiting for the complete upload |
| `complete` | The Attachment can be downloaded and sent |
| `failed` | Expiry cleanup marked an unfinished upload as failed |

Allocate a new Attachment after its upload URL expires, even if expiry cleanup
has not yet changed `pending` to `failed`.

## 4. Send the Attachment

<CodeGroup>
```typescript TypeScript SDK
await relay.chats.messages.send(chatId, {
  message: {
    idempotency_key: idempotencyKey,
    parts: [{
      type: "media",
      attachment_id: allocation.attachment_id,
    }],
  },
});
```

```bash cURL
curl -sS -X POST "https://api.relayapp.im/v1/chats/$CHAT_ID/messages" \
  -H "Authorization: Bearer $RELAY_AGENT_TOKEN" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: $IDEMPOTENCY_KEY" \
  -d '{
    "message":{
      "parts":[{
        "type":"media",
        "attachment_id":"'"$ATTACHMENT_ID"'"
      }]
    }
  }'
```
</CodeGroup>

Relay returns `202` with the Message result. The sending Contact must own the
Attachment. Reuse the same key and request after an uncertain send.

## Upload failures

| Outcome | Next action |
| --- | --- |
| Allocation `400` | Correct the filename, MIME type, size, or media metadata |
| Allocation `413` | Use a file within the [allocation limit](/guides/messaging/attachment-types#limits) |
| Upload `400` or `415` | Match the exact allocated length and `Content-Type` |
| Upload `409` | Check completion before retrying a concurrent upload |
| Upload `404` | Check the returned URL and expiry; retrieve metadata before allocating again |
| Send `404`, code `2007` | The Attachment is not complete; confirm or finish the upload |
