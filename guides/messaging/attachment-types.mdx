Relay Message Attachments accept any valid MIME type and preserve the uploaded bytes.

```json Allocation metadata
{
  "filename": "report.pdf",
  "content_type": "application/pdf",
  "size_bytes": 48291
}
```

## File types

| Rule | Value |
| --- | --- |
| MIME shape | `type/subtype` using MIME token characters, without parameters |
| Length | Up to 255 characters |
| Case | Normalized to lowercase |
| Invalid MIME value | `400`, code `1005` |
| Public URL import | Keeps a valid declared type; otherwise uses `application/octet-stream` |

**A declared MIME type describes how the file is served, not whether its contents are safe.**
Apply your application's own validation before processing downloaded files.

## Download safety

| Response header | Value |
| --- | --- |
| `Content-Type` | The stored MIME type |
| `X-Content-Type-Options` | `nosniff` |
| `Content-Security-Policy` | `sandbox; default-src 'none'` |
| `Referrer-Policy` | `no-referrer` |
| `Cache-Control` | `private, no-store` |

| Type | `Content-Disposition` |
| --- | --- |
| `image/*`, `audio/*`, `video/*`, `application/pdf` | `inline` |
| Every other type | `attachment` |

SVG can be allocated, uploaded, and downloaded under these same headers.
Unknown file types remain downloadable files.

## Media metadata

| Field | Requirement |
| --- | --- |
| `filename` | Required, 1 to 255 characters with no surrounding whitespace |
| `content_type` | Required MIME type |
| `size_bytes` | Required exact integer byte length |
| `duration_ms` | Optional nonnegative integer for audio or video |
| `width`, `height` | Optional positive integer pixel dimensions for images or video; supply both together |

## Limits

| Boundary | Value |
| --- | --- |
| Allocation size | 1 to 104,857,600 bytes, 100 MiB |
| Public HTTPS media import | 1 to 10,485,760 bytes, 10 MiB |
| Public URL media parts per Message | 40 |
| Total parts per Message | 100 |
| Upload URL lifetime | 15 minutes |
| Download URL lifetime | 60 minutes from issuance |

The upload and URL-import ceilings are also described as 100 MB and 10 MB in
the API; use the exact byte counts when validating files.

## Profile and group photos

Photo inputs have their own image-only checks:

| Use | Accepted input |
| --- | --- |
| [Profile photos](/guides/contacts/profile-photos) | A public image URL or completed owned Attachment with one of the profile-image MIME types |
| [Group photo](/guides/chats/group-photo) | A public image URL passing the image-ingestion checks, or a completed owned `image/*` Attachment |

Follow the photo guides for the allowed image types, URL safety checks, and
photo storage behavior.
