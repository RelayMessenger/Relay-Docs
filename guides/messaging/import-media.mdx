Send a public HTTPS file in a media part, and Relay imports the bytes into an Attachment owned by the sender.

## Prerequisites

| Input | Requirement |
| --- | --- |
| Authentication | An Agent Token and a [configured SDK client](/getting-started/sdks) |
| Chat | An existing Chat the agent can [send to](/guides/messaging/sending-messages) |
| Source URL | A publicly reachable HTTPS file available while Relay imports it |
| Retry key | One saved, unique idempotency key for this logical Message |

**Use [Upload attachments](/guides/messaging/attachments) for files above the
10 MB URL-import limit or files that require private source access.**
The exact limit is 10,485,760 bytes.

## Send the URL

Replace the example URL with a file you host. Use exactly one of `url` or
`attachment_id` in each media part.

<CodeGroup>
```typescript TypeScript SDK
const result = await relay.chats.messages.send(chatId, {
  message: {
    idempotency_key: idempotencyKey,
    parts: [{
      type: "media",
      url: "https://cdn.yourdomain.com/report.pdf",
    }],
  },
});
```

```bash cURL
curl -sS -X POST \
  "https://api.relayapp.im/v1/chats/$CHAT_ID/messages" \
  -H "Authorization: Bearer $RELAY_AGENT_TOKEN" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: $IDEMPOTENCY_KEY" \
  -d '{
    "message":{
      "parts":[{
        "type":"media",
        "url":"https://cdn.yourdomain.com/report.pdf"
      }]
    }
  }'
```
</CodeGroup>

Relay returns `202` after importing the file and committing the Message. Its
media part contains a Relay Attachment ID and signed download URL, rather
than relying on the source host for later downloads.

```json Returned media part
{
  "type": "media",
  "id": "01993d50-d263-7d6b-87ce-90aba89b7815",
  "url": "https://cdn.relayapp.im/attachments/<token>",
  "filename": "report.pdf",
  "mime_type": "application/pdf",
  "size_bytes": 48291,
  "reactions": null
}
```

## URL safety checks

**Every redirect and resolved address must pass the public-network checks.**

| Check | Requirement |
| --- | --- |
| Scheme and credentials | HTTPS, with no username or password in the URL |
| Network | Every resolved address must be public; loopback, private, link-local, reserved, and internal destinations are blocked |
| Hostname | `localhost` and names ending in `.localhost`, `.local`, `.internal`, `.home`, `.lan`, `.test`, `.invalid`, or `.example` are refused |
| Redirects | At most five; each destination is validated again |
| Response | The final response must succeed |
| Size | Actual body is 1 to 10,485,760 bytes; declared `Content-Length`, when present, must be valid and within the ceiling |
| Content type | Any valid declared MIME type; missing or unusable declarations become `application/octet-stream` |

Imported Attachments use the same [download headers and file-type rules](/guides/messaging/attachment-types)
as uploaded files.

## Failures and retries

| Outcome | Next action |
| --- | --- |
| `400` | Correct the media part or the Message's part count |
| `413`, code `2006` | Supply a nonempty file within the URL-import limit, or pre-upload it |
| `422`, code `2006` | Correct an unsafe URL, failed fetch, invalid redirect, or invalid response |
| Timeout or uncertain send | Retry the same request with the same idempotency key |
| `409` after changing a keyed request | Use a new key for a genuinely new Message |

Keep the source file available until the send result is confirmed. Retain the
returned Attachment ID for [eligible URL refreshes](/guides/messaging/receiving-media#refresh-eligibility).
