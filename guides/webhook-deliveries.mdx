Return `2xx` only after your system owns the event.

## Outcomes

| Endpoint result | Relay action |
| --- | --- |
| `2xx` | Mark delivery successful |
| `429` | Retry |
| `5xx` | Retry |
| Network error or timeout | Retry |
| Other `4xx` | Stop |
| Redirect | Stop |

Relay waits up to 10 seconds for one response.

## Retry schedule

Relay makes at most 10 attempts. The body and `webhook-id` remain unchanged across attempts.

| Retry after attempt | Centered delay |
| ---: | ---: |
| 1 | 3.5 seconds |
| 2 | 7 seconds |
| 3 | 14 seconds |
| 4 | 28 seconds |
| 5 | 56 seconds |
| 6 | 112 seconds |
| 7 | 224 seconds |
| 8 | 448 seconds |
| 9 | 600 seconds |

Each delay has up to 10 percent jitter. The centered retry window is 24 minutes 52.5 seconds.

## Duplicate handling

At-least-once delivery permits duplicates. Use `event_id` as the durable deduplication key.

```text
begin transaction
  insert event_id if absent
  save raw event or enqueue work
commit
return 204
```

If the insert finds an existing event, return `2xx` and skip repeated side effects.

## Crash behavior

| Crash point | Safe result |
| --- | --- |
| Before your commit | Return failure or disconnect, then accept a retry |
| After your commit and before `2xx` | Retry arrives, deduplication suppresses repeated work |
| After `2xx` | Process from your durable queue |

For `message.received`, Relay commits the webhook success and agent Delivered acknowledgement together. A failed local finalization causes another delivery.
