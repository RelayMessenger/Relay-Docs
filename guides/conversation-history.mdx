Read canonical Chat state after startup, foregrounding, or an explicit refresh.

## List Chats

```bash
curl -sS "$RELAY_API_URL/v1/chats?limit=20" \
  -H "Authorization: Bearer $RELAY_AGENT_TOKEN"
```

A Chat contains its ID, current Handles, direct-or-group state, timestamps, and current profile fields. No Chat or Handle carries a transport discriminator.

## List Messages

```bash
curl -sS "$RELAY_API_URL/v1/chats/$CHAT_ID/messages?limit=50" \
  -H "Authorization: Bearer $RELAY_AGENT_TOKEN"
```

Pass `next_cursor` unchanged when another page exists:

```bash
curl -sS "$RELAY_API_URL/v1/chats/$CHAT_ID/messages?limit=50&cursor=$NEXT_CURSOR" \
  -H "Authorization: Bearer $RELAY_AGENT_TOKEN"
```

| Field | Meaning |
| --- | --- |
| `messages` | Canonical Message projections |
| `next_cursor` | Opaque page token, or `null` |
| `parts` | Ordered projection from Apple `attributedBody` |
| `delivery_status` | Current aggregate state |
| `is_from_me` | Derived for the authenticated Handle |
| `is_system_message` | `true` for visible ordered group history |
| `system_event` | Actor, affected Contact, and group change data |

The page cursor continues one list operation. It is not a durable sync checkpoint.

## Membership visibility

**A Contact sees only Messages and group events from periods when it belonged
to the Chat.**

| Event | Visibility |
| --- | --- |
| Added to group | The added Contact sees this event and later activity |
| Earlier history | Hidden from a newly added Contact |
| Removed or left | The Contact sees this event |
| Later activity | Hidden after the membership period closes |
| Rejoined | A new membership period begins |

## Relay app flow

The current app reconciles through HTTP at finite lifecycle points:

| Trigger | Action |
| --- | --- |
| App startup | Read Chats and visible Messages |
| Foreground | Reconcile canonical resources |
| Explicit refresh | Reconcile canonical resources |
| Successful send | Perform one follow-up reconciliation |

There is no successful-state polling timer. Agent-only Socket Mode is not a
mobile synchronization source.

## Agent flow

Agents receive events through signed webhooks or Socket Mode. Use history reads
after restart or an uncertain REST request, not as polling.
