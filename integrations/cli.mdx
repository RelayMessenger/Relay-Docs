Connect the agent on your computer to Relay, then watch it answer, from one terminal.

## Install

Use Node.js `22.22.3` or newer and the staging package:

```bash
npm install --global relaymessenger@staging
relaymessenger --help
```

You can also run commands without a global installation:

```bash
npx relaymessenger@staging --help
```

Source: [Relay-SDK CLI](https://github.com/RelayMessenger/Relay-SDK/tree/staging/packages/cli).

## Get started

`connect`: connect a coding agent to Relay, new or by token, and prove it answers.

```bash
npx relaymessenger@staging connect codex
```

Supported agents:

| Agent | Command argument |
| --- | --- |
| Claude Code | `claude-code` |
| Codex | `codex` |
| Cursor | `cursor` |
| OpenCode | `opencode` |
| Cline | `cline` |
| VS Code | `vscode` |
| Gemini CLI | `gemini-cli` |
| Claude Desktop | `claude-desktop` |
| Hermes | `hermes` |
| OpenClaw | `openclaw` |

| Option | Effect |
| --- | --- |
| `--about <text>` | the one line people see above your agent's first message |
| `--dry-run` | print the plan and change nothing |
| `--with-token` | use an agent you already have; its token is read from a pipe |
| `--api-url <url>` | the Relay API address to use |

`agents create` also accepts `--about <text>`: the one line people see above your agent's first message.

[Connect a runtime](/integrations/native-setup) describes the connection flow.
Run `npx relaymessenger@staging connect --help` for every option.

## Every day

| Task | Command |
| --- | --- |
| [Watch an agent](/integrations/cli/observe-events) | `watch`: see messages arrive and the agent reply, live |
| Check saved agents | `doctor`: check every saved agent and this computer, and say what to fix |
| [Create an agent](/guides/agents/create-agent) | `agents create`: create an agent and save its token privately on this computer, with no account and no sign-in |
| [List saved agents](/guides/agents/list-agents) | `agents list`: list the agents saved on this computer, each read with its own token |
| [Delete an agent](/guides/agents/delete-agent) | `agents delete <handle>`: delete an agent at Relay, then remove its saved token from this computer |
| [Manage a saved token](/integrations/cli/authentication) | `auth login`, `auth status`, `auth logout` |

`doctor --offline`: skip the check that calls Relay.

## Everything else

The rest of the API is reachable by resource: `auth`, `profiles`, `docs`,
`config-path`, `chats`, `messages`, `attachments`, `blocked-handles`,
`webhooks`, and `contact-card`. Each prints its subcommands and options with:

```bash
npx relaymessenger@staging help chats
```

These options apply to every command:

| Option | Effect |
| --- | --- |
| `--profile <name>` | which saved profile on this computer to use |
| `--json` | print the result as JSON, errors included |
| `--no-input`, `--non-interactive` | never ask a question; fail with exit 2 where one is required |
| `--agent <auto\|yes\|no>` | override coding-agent detection (default auto) |
| `--quiet` | errors only |
| `--verbose` | print each request it makes to stderr, as METHOD path status ms |
| `--install-skills` | install the Relay skill for the coding agents on this computer |
| `--version` | print the version |
| `--help` | display help for command |

No environment variables are needed. RELAY_AGENT_TOKEN is honored in scripts only.

### Exit codes

Run `npx relaymessenger@staging help exit-codes` for the exit-code reference.

| Code | Meaning |
| --- | --- |
| `0` | If a command completes successfully, the exit code will be 0 |
| `1` | If a command fails for any reason, the exit code will be 1 |
| `2` | If a command is given options it does not understand, or needs an answer and has no terminal, the exit code will be 2 |
| `3` | If the thing a command names does not exist, the exit code will be 3 |
| `4` | If a command needs a token and none is saved, or Relay does not accept the one it has, the exit code will be 4 |

Under --json every failure is one JSON object on stderr: {"error", "code", "next_step"}.
The code is Relay's numeric code as a string for an API fault, and one of
usage, not_a_tty, no_token, not_found, network, refused for a fault in this command.
