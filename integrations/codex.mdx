## Before you start

- [Codex](https://github.com/openai/codex#quickstart), installed and signed in.
- Node.js 22.22.3 or newer.

## Connect

Run this in the folder where you work to connect codex to Relay.

```bash
npx relaymessenger@staging connect codex
```

In an unlinked folder, this creates a new agent by default. If the folder is already linked, it uses that agent. Use `--handle` or `--name` to customize the new agent.

then scan the QR with Relay on your phone to add the agent, and send it a message. Leave the command running: it answers each message with Codex from the folder you ran it in. Control-C stops it.

### Do it by hand

```bash
codex plugin marketplace add RelayMessenger/Relay-SDK@staging
codex plugin add relay@relay-plugin-marketplace
```

## Send it a message

Open Relay on your phone and message the handle. While connect runs, Codex answers on its own in the same chat, and each chat keeps its own Codex session.

## What it can do

These come from the connection code for `codex` and the Relay MCP tool list.

| Relay feature | Codex |
| --- | --- |
| Connect | Codex's own `codex mcp add` writes the Relay MCP server into `~/.codex/config.toml`. |
| Start | Connect stays running and holds `codex app-server` open in its folder. Each chat keeps its own thread. |
| Wakes when a message arrives | Yes, while connect runs, one message at a time. |
| Reply in the chat | Yes, text up to 10,000 characters, with a stable idempotency key. |
| Send attachments | No. The MCP tools send text only. |
| Receive attachments | Yes. Photos and files are saved under ~/.config/relay/media and their paths are added to the message. Codex also receives the image itself. |
| Read chat history | Yes, by chat, oldest or newest first, one page at a time. |
| React, type, mark read | Yes, with reactions, typing indicators, and read marks. |
| Contact card | Yes, read and set the agent's name and picture. |
| Buttons | Yes; see [Buttons](/interactions/buttons). A tap comes back as a message whose text is the label. |
| Link preview | Yes; a URL alone on its own line in the answer goes out as its own link message, drawn as a card; see [Rich link previews](/messages/rich-link-previews). |

## When it fails

- `No reply yet. Run: relay watch @<handle>` Connect is not running, or Codex is still working; run connect again and it answers from there.

Use the [CLI guide](/cli/index) for prompt, token, and restart errors.

[Selection](/interactions/selection). End the final answer with a `selection` JSON fence holding the question as `title` (1 to 60 characters) and the `options`; any words outside the fence go as a normal message above the card. The app-server prompt preserves `selected_values`, `reply_to`, and ordered rich parts as data alongside the readable bullet text.

[Payments](/interactions/payments). End the final answer with a `payment` JSON fence holding the payment request's fields, named as in the API. Connect creates the request with its own Relay token, any words before it go out first, and the card follows as its own Message. If Relay refuses the request, the terminal says why and sends no card.
