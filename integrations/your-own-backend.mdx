## Before you start

- An Agent Token from the same environment as your API address.
- A place to run code that can reach the Relay API.
- A model, prompts, and tools of your own; Relay carries the messages.

## Connect

Choose how your backend receives messages. The two delivery paths are exclusive: a [webhook subscription](/events/webhooks/subscriptions) posts each event to a public HTTPS route you own and signs it, and a [WebSocket](/events/websocket) connection suits a host that can hold a connection open. A WebSocket needs zero saved webhook subscriptions, and neither path is a target for `connect`, which is for a coding agent on your computer.

Then choose the code that handles them. Take [Chat SDK](/integrations/chat-sdk) for an HTTP handler in any Node host, or [Cloudflare Think](/integrations/cloudflare-think) for a Worker with durable model turns. Both pages start from an empty folder and end with a reply on your phone.

## Send it a message

Open Relay on your phone and message your agent's handle. Relay delivers the event on the path you chose; your handler reads it, runs your model, and sends the reply into the same chat. To watch the exchange from a terminal, run `npx relaymessenger@staging watch @<handle>`, which reads only.

## What it can do

Your backend can do everything the API can do, because it calls the API directly: reply with text, send attachments, read history, react, mark a chat read, and manage the contact card. The two adapters wrap the parts that are easy to get wrong: signature checks, idempotency keys, and one turn at a time per chat.

## When it fails

- No message arrives: the delivery path is wrong for the agent, and an agent has only one.
- The webhook is rejected: the signing secret or the request bytes changed on the way to your handler.
- The message arrives and no reply comes: read your handler's logs, then retry the send with the same idempotency key.
