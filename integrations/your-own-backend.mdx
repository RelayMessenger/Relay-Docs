Run your own code as the agent: read each message and choose its reply.

## Before you start

You need an Agent Token from the same environment as your API address, and a place to run code that can reach the Relay API. Your backend owns the model, the prompts, the tools, and the hosting; Relay carries the messages. This page is the map; the two pages it points to carry the code.

## Connect

Choose how your backend receives messages, then choose the code that handles them. There are two delivery paths and they are exclusive. A [webhook subscription](/events/webhooks/subscriptions) posts each event to a public HTTPS route you own and signs it; keep the signing secret and pass the request body to your handler unchanged. A [WebSocket](/events/websocket) connection is for a host that can hold a connection open; it needs zero saved webhook subscriptions. Neither is a target for `connect <agent>`: that command is for a coding agent on your computer.

For the handler, take [Chat SDK](/integrations/chat-sdk) when you want an HTTP handler in any Node host, or [Cloudflare Think](/integrations/cloudflare-think) when you want a Worker with durable model turns. Both pages start from an empty folder and end with a reply on your phone.

## Send it a message

Open Relay on your phone and send a message to your agent's handle. Relay delivers the event to your backend on the path you chose; your handler reads it, runs your model, and sends the reply through the API. The reply appears in the same chat. To watch the exchange from a terminal, run `npx relaymessenger@staging watch @<handle>`; it reads only and never consumes an event.

## What it can do

Your backend can do everything the API can do, because it calls the API directly. It can reply with text, send attachments, read history, react, mark a chat read, and manage the agent's contact card. The two adapters wrap the parts that are easy to get wrong: signature checks, idempotency keys, and one turn at a time per chat.

## When it fails

If no message arrives, the delivery path is wrong for the agent. An agent with a saved webhook subscription never gets a WebSocket, and one without never gets a webhook. If the webhook is rejected, the signing secret or the request bytes changed on the way to your handler. If the message arrives and no reply comes, the failure is in your handler or model. Read its logs, and reuse the same idempotency key when you retry a send.
