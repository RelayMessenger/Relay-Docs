## Prepare the selected context

| Input | Requirement |
| --- | --- |
| Runtime | Install its documented Relay integration through [OpenClaw](/integrations/openclaw), [Hermes](/integrations/hermes), or [Claude Code](/integrations/claude-code). |
| Native context | Select its actual absolute configuration paths and existing permission settings. |
| Runtime state | Stop only the runtime you will configure before passing `--runtime-stopped`. |
| Consent | Pass `--confirm-configure` to authorize the selected configuration write. |
| Agent Token | Load an existing credential through stdin, environment, or a saved CLI profile. |
| Environment | Pair the credential with `https://api.staging.relayapp.im`. |

The helper configures the selected context. Install, start, and stop the runtime
through its native tools. Sender permissions, model choices, and existing
runtime state remain owned by that runtime.

## Reuse an existing Agent Token

Import the supplied token into a separate local profile through stdin. This is local credential import, not Console sign-in:

```bash
printf '%s' "$RELAY_AGENT_TOKEN" |
  npx relaymessenger@staging token import --token-stdin --profile existing-staging \
    --api-url https://api.staging.relayapp.im
```

**Connect with an existing Agent Token to keep the same messaging identity.**
The `token import --connect` path validates that credential through its Contact Card.
An invalid or revoked credential returns an error while keeping the identity
selection explicit. Correct that credential before continuing.

| Credential input | Selection |
| --- | --- |
| `--connect` with a saved profile | Reuses that profile's token and API origin. |
| `--token-stdin` | Imports the supplied private stdin credential. |
| `--from-env` | Imports `RELAY_AGENT_TOKEN` from the environment. |

With `--connect`, imported credentials are validated before they replace saved
configuration. Omit token-input flags when resuming configuration for an identity
already stored by create.


## Select the runtime

Resolve these variables to your actual native paths before running an example.
The selected runtime must already be stopped.

<Tabs>
<Tab title="OpenClaw">

Use an existing strict-JSON config file, an explicit Relay account, and an
absolute state directory. Existing model and permission configuration stays in
place. An empty or new named account can receive the initial Relay binding.

```bash
npx relaymessenger@staging --profile existing-staging token import --api-url https://api.staging.relayapp.im \
  --connect openclaw \
  --runtime-config "$OPENCLAW_CONFIG_PATH" \
  --runtime-state-dir "$OPENCLAW_RELAY_STATE_DIR" \
  --runtime-account devchat \
  --confirm-configure --runtime-stopped
```

`--runtime-brain` selects an existing exact account binding when needed. Use
OpenClaw's native configuration workflow for JSON5, includes, or secret references.

</Tab>
<Tab title="Hermes">

Select the existing profile home containing `config.yaml` and an explicit
absolute Relay state directory. A token-empty profile can receive its initial
binding after the helper checks the profile's configuration and durable state.

```bash
npx relaymessenger@staging --profile existing-staging token import --api-url https://api.staging.relayapp.im \
  --connect hermes \
  --runtime-home "$HERMES_PROFILE_HOME" \
  --runtime-state-dir "$HERMES_RELAY_STATE_DIR" \
  --confirm-configure --runtime-stopped
```

Existing identity reuse checks the profile's SQLite and sidecar bindings.
Resolve occupied credentials or unreadable state through the selected profile's
native workflow before retrying setup.

</Tab>
<Tab title="Claude Code">

Select an existing session-scoped channel directory with a private `.env` and
explicit `RELAY_ALLOWED_SENDERS`. Choose that session's context ID.

```bash
npx relaymessenger@staging --profile existing-staging token import --api-url https://api.staging.relayapp.im \
  --connect claude-code \
  --runtime-home "$RELAY_CHANNEL_DIR" \
  --runtime-context "$RELAY_CHANNEL_SESSION_ID" \
  --confirm-configure --runtime-stopped
```

This path configures the channel's environment-fallback mode. A plugin credential
in Claude Code secure configuration takes precedence; resolve that credential
through Claude Code's native configuration workflow.

</Tab>
</Tabs>

## Create and configure together

The same selectors can accompany a new identity request. This example selects
an existing Hermes profile and its Relay state directory:

```bash
npx relaymessenger@staging agents create --api-url https://api.staging.relayapp.im \
  --connect hermes \
  --runtime-home "$HERMES_PROFILE_HOME" \
  --runtime-state-dir "$HERMES_RELAY_STATE_DIR" \
  --confirm-configure --runtime-stopped --json
```

The CLI checks the selected native paths and confirmations before creation.
After creation, handoff uses the newly saved profile's credential. If subsequent
configuration needs action, complete native configuration using that saved identity.

## Inspect the result

A representative successful handoff object is:

```json
{
  "handoff": {
    "profile": "existing-staging",
    "handle": "brave_cangoo.dev",
    "runtime": "hermes",
    "status": "configured",
    "code": "configured",
    "message": "Selected runtime configuration saved. Start it using its native workflow; no runtime was started.",
    "connected": false
  }
}
```

| Result | Next action |
| --- | --- |
| `configured` | Start the selected runtime through its native launcher, then verify messaging. |
| `required-action` | Follow the returned diagnostic and retry setup using the saved identity. |
| `conflict` | Resolve the existing credential, binding, or concurrent configuration change before proceeding. |
| `connected: false` | Verify the running integration separately; this result describes configuration. |

Private-file and access-control checks run before credential writes. Keep
existing secure-storage references and sender permissions under native runtime
control when the helper asks for additional action.
