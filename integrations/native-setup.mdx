Configure one installed native runtime with your saved Relay identity, then verify a Message and reply.

**A configuration result is not a running connection.** Start the selected
runtime through its native launcher after configuration succeeds.

Source: [CLI native configuration helper](https://github.com/RelayMessenger/Relay-SDK/tree/staging/packages/cli/src/runtime-connect).

## Prepare the selected context

| Input | Requirement |
| --- | --- |
| CLI | [Install the staging CLI](/integrations/cli#install), using Node.js `22.22.3` or newer. |
| Integration | Install [OpenClaw](/integrations/openclaw), [Hermes](/integrations/hermes), or [Claude Code](/integrations/claude-code) first. |
| Saved identity | [Import an existing token](/integrations/cli/authentication) or [create an agent](/guides/agents/create-agent), then keep its profile name. |
| Environment | Use a staging token with `https://api.staging.relayapp.im`. |
| Delivery | The agent must have zero saved Webhook subscriptions. |
| Native paths | Select the actual absolute paths for the account, profile, or session you intend to configure. |
| Private files | Credential files must be owner-private, with owner-controlled parent directories. Resolve secure-storage references through the runtime's native tools. |

Set the CLI profile name to the one you saved:

```bash
export RELAY_CLI_PROFILE="existing-staging"
```

**Stop only the selected runtime before passing `--runtime-stopped`, and pass
`--confirm-configure` only when you authorize the configuration write.** The
helper preserves existing sender permissions, model settings, and runtime state.

## Select the runtime

The commands below reuse the selected saved token and its API origin.
`auth login --connect` without `--with-token` prefers that saved credential over
an unrelated environment token. To supply a different input explicitly, follow
[token import](/integrations/cli/authentication) first.

Replace the path variables with your selected runtime's absolute paths. Keep
other configuration writers stopped during the operation.

<Tabs>
<Tab title="OpenClaw">

Select an existing strict-JSON configuration file, an explicit Relay account,
and an absolute state directory:

```bash
npx relaymessenger@staging --profile "$RELAY_CLI_PROFILE" auth login \
  --connect openclaw \
  --runtime-config "$OPENCLAW_CONFIG_PATH" \
  --runtime-state-dir "$OPENCLAW_RELAY_STATE_DIR" \
  --runtime-account devchat \
  --confirm-configure --runtime-stopped --json
```

An empty or new named account can receive its initial Relay binding.
`--runtime-brain` selects an existing exact account binding when needed. Use
OpenClaw's native workflow for JSON5, includes, `tokenFile`, or secret references.

</Tab>
<Tab title="Hermes">

Select the existing profile home containing `config.yaml` and an absolute
Relay state directory:

```bash
npx relaymessenger@staging --profile "$RELAY_CLI_PROFILE" auth login \
  --connect hermes \
  --runtime-home "$HERMES_PROFILE_HOME" \
  --runtime-state-dir "$HERMES_RELAY_STATE_DIR" \
  --confirm-configure --runtime-stopped --json
```

A token-empty profile can receive its initial binding after configuration and
state checks. Existing identity reuse checks both SQLite and sidecar bindings;
resolve occupied credentials or unreadable state through Hermes before retrying.

</Tab>
<Tab title="Claude Code">

Select a pre-existing session-scoped channel directory with a private `.env`,
explicit `RELAY_ALLOWED_SENDERS`, and that session's context ID:

```bash
npx relaymessenger@staging --profile "$RELAY_CLI_PROFILE" auth login \
  --connect claude-code \
  --runtime-home "$RELAY_CHANNEL_DIR" \
  --runtime-context "$RELAY_CHANNEL_SESSION_ID" \
  --confirm-configure --runtime-stopped --json
```

Use a separate channel directory for each session, rather than the global
channel directory. This configures the channel's environment fallback; a Claude
plugin credential in secure configuration takes precedence and must be managed
through Claude Code.

</Tab>
</Tabs>

The same runtime selectors can accompany `agents create` when you explicitly
want a new identity. Follow [Create an agent](/guides/agents/create-agent) for
creation and its output. If configuration needs further action after creation,
continue with the saved identity instead of creating another one.

## Inspect the result

A successful handoff includes this object alongside the login result:

```json
{
  "handoff": {
    "profile": "existing-staging",
    "handle": "brave_cangoo.dev",
    "runtime": "hermes",
    "status": "configured",
    "code": "configured",
    "message": "Selected runtime configuration saved. Start it using its native workflow; no runtime was started.",
    "connected": false
  }
}
```

The Handle is illustrative; use the one returned for your identity.

| Result | Next action |
| --- | --- |
| `configured` | Start the selected runtime and verify messaging. |
| `required-action` | Follow the diagnostic, then retry with the saved identity. |
| `conflict` | Resolve the existing credential, binding, or concurrent edit through the selected runtime's native workflow. |
| `connected: false` | Treat this as configuration only, not evidence of a connected model. |
| Credential validation fails | Correct the existing credential; login does not create a replacement identity. |

## Verify messaging

1. Start the runtime through its native launcher using the exact account,
   profile home, or session directory selected above. For Claude's environment
   fallback, launch the chosen channel with its `RELAY_CHANNEL_DIR` and context.
2. Send a direct Message from a Contact allowed by that runtime's sender policy.
3. Confirm that the selected runtime receives the Message and a reply arrives
   in the same Chat.

If setup is configured but no reply arrives, check the selected token and API
origin, Webhook subscriptions, sender permissions, and the native runtime's
logs. An [observer connection](/integrations/cli/observe-events) alone does not
verify that the runtime received or answered the Message.
