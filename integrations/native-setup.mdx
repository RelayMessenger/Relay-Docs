Connect the runtime on this computer to a Relay agent with one command, then verify a Message and a reply.

Source: [CLI connect](https://github.com/RelayMessenger/Relay-SDK/tree/staging/packages/cli/src/runtime-connect).

## Prepare

| Input | Requirement |
| --- | --- |
| CLI | [Install the staging CLI](/integrations/cli#install), using Node.js `22.22.3` or newer. |
| Runtime | Install [Claude Code](/integrations/claude-code) first. Relay looks for it on this computer. |
| Agent | None needed. To reuse an agent, keep its Agent Token in your secret store; to save a token without connecting, follow [CLI authentication](/integrations/cli/authentication). |
| Environment | A staging token pairs with `https://api.staging.relayapp.im`. |
| Delivery | The agent must have zero saved Webhook subscriptions. |
| Phone | Relay on your phone, to add the agent and send it the first message. |

## Connect

`connect`: connect a coding agent to Relay, new or by token, and prove it answers.

Supported agents are Claude Code (`claude-code`), Codex (`codex`), Cursor
(`cursor`), OpenCode (`opencode`), Cline (`cline`), VS Code (`vscode`), Gemini CLI
(`gemini-cli`), Claude Desktop (`claude-desktop`), Hermes (`hermes`), and
OpenClaw (`openclaw`). The example below connects Claude Code.

Run the command in a terminal:

```bash
npx relaymessenger@staging connect claude-code
```

Relay says what it found, prints its plan, and asks `Continue?` before it
writes anything. Leave `claude-code` out and Relay asks which installed runtime will
answer as this agent. Then it:

1. Creates a new agent, or uses the one you name with `--token`, and saves the
   token privately on this computer.
2. Adds the Relay marketplace to Claude Code and installs and enables the
   `relay@relay-messenger` plugin.
3. Writes the channel file, owner-only, with `RELAY_AGENT_TOKEN`,
   `RELAY_BASE_URL`, and `RELAY_ALLOWED_SENDERS`. The path is
   `channels/relay/.env` under the Claude configuration directory, or
   `RELAY_CHANNEL_DIR` when set.
4. Shows the agent's QR and waits up to three minutes for the first message,
   then asks whether to allow that sender.
5. Offers to start Claude Code with the Relay channel loaded.

To reuse an agent you already have, pass its token from your secret store:

```bash
npx relaymessenger@staging connect claude-code --token "$RELAY_AGENT_TOKEN"
```

| Flag | Effect |
| --- | --- |
| `--new` | create a new agent instead of using one you already have |
| `--handle <handle>` | the .dev handle you want for a new agent; leave it out and Relay picks one |
| `--name <name>` | the name people see next to a new agent |
| `--about <text>` | the one line people see above your agent's first message |
| `--image <path-or-url>` | a picture for a new agent: a file on this computer, or an https:// address |
| `--token <token>` | use an agent you already have, by its token; visible in ps and shell history |
| `--with-token` | use an agent you already have; its token is read from a pipe |
| `--all` | connect every detected coding agent |

## Run it from a script

`--no-input`, `--non-interactive`: never ask a question; fail with exit 2 where one is required.
No environment variables are needed. RELAY_AGENT_TOKEN is honored in scripts only.
This example reads an existing token from a script variable:

```bash
npx relaymessenger@staging connect claude-code \
  --token "$RELAY_AGENT_TOKEN" \
  --allow alice,ops_bot.dev \
  --yes --no-start --json
```

| Flag | Effect |
| --- | --- |
| `--allow <handles>` | the handles allowed to message this agent, separated by commas; skips waiting for a first message |
| `--yes` | take the plan as it is |
| `--no-start` | do not start the agent at the end; print its command instead |
| `--no-skill` | do not offer the Relay skill at the end |
| `--dry-run` | print the plan and change nothing |
| `--api-url <url>` | the Relay API address to use |
| `--json` | print the result as JSON |

Inspect the plan without changing anything:

```bash
npx relaymessenger@staging connect claude-code --dry-run --json
```

The dry-run result has this shape. The home path depends on your computer:

```json
{
  "ok": true,
  "dry_run": true,
  "agents": [
    {
      "agent": "claude-code",
      "files": [
        "/Users/you/.claude/channels/relay/.env"
      ],
      "commands": [
        "claude plugin marketplace add RelayMessenger/Relay-SDK@staging",
        "claude plugin install relay@relay-messenger --yes",
        "claude plugin enable relay@relay-messenger"
      ]
    }
  ],
  "steps": [
    "1  create a new agent and save its token privately on this computer",
    "2  run  claude plugin marketplace add RelayMessenger/Relay-SDK@staging",
    "3  run  claude plugin install relay@relay-messenger --yes, then  claude plugin enable relay@relay-messenger",
    "4  write  /Users/you/.claude/channels/relay/.env  (token, API address, allowed senders)",
    "5  start Claude Code with Relay when you are ready"
  ]
}
```

Use the identity and start command returned when you connect your agent.
Run `npx relaymessenger@staging connect --help` to read the command's help.

## Verify messaging

1. Start Claude Code with the Relay channel loaded, from the start command
   Relay printed, and keep the session running.
2. Send a direct Message from a Contact named in `RELAY_ALLOWED_SENDERS`.
3. Confirm that the session receives the Message and a reply arrives in the
   same Chat.

**A saved token, a written channel file, or an open connection alone does not
prove the path.** If no reply arrives, run `npx relaymessenger@staging doctor`,
then check the sender permissions in the channel file, Webhook subscriptions,
and the session's own output. The [live view](/integrations/cli/observe-events)
shows whether a runtime is connected and what arrives, without taking any event.
