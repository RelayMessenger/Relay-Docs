Relay docs search.

Source:
[Relay-SDK `skills/relay`](https://github.com/RelayMessenger/Relay-SDK/tree/staging/skills/relay)

## Install

The current portable Agent Plugin and Claude plugin manifest version is
`1.0.0`:

```bash
git clone --branch staging \
  https://github.com/RelayMessenger/Relay-SDK.git
npx skills@1.5.24 add ./Relay-SDK/skills/relay --skill relay
```

Run the installer explicitly and choose the coding agent and installation scope.
Running `npx relaymessenger@staging` is a separate action; it does not silently
install or replace agent instructions. Updating instructions leaves messaging
identity and runtime configuration under their existing owners.

The Relay Skill is the editable source for the generated Codex and Cursor
packages. Its checked-in references lock the Relay v1 OpenAPI and maintained
TypeScript SDK.

## Offer skills before setup

<Info>
Coming soon to the next CLI release. The existing standalone installer above
remains an explicit installation path.
</Info>

In an interactive terminal, the next CLI offers skill installation before the
create fields or existing-token setup. Installation is opt-in and uses the
standard Skills installer, which asks for coding agents and project/global scope.

| Choice or mode | Result |
| --- | --- |
| Accept | Run the standard installer with the selected scope. |
| Decline or cancel the optional offer | Continue setup without installing instructions. |
| Existing skill or unknown detection | Skip the automatic offer. |
| Explicit Install Relay skill action fails | Return a nonzero status. |
| Optional installation fails during setup | Keep the identity workflow separate from installation failure. |
| `--json`, piped input, non-TTY, or CI | Suppress optional installation prompts. |

Selected Codex, Claude Code, and Hermes homes and telemetry opt-outs stay with
the installer environment. Agent Tokens and provider API keys are not forwarded.

## Choose the docs MCP

The skill configures a hosted, read-only docs MCP. It searches documentation
and requires no Relay Agent Token.

| Docs source | MCP URL |
| --- | --- |
| Staging docs | `https://docs.staging.relayapp.im/mcp` |

Use [MCP](/integrations/mcp) instead when the local coding agent should call
Relay messaging tools with an Agent Token.

## Prepare hosted proof

The local docs candidate keeps the current event paths and payload version in
`llms.txt` for these later hosted queries:

```text
Relay v1 /v1/websocket /v1/webhook-subscriptions full_sync
message.received webhook_version 2026-08-30 api_version v1
```

The expected markers are `/v1/websocket`, `/v1/webhook-subscriptions`,
`webhook_version`, `2026-08-30`, and `api_version`.

Run the strict hosted-search test only after this docs candidate is pushed and
the hosted staging index refreshes:

```bash
RELAY_DOCS_MCP_URL=https://docs.staging.relayapp.im/mcp npm run test:live
```

Local Docs validation prepares these source markers. It does not prove the
hosted preview or MCP index.
