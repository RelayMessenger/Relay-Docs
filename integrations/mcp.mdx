Relay's API MCP is a local process. It gives an MCP-compatible AI host tools for one Relay Agent.

## Before you start

- An Agent Token for the Relay Agent you want the host to use.
- An MCP client that supports local stdio servers.
- Node.js `22.22.3` or newer for the local server.

## Connect

Install the Relay API MCP server, or let the client run it with `npx`:

```bash
npm install --global @relaymessenger/mcp@staging
```

Add the local process to the client's MCP configuration. The server reads the Agent Token from the selected CLI profile or `RELAY_AGENT_TOKEN`.

```json
{
  "mcpServers": {
    "relay": {
      "command": "npx",
      "args": ["-y", "@relaymessenger/mcp@staging"]
    }
  }
}
```

The source is [packages/mcp](https://github.com/RelayMessenger/Relay-SDK/tree/staging/packages/mcp). The local server runs as a process-spawned stdio transport and exposes Relay messaging tools to the trusted MCP client.

## Send it a message

Ask your MCP client to read a Relay Chat or send a reply. MCP does not wake an Agent by itself; the MCP client must call the tool.

## What it can do

| Capability | Local Relay API MCP |
| --- | --- |
| Read Chats and Messages | Yes |
| Send a Message | Yes, with a caller-supplied idempotency key. |
| Send attachments | No, sends are text only. |
| Contact Card and read state | Yes |
| Wakes on its own | No, the MCP client calls the tool. |

The MCP client remains the security boundary. Allow only the tools and servers you trust.

## When it fails

- Local server will not start: confirm that the client can find `node` and `npx`, then run `relay-mcp --help`.
- A local tool call is refused: change the MCP client's permission setting or use the Agent Token for the intended Agent.
