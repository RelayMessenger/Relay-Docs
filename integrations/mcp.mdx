## Before you start

- Node.js 22.22.3 or newer.
- An Agent Token [saved in a CLI profile](/cli/auth), named in `RELAY_PROFILE`.
- `RELAY_API_URL` set to the token's API, `https://api.staging.relayapp.im`.

## Connect

Install the server, or let the client run it with `npx`:

```bash
npm install --global @relaymessenger/mcp@staging
```

It is a local stdio process with no remote HTTP or OAuth mode. The source is [packages/mcp](https://github.com/RelayMessenger/Relay-SDK/tree/staging/packages/mcp).

Add one server entry to the client's MCP configuration, naming your saved profile:

```json
{
  "mcpServers": {
    "relay": {
      "command": "npx",
      "args": ["-y", "@relaymessenger/mcp@staging", "--profile", "staging"]
    }
  }
}
```

`RELAY_AGENT_TOKEN` and `RELAY_API_URL` in that entry override the saved profile; keep them paired, one token to one API. The trusted local MCP host decides which tools the model may call, and Relay never grants one on its behalf.

## Send it a message

Open Relay on your phone and message the agent whose token the profile holds. The client does not wake up on its own, so ask it to read your Relay messages and answer them. The reply appears in the same chat.

## What it can do

These are the tools the server registers; nothing else is there.

| Relay feature | MCP server |
| --- | --- |
| Wakes when a message arrives | No. The client reads when asked. |
| Reply in the chat | Yes, text up to 10,000 characters, to a chat or to handles, with an idempotency key. |
| Send attachments | No. Sends are text only. |
| Read chat history | Yes, chats, messages, and threads, one page at a time. |
| React, type, mark read | Yes. |
| Contact card | Yes, read and set. |

For documentation search without a token, use the docs MCP server on the [skills page](/integrations/skills).

## When it fails

- No saved token: [save one](/cli/auth) into the profile named in the entry.
- The server will not start: the client cannot find `node` or `npx`; give it the full path.
- A tool call is refused: the client's own permission setting blocked it, so allow it there.
