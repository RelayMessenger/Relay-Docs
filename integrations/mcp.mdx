Give any MCP client on your computer the Relay messaging tools.

## Before you start

You need Node.js 22.22.3 or newer and an Agent Token saved in a CLI profile: [save one](/cli/auth) and set `RELAY_PROFILE` to the profile's name. Set `RELAY_API_URL` to the API the token comes from, `https://api.staging.relayapp.im` here; the token and the address must match. For a coding agent Relay knows, use its own page instead, [Claude Code](/integrations/claude-code) for example; `connect` writes this entry for you. Install the server, or let the client run it with `npx`:

```bash
npm install --global @relaymessenger/mcp@staging
```

The server is a local stdio process; it has no remote HTTP or OAuth mode. The source is [packages/mcp](https://github.com/RelayMessenger/Relay-SDK/tree/staging/packages/mcp).

## Connect

Add one server entry to the client's MCP configuration. Replace `staging` with your saved profile name. If the profile file lives at a custom path, add `RELAY_CONFIG_PATH` to the entry's environment. `RELAY_AGENT_TOKEN` and `RELAY_API_URL` there override the saved profile, and they must stay paired:

```json
{
  "mcpServers": {
    "relay": {
      "command": "npx",
      "args": ["-y", "@relaymessenger/mcp@staging", "--profile", "staging"]
    }
  }
}
```

Start the client and ask it to call `relay_list_chats`. An empty list is a good answer; an error names what is missing. The trusted local MCP host is the security boundary: it decides which tools the model may call, and Relay never grants a tool on its behalf.

## Send it a message

Open Relay on your phone and send a message to the agent whose token the profile holds. The client does not wake up on its own; ask it to read your Relay messages and answer them. It lists the chat, reads the message, and sends the reply, which appears in the same chat on your phone.

## What it can do

The tools are the ones the server registers; anything not listed is not there.

| Relay feature | MCP server |
| --- | --- |
| Wakes when a message arrives | No. The client reads when asked. |
| Reply in the chat | Yes, text up to 10,000 characters, to a chat or to handles, with an idempotency key. |
| Send attachments | No. Sends are text only. |
| Read chat history | Yes, chats, messages, and threads, one page at a time. |
| React, type, mark read | Yes. |
| Contact card | Yes, read and set. |

For documentation search without a token, use the docs MCP server on the [skills page](/integrations/skills).

## When it fails

If the client reports no saved token, [save one](/cli/auth) into the profile named in the entry. If the server cannot start, the client cannot find `node` or `npx` on its own path; give it the full path to `npx`. If a tool call is refused, the client's own permission setting blocked it; allow it there.
