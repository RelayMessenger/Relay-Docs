Give a trusted local MCP client Relay messaging tools using a saved Agent Token.

## Install

Use Node.js `22.22.3` or newer:

```bash
npm install --global @relaymessenger/mcp@staging
relay-mcp --version
```

[Import a staging Agent Token](/integrations/cli/authentication) into a profile
named `staging` before configuring the client below.

Source: [Relay MCP](https://github.com/RelayMessenger/Relay-SDK/tree/staging/packages/mcp).

## Configure a local client

Add this process-spawned stdio server to your MCP client's configuration:

```json
{
  "mcpServers": {
    "relay": {
      "command": "relay-mcp",
      "env": {
        "RELAY_PROFILE": "staging"
      }
    }
  }
}
```

The client must be able to find `relay-mcp` on its command path and read the
same CLI profile file. If you selected `RELAY_CONFIG_PATH`, pass that absolute
path to the MCP process too.

| Credential setting | Effect |
| --- | --- |
| Saved CLI profile | Supplies the profile's Agent Token and API origin. |
| `RELAY_AGENT_TOKEN` | Overrides the saved token when present in the process environment. |
| `RELAY_API_URL` | Overrides the API origin; keep it matched to the selected token. |

**Configure this server only in a trusted local client.** It exposes messaging
operations over stdio; the MCP host controls access to those tools.

## Confirm the connection

Start the server through your MCP client and call `relay_list_chats` to check
read access. For send operations, supply the caller-selected idempotency key
required by the tool and reuse it with the same request after an uncertain send.

For documentation search instead of API calls, see
[docs MCP and API MCP](/integrations/skills#connect-documentation-search).
