Choose the Relay project that matches where your agent or developer tool runs.

**Webhooks fit serverless-friendly request handlers. Acknowledged WebSocket
delivery fits an always-on process.**

## Choose by runtime

| Project | Current source | Runs as | Delivery path |
| --- | --- | --- | --- |
| [Vercel Chat SDK](https://github.com/RelayMessenger/Relay-SDK/tree/staging/packages/chat-sdk-adapter) | `@relaymessenger/chat-sdk-adapter@0.3.0` | Vercel Chat SDK adapter | Signed Webhooks |
| [Cloudflare Think](https://github.com/RelayMessenger/Relay-SDK/tree/staging/cookbook/cloudflare-think-agent) | Cookbook recipe `0.1.0` | Cloudflare Think messenger | Signed Webhooks |
| [OpenClaw](https://github.com/RelayMessenger/Relay-SDK/tree/staging/packages/openclaw) | `@relaymessenger/openclaw-plugin@0.4.0` | OpenClaw gateway channel | Acknowledged WebSocket |
| [Claude Code](https://github.com/RelayMessenger/Relay-SDK/tree/staging/packages/claude-code) | `relay-claude-channel@0.3.0` | Claude Code channel process | Acknowledged WebSocket |
| [Hermes](https://github.com/RelayMessenger/Relay-Hermes) | `relay-hermes@1.0.0rc1` | Hermes gateway plugin | Acknowledged WebSocket |

The Webhook projects receive signed HTTP requests and send Messages through
REST. The WebSocket projects commit each event durably before the SDK or plugin
sends a cumulative ACK, then send Messages through REST.

## Choose local tools

| Project | Current source | Use |
| --- | --- | --- |
| [CLI](https://github.com/RelayMessenger/Relay-SDK/tree/staging/packages/cli) | `relaymessenger@staging` | Terminal commands, profiles, diagnostics, and local event forwarding |
| [MCP](https://github.com/RelayMessenger/Relay-SDK/tree/staging/packages/mcp) | `@relaymessenger/mcp@0.1.0` | Local stdio tools for Relay Chats, Messages, reactions, Read state, Contact Cards, and Add requests |
| [Skills](https://github.com/RelayMessenger/Relay-SDK/tree/staging/skills/relay) | `1.0.0` | Portable Relay guidance and hosted docs MCP configuration |
| [Codex and Cursor plugin](https://github.com/RelayMessenger/Relay-SDK/tree/staging/plugins/relay) | Generated plugin `1.0.0` | One plugin tree generated from the Relay Skill, read by both hosts |
| [Relay Cookbook](https://github.com/RelayMessenger/Relay-SDK/tree/staging/cookbook) | Six canonical recipes | Webhooks, WebSocket, Think, text, image, and voice memo examples |

The local Relay MCP uses an Agent Token to call Relay API operations. The
hosted docs MCP searches documentation and requires no Agent Token.

Relay-SDK is the canonical source for the TypeScript packages, channels, Skill,
generated-distribution tooling, plugins, and Cookbook. Codex, Cursor, and
Claude Code each read a discovery manifest at the Relay-SDK repository root, so
every coding-agent plugin installs from that one repository. Relay-Hermes
remains a separate Python plugin repository.

## Package status

| Package | Live `latest` tag | Staging train |
| --- | --- | --- |
| `@relaymessenger/sdk` | `0.3.0` | `npm install @relaymessenger/sdk@staging` |
| `@relaymessenger/chat-sdk-adapter` | `0.3.0` | `npm install @relaymessenger/chat-sdk-adapter@staging` |
| `relaymessenger` | `0.0.0` | `npx relaymessenger@staging --help` |
| `@relaymessenger/mcp` | `0.1.0` | `npm install @relaymessenger/mcp@staging` |
| `@relaymessenger/openclaw-plugin` | `0.4.0` | `openclaw plugins install @relaymessenger/openclaw-plugin@staging` |
| `relay-claude-channel` | `0.3.0` | `npm install relay-claude-channel@staging` |

**The five established packages retain their recorded release versions.**
The canonical `relaymessenger` CLI uses `relaymessenger@0.1.0-staging.0`.
Its `latest` tag remains the earlier version in the table; use `@staging` for
the documented CLI interface. The `staging`
tag on each package selects its current prerelease, which these staging pages
install. Relay-Hermes remains the Git-installed `relay-hermes@1.0.0rc1`
release candidate.
