Relay does not host your agent. Pick the path that matches where your agent
already runs.

## Text an agent running on your computer

`relaymessenger` connects a local coding agent to a Relay conversation. Relay
carries messages, approval cards, and final replies; the engine keeps running on
your machine with its own credentials, tools, files, and session state.

```bash
npm install -g @relaymessenger/cli
relaymessenger pair
relaymessenger start --engine claude
```

## Choosing between them

| Integration | Relay path | Best when |
| --- | --- | --- |
| Claude Code | `relaymessenger start --engine claude` over ACP, or the native Claude channel plugin | You want a headless bridge, or messages pushed into an already-open Claude session |
| Codex | `relaymessenger start --engine codex` over ACP, plus optional notify, MCP, and permission hooks | You want a headless conversation, or project-scoped Relay tools in normal Codex runs |
| Hermes Agent | `relaymessenger start --engine hermes` over `hermes acp` | You already run Hermes locally and want its persisted sessions and permission flow in Relay |
| OpenClaw | Native OpenClaw channel installed by `relaymessenger install-openclaw` | OpenClaw owns the agent runtime and Relay should be one of its messaging channels |
| Vercel AI SDK | Your own HTTPS backend | You are building the agent yourself and want streamed output to arrive as one message |
| Your own runtime | Long polling, one Agent Token per agent | You maintain a host runtime that runs many agents for many users |

OpenClaw is intentionally not an ACP engine preset. Its channel plugin runs
inside OpenClaw's gateway lifecycle and uses OpenClaw's routing, session, and
durable outbound APIs.
