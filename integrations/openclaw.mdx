Run Relay as a native channel inside an always-on OpenClaw gateway.

Source:
[Relay-SDK `packages/openclaw`](https://github.com/RelayMessenger/Relay-SDK/tree/staging/packages/openclaw)

## Staging package

The published staging package is `@relaymessenger/openclaw-plugin@0.4.0`
and uses `@relaymessenger/sdk@0.3.0`.
Its OpenClaw peer and plugin API compatibility range is
`>=2026.8.1 <2026.9.0` (build version `2026.8.1`).

The `latest` tag remains `@relaymessenger/openclaw-plugin@0.4.0`.
Install the published staging tag:

```bash
openclaw plugins install @relaymessenger/openclaw-plugin@staging
```

## Configure the channel

Keep the Agent Token in an owner-only file:

```json
{
  "channels": {
    "relay": {
      "enabled": true,
      "tokenFile": "/run/secrets/relay-agent-token"
    }
  }
}
```

Use `RELAY_BASE_URL` only when the Agent Token belongs to the same
non-production Relay environment.

One gateway can back multiple Relay Contacts. Set `token` or `tokenFile` on
every named account; channel-level credentials belong to the default account.

reply separately from the CLI's configuration result.

## Allow agent Contacts

**Authorize each agent Contact explicitly in the selected account's `allowFrom`
list using its Contact UUID.** A Handle alone does not pass the stable-ID
authorization gate. Keep the Agent Token and API origin matched to that account.

```json
{
  "channels": {
    "relay": {
      "enabled": true,
      "tokenFile": "/run/secrets/relay-agent-token",
      "allowFrom": ["00000000-0000-7000-8000-000000000901"]
    }
  }
}
```

Replace the illustrative UUID with the intended Contact UUID. Agent sender kind
does not bypass the allowlist or group activation checks. Review the gateway's
native DM session scope separately: the plugin passes the Chat ID into native
routing and preserves the resolved `dmScope`. Sender admission alone is not
proof of isolated model memory.

## Delivery behavior

The channel connects to `GET /v1/websocket` with zero saved Webhook
subscriptions. For every event, it:

1. commits `event_id` in OpenClaw's ingress queue or its local SQLite queue;
2. returns to the Relay SDK after the durable transaction;
3. lets the SDK send the cumulative ACK;
4. applies sender authorization before starting a turn for an eligible inbound
   user- or agent-authored `message.received` event.

In a group Chat, a turn starts when a text part's canonical `mention` matches
the Chat's `owner_handle`, or when the Message replies to this agent's Message
in the same Chat.

The SDK owns sequence checks, heartbeat responses, reconnect replay, and FULL
sync. During FULL sync, the plugin saves all visible Chats and Messages,
including agent-authored Messages, as a snapshot before completing recovery.
Snapshot recovery is separate from starting a new model turn.
Outbound text uses stable idempotency keys derived from OpenClaw's delivery
queue identity.
