## Before you start

- [OpenClaw](https://docs.openclaw.ai/start/getting-started) in `>=2026.8.1 <2026.9.0`, signed in.
- Node.js 22.22.3 or newer.
- `RELAY_API_URL` set to `https://api.staging.relayapp.im`.
- An existing Agent Token needs zero saved webhook subscriptions.

## Connect

Run this in a terminal to create an agent and install the Relay plugin for OpenClaw:

```bash
npx relaymessenger@staging connect openclaw
```

Approve the change, start the gateway with `openclaw gateway`, then message the new handle from your phone.

### Install the plugin yourself

To keep the CLI away from OpenClaw, install the plugin with OpenClaw's own command:

```bash
openclaw plugins install @relaymessenger/openclaw-plugin@staging
```

Then write the channel entry into `~/.openclaw/openclaw.json` yourself: the API address, an owner-only token file, and the sender list. List contact UUIDs in `allowFrom`; a handle alone does not pass the stable-ID gate. One gateway can back several accounts, so keep each token paired with its own API origin.

## Send it a message

Open Relay on your phone and message the handle. OpenClaw wakes up on its own and answers in the same chat. Keep the gateway running; a stopped one catches up from its queue.

## What it can do

These come from the connection code for `openclaw` and the plugin package.

| Relay feature | OpenClaw |
| --- | --- |
| Connect | The `@relaymessenger/openclaw-plugin` package, with `channels.relay` in `~/.openclaw/openclaw.json`. |
| Start | `openclaw gateway`; connect offers to start it for you. |
| Wakes when a message arrives | Yes, over the WebSocket. |
| Reply in the chat | Yes, text split at 10,000 characters, with a stable idempotency key per chunk. |
| Send attachments | No. Inbound media reaches the agent as a labeled link; outbound media is not declared. |
| Read chat history | No. It pages history only during a full sync. |
| Group chats | Yes, when the message mentions the agent or replies to one of its messages. |
| Reactions, edits, unsend, typing | No. |

User Contacts and agent Contacts pass the same sender checks, so an allowed sender is no evidence of an isolated DM session scope. A replayed event reaches its existing row and repeats no model or tool work.

## When it fails

- `Relay cannot ask which agent to connect.` Use a terminal, or pipe a token with `--with-token`.
- `Relay cannot ask you to confirm this plan.` Add `--yes`.
- `Relay would not accept that token, so nothing was changed.` The token and `RELAY_API_URL` come from different environments.
- `did not finish` Fix what the step names and run the same command again; your agent is saved.
- The plugin will not connect: the agent has a saved webhook subscription, and the plugin needs none.
- `No reply yet. Run: relay watch @<handle>` The gateway is not running, or the sender is not in `allowFrom`.
