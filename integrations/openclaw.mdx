OpenClaw owns the agent runtime. Relay becomes one of its messaging channels,
installed as a native plugin rather than an ACP engine preset, because the plugin
runs inside OpenClaw's gateway lifecycle and uses OpenClaw's routing, session, and
durable outbound APIs.

```bash
npm install -g @relaymessenger/cli
relaymessenger pair
relaymessenger install-openclaw
```

## What the installer touches

The installer persists the bundled OpenClaw plugin archive, runs OpenClaw's own
plugin installer, adds only the Relay plugin and channel fields to
`~/.openclaw/openclaw.json`, and stores the token in an owner-only file.

Unrelated OpenClaw configuration is preserved, and a different existing Relay
identity is never overwritten.

## How the plugin behaves

It follows OpenClaw's current channel SDK: setup discovery stays network-free,
installed packages load built JavaScript runtime entrypoints, inbound events use
stable ingress and envelope helpers, and replies use the durable outbound path.

## Current scope

| Surface | State |
| :---: | --- |
| ✅ | Direct conversations |
| ⚠️ | Inbound media and voice memos arrive as a fetchable capability URL, so the agent does not see the file inline |
| ❌ | Reactions and receipts do not start agent turns |
| ❌ | Group conversations |

<Warning>
Treat capability URLs as secrets. Keep them out of analytics, public logs,
model-training corpora, and any response outside the conversation that supplied
them.
</Warning>

## Feature reference

<AccordionGroup>
  <Accordion title="Network-free setup discovery">
    Setup discovery makes no network calls. Installed packages load built
    JavaScript runtime entrypoints rather than resolving anything at setup time.
  </Accordion>

  <Accordion title="Ingress and envelopes">
    Inbound events use OpenClaw's stable ingress and envelope helpers, so Relay
    messages enter the same routing path as any other OpenClaw channel.
  </Accordion>

  <Accordion title="Durable outbound">
    Replies use OpenClaw's durable outbound path, so a reply that is accepted
    survives a gateway restart.
  </Accordion>

  <Accordion title="Media arrives as a capability URL">
    Inbound media and voice memos arrive as a fetchable capability URL. The
    agent does not see the file inline and must fetch it.
  </Accordion>

  <Accordion title="Configuration is additive">
    The installer adds only the Relay plugin and channel fields to
    `~/.openclaw/openclaw.json`. Unrelated OpenClaw configuration is preserved,
    and a different existing Relay identity is never overwritten.
  </Accordion>
</AccordionGroup>

## Troubleshooting

Start with `relaymessenger doctor`, then
[integration troubleshooting](/integrations/troubleshooting) for symptoms shared
with every other integration. These are specific to this one.

<AccordionGroup>
  <Accordion title="Reactions or receipts do not wake the agent">
    Expected. Reactions and receipts do not start agent turns in this channel
    today.
  </Accordion>

  <Accordion title="The agent cannot read an attachment">
    Media arrives as a capability URL rather than inline content. The agent has
    to fetch the URL. See [Attachments](/guides/attachments).
  </Accordion>

  <Accordion title="The installer refuses to overwrite">
    A different Relay identity is already configured. That refusal is
    deliberate. Remove the existing identity first if you intend to replace it.
  </Accordion>
</AccordionGroup>
