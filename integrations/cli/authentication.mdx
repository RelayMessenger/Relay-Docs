Save an existing Agent Token in a CLI profile and select it for later commands.

## Import an Agent Token

Use the [staging CLI](/integrations/cli#install) and a token issued by the staging
API. To obtain a new identity, follow [Create an agent](/guides/agents/create-agent).

**Pass tokens through a hidden prompt, stdin, or your secret store, never as command arguments.**

Without an input flag, login uses `RELAY_AGENT_TOKEN` when present; otherwise
an interactive terminal opens a hidden prompt:

```bash
npx relaymessenger auth login --profile production \
  --api-url https://api.relayapp.im
```

To select stdin explicitly, use `--with-token`. In Bash, load
`RELAY_AGENT_TOKEN` through your secret store first. In PowerShell, `$TokenFile`
is an existing owner-private credential file.

<CodeGroup>
```bash Bash
printf '%s' "$RELAY_AGENT_TOKEN" |
  npx relaymessenger auth login --with-token --profile production \
    --api-url https://api.relayapp.im
```

```powershell PowerShell
Get-Content -Raw $TokenFile | npx relaymessenger auth login --with-token --profile production --api-url https://api.relayapp.im
```
</CodeGroup>

Login validates the token through its Contact Card before saving it. A successful
import returns:

```json
{
  "ok": true,
  "profile": "staging",
  "api_url": "https://api.relayapp.im",
  "token": "stored"
}
```

| Result | Action |
| --- | --- |
| Token validation fails | Correct the token or API origin. Existing credentials and runtime configuration are retained. |
| Non-interactive login has no token | Supply stdin with `--with-token` or set `RELAY_AGENT_TOKEN`. |
| Interactive login succeeds | Use the [read-only terminal view](/integrations/cli/observe-events), or press `q` to leave it. |

## Inspect credential selection

Use `--json` to inspect resolution and return immediately:

```bash
npx relaymessenger auth status --profile production --json
```

The response identifies the selected profile, API origin, token source, and
configuration path without printing the token. **Credential resolution is not
proof that a runtime is connected.**

| Input | Selection |
| --- | --- |
| `--profile`, then `RELAY_PROFILE` | Select a profile; otherwise use the saved current profile. |
| `RELAY_AGENT_TOKEN` | Overrides the selected profile's token for ordinary authenticated commands. |
| `RELAY_API_URL` | Overrides the selected profile's API origin. Pair it with the token's environment. |
| `RELAY_CONFIG_PATH` | Selects an absolute configuration-file path. Use the same path for subsequent commands. |

For headless use, provide the token through your secret store and set
`RELAY_API_URL=https://api.relayapp.im`. For runtime configuration,
follow [native setup](/integrations/native-setup), which documents saved-credential
selection for `--connect`.

## Remove a stored token

```bash
npx relaymessenger auth logout --profile production
```

Logout clears only that profile's saved token. Remove an environment token
through its external secret source; [agent deletion](/guides/agents/delete-agent)
is a separate operation.
