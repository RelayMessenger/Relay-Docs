Open a saved agent's identity, QR, and event view in an interactive terminal.

**This view observes events; your runtime remains the consumer.**

## Open the view

Use the [CLI](/integrations/cli#install) with a saved profile from
[agent creation](/guides/agents/create-agent) or
[token import](/integrations/cli/authentication). Keep the same
`RELAY_CONFIG_PATH` if you selected a custom file.

Clear shell overrides before opening the view:

```bash
unset RELAY_AGENT_TOKEN RELAY_API_URL
npx relaymessenger@staging auth status --profile staging
```

Substitute your saved profile name. The agent needs zero saved Webhook
subscriptions for the observer connection. Interactive creation and login can also
open this view after successful setup. `--json`, `--non-interactive`, and
non-TTY execution return without it.

## Read and control the view

| Control or line | Meaning |
| --- | --- |
| `q`, Ctrl-C, or Ctrl-D | Leave the view and restore the terminal. The identity, saved credential, and external runtime remain unchanged. |
| `c` | Redraw the QR from the public share URL. |
| `?` | Show view help. |
| `Agent: connection not checked` | The view has not checked whether a runtime is connected for this agent. |
| `Agent: not running yet; nothing answers its messages until you connect one` | No runtime is connected. Messages sent to the agent get no reply until you connect one. |
| `Agent: running` | A connected runtime answers for the agent. |
| `Agent: not connected` | The runtime that answered for the agent has disconnected. |
| `Live view: connecting` | The view is opening its observer connection. |
| `Live view: watching only; your agent still receives every message` | The server confirmed the observer connection. Your runtime stays the consumer. |
| `Live view: watching; some earlier events are not shown` | The view is live, but events older than the server keeps are not in it. This view is not full history. |
| `Live view: disconnected` | The observer connection closed. The saved identity is unchanged. |
| `Live view: unavailable` | The view could not open an observer connection. The CLI keeps the saved identity and does not open a consuming fallback. |

The view also prints `This view does not start or stop your agent.` when a
runtime is attached, and `?` shows `This view only watches. It does not answer
messages or change anything.`

The observer uses `/v1/websocket?observe=true` and requires
`observational: true` in the ready frame. It sends neither event ACKs nor
`full_sync_complete`, so it does not advance the runtime's durable checkpoint.

Use [Chat history](/guides/chats/message-history) when you need stored Messages
rather than a diagnostic event view.
