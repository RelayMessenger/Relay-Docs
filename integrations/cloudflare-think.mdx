## Before you start

- Node.js 22.22.3 or newer, and a Cloudflare account with Workers AI.
- An Agent Token from `https://api.staging.relayapp.im`, set as `RELAY_API_URL`.
- A [webhook subscription](/webhooks/subscriptions) for your public `/webhooks/relay` route.

## Connect

Clone the starter, install it, and copy the secrets template, which stays out of source control:

```bash
git clone --branch staging https://github.com/RelayMessenger/Relay-SDK.git
cd Relay-SDK/cookbook/cloudflare-think-agent
npm ci
cp .dev.vars.example .dev.vars
```

The source is [cookbook/cloudflare-think-agent](https://github.com/RelayMessenger/Relay-SDK/tree/staging/cookbook/cloudflare-think-agent), and its README records the choices below.

Put the Agent Token and the webhook signing secret in `.dev.vars`. In `wrangler.jsonc`, under the staging environment variables, set the API origin, your agent's handle, and the model `@cf/openai/gpt-oss-120b`. Then start the Worker and route the registered address to it:

```bash
npm run dev
```

The Worker verifies each webhook, commits the event, and runs one Think turn per message. Deploy it the way you deploy any Worker; the same variables go into the deployed environment.

## Send it a message

Open Relay on your phone and message your agent's handle. Relay posts the event to the Worker, Think runs the model, and the reply comes back in the same chat. To watch the exchange from a terminal, run `npx relaymessenger@staging watch @<handle>`.

## What it can do

The starter builds the Chat SDK instance itself, so these are Think's rules, not settings.

| Relay feature | Cloudflare Think starter |
| --- | --- |
| Wakes when a message arrives | Yes, by webhook. |
| Reply in the chat | Yes, one turn per message, with the chat locked for the whole turn. |
| Send attachments | Yes, through the Chat SDK adapter it wraps. |
| Read chat history | Yes, through the adapter's history walk. |
| Marks the chat read | Yes, on receipt. |

Think sets `concurrency` to `burst` with a 600 ms window, and waits for each reply to finish. A second message inside that window replaces the first; a second message during the turn waits and gets its own reply. A newer message never cancels a running turn, because Think's handlers never read `thread.signal`.

## When it fails

- Signature verification fails: the secret is not this subscription's, or the body was re-encoded.
- No reply comes: read the Worker's logs, because the turn either threw or the model call failed.
- A send's result is uncertain: retry it with the same idempotency key and the same content.
