Use the local forwarder while you develop on your laptop, then point the same handler at a webhook subscription when you deploy.

## Before you start

- Node.js `22.22.3` or newer.
- [Chat SDK](https://chat-sdk.dev) `4.39.0`, its memory state adapter, and Relay's adapter.
- An Agent Token and a webhook signing secret for your staging agent.

## Connect

### On your laptop

The signed local forwarder is pending the CLI release. The staging CLI published today does not include this command yet.

```bash
npx relaymessenger@staging listen --forward-to http://localhost:3000/webhooks/relay
```

The command will read the agent's WebSocket events and POST each one to your local route with the same signature headers used by a deployed webhook. Set the printed local signing secret as `RELAY_WEBHOOK_SECRET` while the process runs.

### Deployed

Create a [webhook subscription](/webhooks/subscriptions) whose target is your public HTTPS route, then store its signing secret as `RELAY_WEBHOOK_SECRET`. Relay sends the same signed request to both paths, so your handler does not need an environment-specific branch.

Install the packages from one Chat SDK major version line:

```bash
npm install chat@4.39.0 @chat-adapter/state-memory@4.39.0 \
  @relaymessenger/chat-sdk-adapter@staging
```

The source is [packages/chat-sdk-adapter](https://github.com/RelayMessenger/Relay-SDK/tree/staging/packages/chat-sdk-adapter), with a [standalone server example](https://github.com/RelayMessenger/Relay-SDK/blob/staging/packages/chat-sdk-adapter/examples/server.mjs).

Create one Chat SDK instance with the Relay adapter and mount `POST /webhooks/relay`:

```typescript
import { Chat } from "chat";
import { createMemoryState } from "@chat-adapter/state-memory";
import { createRelayAdapter } from "@relaymessenger/chat-sdk-adapter";

const chat = new Chat({
  userName: "Relay example",
  concurrency: { strategy: "burst", debounceMs: 2000 },
  adapters: {
    relay: createRelayAdapter({
      baseUrl: "https://api.staging.relayapp.im",
      token: process.env.RELAY_AGENT_TOKEN,
      webhookSecret: process.env.RELAY_WEBHOOK_SECRET,
      markReadOnReceipt: true,
      abortActiveTurnOnReceipt: true,
    }),
  },
  state: createMemoryState(),
});

chat.onDirectMessage(async (thread, message) => {
  await thread.post(`Echo: ${message.text}`);
});

export async function POST(request: Request): Promise<Response> {
  return chat.webhooks.relay(request);
}
```

Pass the request body unchanged because the signature covers the raw bytes. Use a shared state adapter before running more than one instance.

## Send it a message

Open Relay on your phone and message the agent's Handle. Relay sends the event to your local route or deployed endpoint, the adapter verifies it, and your handler replies in the same Chat.

## What it can do

| Relay feature | Chat SDK adapter |
| --- | --- |
| Receive a Message | Yes, through the local signed forwarder or a webhook subscription. |
| Reply in the Chat | Yes, with an idempotency key derived from the event ID. |
| Send attachments | Yes, from a public HTTPS URL or file bytes. See [attachments](/messages/attachments). |
| Read Chat history | Yes, one page at a time. |
| Handle a second Message | `burst` waits two seconds and keeps the latest Message; `abortActiveTurnOnReceipt` can cancel the active turn through `thread.signal`. |

## When it fails

- Signature verification fails: the secret does not belong to this delivery path, or the body was re-encoded.
- No reply arrives: read the handler logs to find whether the turn threw or never started.
- A send result is uncertain: retry with the same idempotency key and content.
