## Before you start

- Node.js 22.22.3 or newer, and a public HTTPS route for the webhook.
- An Agent Token from `https://api.staging.relayapp.im`, set as `RELAY_API_URL`.
- A [webhook subscription](/webhooks/subscriptions) for that route, with its signing secret.

## Connect

Install Chat SDK, its in-memory state, and the Relay adapter from one major version line:

```bash
npm install chat@4.39.0 @chat-adapter/state-memory@4.39.0 \
  @relaymessenger/chat-sdk-adapter@staging
```

The source is [packages/chat-sdk-adapter](https://github.com/RelayMessenger/Relay-SDK/tree/staging/packages/chat-sdk-adapter), with a [standalone server example](https://github.com/RelayMessenger/Relay-SDK/blob/staging/packages/chat-sdk-adapter/examples/server.mjs).

Create one Chat SDK instance with the Relay adapter, register a direct-message handler, and mount `POST` at your route:

```typescript
import { Chat } from "chat";
import { createMemoryState } from "@chat-adapter/state-memory";
import { createRelayAdapter } from "@relaymessenger/chat-sdk-adapter";

const chat = new Chat({
  userName: "Relay example",
  concurrency: { strategy: "burst", debounceMs: 2000 },
  adapters: {
    relay: createRelayAdapter({
      baseUrl: process.env.RELAY_API_URL!,
      token: process.env.RELAY_AGENT_TOKEN,
      webhookSecret: process.env.RELAY_WEBHOOK_SECRET,
      markReadOnReceipt: true,
      abortActiveTurnOnReceipt: true,
    }),
  },
  state: createMemoryState(),
});

chat.onDirectMessage(async (thread, message) => {
  await thread.post(`Echo: ${message.text}`);
});

export async function POST(request: Request): Promise<Response> {
  return chat.webhooks.relay(request);
}
```

Pass the request body unchanged, because the signature is over the raw bytes. Swap the in-memory state for a shared store before more than one instance runs.

Three adapter settings matter. `burst` waits two seconds and runs the handler once for the latest message, and `markReadOnReceipt` marks the chat read as soon as the signature checks. `abortActiveTurnOnReceipt` lets a newer message cancel a running turn through `thread.signal`, so pass that signal to your model call.

## Send it a message

Open Relay on your phone and message your agent's handle. Relay posts the event to your route, the adapter verifies it, and your handler answers in the same chat. To watch the exchange from a terminal, run `npx relaymessenger@staging watch @<handle>`.

## What it can do

The adapter gives your handler these; the rest of the API is one import away.

| Relay feature | Chat SDK adapter |
| --- | --- |
| Wakes when a message arrives | Yes, by webhook. |
| Reply in the chat | Yes, with a send key derived from the event id and the send ordinal, so a retry never sends twice. |
| Send attachments | Yes, from a public HTTPS URL or from file bytes; see [attachments](/messages/attachments). |
| Read chat history | Yes. The adapter walks a chat's history backward, 100 messages a page. |
| Second message during a reply | Waits or cancels the running turn, by the three settings above. |

Chat SDK's default `concurrency` is `drop`: a message that arrives during a running handler throws, the webhook fails, and Relay [retries the delivery](/webhooks/delivery). The `burst` setting replaces that, and earlier messages in a burst arrive in `context.skipped`.

## When it fails

- Signature verification fails: the secret is not this subscription's, or the body was re-encoded.
- No reply comes: read the handler's logs, because the turn either threw or never started.
- A send's result is uncertain: retry it with the same idempotency key and content, and keep the prepared attachment id.
