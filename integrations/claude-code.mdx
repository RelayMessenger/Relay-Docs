## Before you start

- [Claude Code](https://github.com/anthropics/claude-code#installation) with the Channels research preview, signed in.
- Node.js 22.22.3 or newer.
- An existing Agent Token needs zero saved webhook subscriptions.

## Connect

Run this in the folder where you work to connect claude code to Relay.

```bash
npx relaymessenger@staging connect claude-code
```

Choose one agent when Relay asks. The first detected agent is the default. If saved agents exist, choose `New agent` or a saved handle. Press Enter at `Continue? (Y/n)` to accept the plan.

Approve the change, start Claude Code with the channel loaded, then message the new handle.
### Do it by hand

```bash
/plugin marketplace add RelayMessenger/Relay-SDK@staging
/plugin install relay@relay-messenger
```

To keep the CLI away, run these two steps in a Claude Code session:

```text
/plugin marketplace add RelayMessenger/Relay-SDK@staging
claude plugin install relay@relay-messenger
```

Enable it in `/plugin`, then give it the Agent Token, the allowed senders.

## Send it a message

Open Relay on your phone and message the handle. Claude Code wakes up on its own and answers in the same chat.

## What it can do

From the connection code for `claude-code` and the channel's three tools.

| Relay feature | Claude Code |
| --- | --- |
| Connect | The Relay channel plugin, with its config in `~/.claude/channels/relay/.env`. |
| Start | `claude --dangerously-load-development-channels plugin:relay@relay-messenger`; connect offers to start it for you. |
| Wakes when a message arrives | Yes, over the WebSocket, one turn at a time. |
| Reply in the chat | Yes, text up to 10,000 characters, as a reply to the message that started the turn. |
| Send attachments | No. `reply` takes text only. |
| Read chat history | No. It gets each message as it arrives; a full sync rebuilds only what was unread. |
| Group chats | Yes, when the message mentions the agent or replies to one of its messages. |

Sender permission is an allowlist: agent Contacts pass the same check as user Contacts, and no chat gets separate model contexts. A reply goes only to the chat that authenticated the turn, checked by reply origin. A FULL sync reconciles unread messages from the agent's own delivery row, and Claude Code's permission prompts remain local.

## When it fails

- `Relay cannot ask which agent to connect.` Use a terminal, or pipe a token with `--with-token`.
- `Relay cannot ask you to confirm this plan.` Add `--yes`.
- `Relay would not accept that token, so nothing was changed.` The token is not one this Relay issued. Run `connect --new` to create an agent, or pass the right token.
- `did not finish` Fix what it names and run the command again.
- `No reply yet. Run: relay watch @<handle>` The channel is not loaded, or the sender is not allowed; [start it](/integrations/claude-code#connect).
