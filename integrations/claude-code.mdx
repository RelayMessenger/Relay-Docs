## Before you start

- [Claude Code](https://github.com/anthropics/claude-code#installation), installed and signed in.
- Node.js 22.22.3 or newer.

## Connect

Run this in the folder where you work to connect Claude Code to Relay.

```bash
npx relaymessenger@staging connect claude-code
```

In an unlinked folder, this creates a new agent by default. If the folder is already linked, it uses that agent. Use `--handle` or `--name` to customize the new agent.

Scan the QR with Relay on your phone to add the agent, and send it a message. Leave the command running: it answers each message with Claude Code from the folder you ran it in. Control-C stops it.

## Send it a message

Open Relay on your phone and message the handle. While connect runs, Claude Code answers on its own in the same chat, and each chat keeps its own Claude Code session.

## What it can do

These come from the connection code for `claude-code` and the Relay MCP tool list.

| Relay feature | Claude Code |
| --- | --- |
| Connect | Nothing is written. Relay's tools travel through the session. |
| Start | Connect stays running and runs a Claude Code session in its folder for each chat. |
| Wakes when a message arrives | Yes, while connect runs, one message at a time in each chat. |
| Reply in the chat | Yes, text up to 10,000 characters, with a stable idempotency key. |
| Send attachments | No. The MCP tools send text only. |
| Receive attachments | Yes. Photos and files are saved under ~/.config/relay/media and their paths are added to the message, so the agent opens them with its own file tools. |
| Read chat history | Yes, by chat, oldest or newest first, one page at a time. |
| React, type, mark read | Yes, with reactions, typing indicators, and read marks. |
| Contact card | Yes, read and set the agent's name and picture. |

Claude Code runs without permission prompts in that folder, the same way Codex does under connect.

## Buttons

The agent can put up to five tappable buttons under its answer by ending it with a fenced code block tagged `buttons` that holds the part's items. The bridge removes the block from the text and sends it as a `buttons` part beside the text; a block it cannot read stays in the text and the reason is printed in the terminal.

````text
Which time works?

```buttons
[{"label": "9am"}, {"label": "2pm"}, {"label": "Open calendar", "url": "https://cal.example/x"}]
```
````

A tap comes back as an ordinary message whose text is the label. The prompt the bridge writes carries the same rules every Relay runtime gives its agent, so it sends buttons under the same conditions as any other agent; see [Choose when to send buttons](/messages/parts#choose-when-to-send-buttons).

## When it fails

- `No reply yet. Run: relay watch @<handle>` Connect is not running, or Claude Code is still working; run connect again and it answers from there.

Use the [CLI guide](/cli/index) for prompt, token, and restart errors.
