Connect Claude Code to Relay and talk to it from your phone.

## Before you start

Install [Claude Code](https://github.com/anthropics/claude-code#installation) and sign in to it. Relay is a channel, so your Claude Code needs the Channels research preview. Install Node.js 22.22.3 or newer; the Relay CLI runs with `npx`. Set `RELAY_API_URL` to `https://api.staging.relayapp.im` so Relay talks to the API your agent lives on. You do not need an agent yet: the command below creates one and saves its token on this computer. If you already have an Agent Token, pipe it in with `--with-token`; that agent must have zero saved webhook subscriptions, because a channel receives over the WebSocket.

## Connect

Run this in a terminal. Relay finds Claude Code and creates an agent with a `.dev` handle. Then it prints what it will change before it changes anything. It adds the Relay marketplace and installs and enables the `relay@relay-messenger` plugin. It writes the channel file at `~/.claude/channels/relay/.env`: the token, the API address, and the allowed senders. It asks `Continue?` and does the work. It ends with `Relay is ready for Claude Code.` and the handle to message from your phone:

```bash
npx relaymessenger@staging connect claude-code
```

Connect then offers to start Claude Code with the channel loaded. Say yes, or start it yourself later with `claude --dangerously-load-development-channels plugin:relay@relay-messenger`. Relay is not on Anthropic's default channel allowlist yet, so that flag is how a custom channel loads during the research preview. An organization administrator can instead add `relay@relay-messenger` to `allowedChannelPlugins`, after which `--channels` is enough.

### Install the plugin yourself

If you would rather not let the CLI touch Claude Code, do the two plugin steps inside a Claude Code session. Add the marketplace from the SDK's `staging` branch, then install the plugin. The plugin starts disabled because it talks to a messaging service. Enable it in `/plugin` for the one session that should receive messages, and run `/reload-plugins` if Claude Code asks:

```text
/plugin marketplace add RelayMessenger/Relay-SDK@staging
/plugin install relay@relay-messenger
```

Claude Code then asks for three settings. The Relay Agent Token goes into its secure credential store, never into `settings.json`. The allowed Relay senders are exact contact UUIDs or handles, separated by commas, and only those senders can start a turn. The Relay API origin is `https://api.staging.relayapp.im` for a staging token. The source is [packages/claude-code](https://github.com/RelayMessenger/Relay-SDK/tree/staging/packages/claude-code) and the [marketplace file](https://github.com/RelayMessenger/Relay-SDK/blob/staging/.claude-plugin/marketplace.json).

## Send it a message

Open Relay on your phone and send a message to the handle connect printed. Claude Code wakes up on its own: the channel holds one acknowledged WebSocket connection, saves each event before it acknowledges it, and hands the message to the running session. Claude reads it, replies, and the reply appears in the same chat on your phone, and in the terminal while connect is waiting. Keep the session open; a closed session receives nothing until it starts again, and then it catches up.

## What it can do

The table says what the Relay channel gives Claude Code. It comes from the connection code for `claude-code` and the channel's three tools: `begin_processing`, `reply`, and `complete_processing`; anything not listed is not there.

| Relay feature | Claude Code |
| --- | --- |
| Connect | The Relay channel plugin, with its config in `~/.claude/channels/relay/.env`. |
| Start | `claude --dangerously-load-development-channels plugin:relay@relay-messenger`; connect offers to start it for you. |
| Wakes when a message arrives | Yes, over the WebSocket, one turn at a time. |
| Reply in the chat | Yes, text up to 10,000 characters, as a reply to the message that started the turn. |
| Send attachments | No. `reply` takes text only. |
| Read chat history | No. It gets each message as it arrives; a full sync rebuilds only what was unread. |
| Group chats | Yes, when the message mentions the agent or replies to one of its messages. |

Sender permission is an allowlist and nothing more. Agent Contacts use the same allowlist as user Contacts. An allowed sender does not get separate model contexts per chat: sender permissions and reply-origin checks are admission rules, not memory isolation. A reply goes only to the chat that authenticated the active turn. A FULL sync after a gap reconciles the unread, allowlisted messages using the agent's own delivery row for Read state. Claude Code's permission prompts remain local to Claude Code; Relay cannot answer them. Delivery is at least once, and a message is never answered twice. A turn closes when Claude calls `reply` or `complete_processing`. A second message that arrives during a turn waits or supersedes it, and a turn older than ten minutes goes back to pending.

## When it fails

Every failure prints one line, and nothing else changes. `Relay cannot ask which agent to connect.` means you ran connect without a terminal and without a token; pipe one in with `--with-token`, or run it in a terminal. `Relay cannot ask you to confirm this plan.` means the same for the plan; add `--yes`. `Relay would not accept that token, so nothing was changed.` means the token and `RELAY_API_URL` come from different environments. `Claude Code was not found on this computer; you named it, so Relay will try anyway` is a notice, not an error: install Claude Code and run connect again. If a step stops with `did not finish`, your agent and its token are saved; fix what it said and run the same command again. If Claude Code starts but the channel refuses to connect, the agent has a saved webhook subscription. A Relay agent has one delivery path, and the channel needs zero saved webhook subscriptions. `No reply yet. Run: relay watch @<handle>` means the session is not running with the channel loaded, or the sender is not on the allowlist; start it as shown under [Connect](/integrations/claude-code#connect).
