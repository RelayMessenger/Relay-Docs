Turn a [Vercel AI SDK](https://ai-sdk.dev) backend into a Relay agent.
`@relaymessenger/vercel-ai` receives signed `message.received` webhooks and
forwards `streamText(...)` output to Relay, which commits it as exactly one
message. The plugin is a thin binding of the public HTTPS contract. Every raw
request it makes is documented on this site and remains available directly.

Prerequisites:

- **An agent and its Agent Token.** See [Create and connect an agent](/guides/your-agent).
- **A registered webhook with its signing secret.** See [Webhooks](/guides/webhooks).
- **A credential for the model you call.** The quickstart's plain `model` string
  resolves through the [Vercel AI Gateway](https://vercel.com/docs/ai-gateway),
  which reads `AI_GATEWAY_API_KEY` from the environment. Without it the model
  call throws `GatewayAuthenticationError` before any reply is sent.

<Info>
The plugin is published as
[`@relaymessenger/vercel-ai`](https://www.npmjs.com/package/@relaymessenger/vercel-ai)
and developed in the public
[`relaymessenger/Relay-SDK`](https://github.com/relaymessenger/Relay-SDK)
repository under `integrations/vercel-ai`.
</Info>

## Quickstart

```bash
npm install @relaymessenger/vercel-ai ai
```

```ts app/api/relay/route.ts
import { createRelay } from "@relaymessenger/vercel-ai";
import { streamText } from "ai";

const relay = createRelay({
  token: process.env.RELAY_AGENT_TOKEN!,
  webhookSecret: process.env.RELAY_WEBHOOK_SECRET!,
});

export const POST = relay.webhook(async ({ message, typing, reply }) => {
  await typing(true, "Thinking…");
  try {
    const result = streamText({
      model: "anthropic/claude-sonnet-5",
      prompt: message.parts.find((p) => p.type === "text")?.text ?? "",
    });
    await reply.stream(result.toUIMessageStreamResponse());
  } finally {
    await typing(false);
  }
});
```

Mount the handler as the POST route your webhook registration points at. It
works in any WinterCG runtime: Next.js route handlers, Cloudflare Workers, or
behind a one-line Express or Hono adapter.

## What the plugin enforces

Each row is a contract from these docs that the plugin implements for you.

| Contract | Plugin behavior |
| --- | --- |
| [Signature verification](/guides/webhooks) | Standard Webhooks HMAC over the exact raw body; unsigned or stale requests get `401` |
| [At-least-once delivery](/guides/delivery-model) | Per-instance `event_id` dedup window, recorded once your handler succeeds, so a failed handler gets its redelivery |
| [Idempotent sends](/guides/sending-messages) | Reply helpers derive `Idempotency-Key` values from the event id and call order; Relay replays the original send on any retry, from any instance |
| [Group invocations](/guides/group-conversations) | `invocation_id` from the event threads into every reply and typing call |
| [Streaming](/guides/streaming) | `reply.stream(...)` forwards the UI message stream to `POST /v1/messages?stream=true`; Relay commits one or more finished messages |
| [Event compatibility](/reference/events) | Unknown event types acknowledge `200` so new Relay events never break your route |

## Configuration

| Option | Description | Default |
| --- | --- | --- |
| `token` | Agent Token used for every send | required |
| `webhookSecret` | Signing secret from webhook registration | required for `webhook()` |
| `baseUrl` | API origin | `https://api.relayapp.im` |
| `toleranceSeconds` | Allowed `webhook-timestamp` skew | `300` |
| `onError` | Receives a handler failure before the route returns `500` | log-and-drop |

## When the route responds

`relay.webhook(handler)` returns a function of `(request, { waitUntil })`. The
second argument is accepted for call-site compatibility with the Vercel and
Cloudflare runtimes and is currently unused: the route runs your handler to
completion, then responds.

A thrown handler error returns `500`. Relay then redelivers the event, and the
derived idempotency keys make the retry safe. Responding before the work
finishes would end delivery for that event, so a handler that then threw would
lose it.

<Note>
Relay stamps [Delivered](/guides/read-receipts) when your route responds, which
here is after the handler finishes rather than when the event arrives.
</Note>

## Handler context

| Field | Contents |
| --- | --- |
| `message` | The full stored message with ordered `parts[]` |
| `event` | The complete event envelope |
| `invocationId` | Present for group deliveries; already threaded into helpers |
| `reply.text` / `reply.parts` / `reply.stream` | Idempotent sends bound to the conversation |
| `typing(started?, label?)` | Proactive typing or an explicit stop |
| `client` | The underlying `RelayClient` for anything beyond the helpers |
