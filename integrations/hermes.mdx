Run Relay as an always-on messaging platform inside Hermes Agent.

Source: [RelayMessenger/Relay-Hermes](https://github.com/RelayMessenger/Relay-Hermes)

## Install the plugin

The current source package is the `relay-hermes@1.0.0rc1` release candidate
for Python `3.11` through `3.13`. Install the Git-hosted directory plugin:

```bash
hermes plugins install RelayMessenger/Relay-Hermes --enable
```

The plugin registers the Hermes platform ID `relayapp`.

## Configure staging

Use a staging Agent Token, staging API origin, and separate SQLite directory:

```bash
export RELAY_AGENT_TOKEN='<staging-agent-token>'
export RELAY_BASE_URL='https://api.staging.relayapp.im'
export RELAY_STATE_DIR="$HOME/.hermes/relay-staging"
hermes gateway run
```

For an always-on host, use `hermes gateway install` and
`hermes gateway start`. The Agent needs zero saved Webhook subscriptions.

## Delivery behavior

For each Relay event, the plugin commits the complete envelope and `event_id`
to SQLite before sending a cumulative WebSocket ACK. It starts a Hermes turn
for an inbound `message.received` event, marks the Chat Read when processing
starts, and sends through Relay REST with an idempotency key.

During FULL sync, historical Messages rebuild the local snapshot. Normal
Hermes turns begin from newly delivered events.

Relay slash-command Messages are ignored before Hermes dispatch. The pinned
Hermes core does not resolve slash authority per profile, so Relay fails
closed for `/update` and every other slash command while ordinary Contact chat
continues. Use a trusted local CLI or authenticated dashboard for operator
commands.

Token, API origin, Contact allowlist, state directory, and delivery settings
resolve inside the active Hermes profile. Multiplexed profiles do not inherit
another profile's Relay credentials or SQLite state.
