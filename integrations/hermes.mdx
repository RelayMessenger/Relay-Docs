Connect Hermes to Relay and talk to it from your phone.

## Before you start

Install [Hermes Agent](https://github.com/NousResearch/hermes-agent#installation) with Python 3.11 through 3.13, sign in to it, and run it once so `~/.hermes/config.yaml` exists. Install Node.js 22.22.3 or newer; the Relay CLI runs with `npx`. Set `RELAY_API_URL` to `https://api.staging.relayapp.im` so Relay talks to the API your agent lives on. You do not need an agent yet: the command below creates one and saves its token on this computer. If you already have an Agent Token, pipe it in with `--with-token`; that agent must have zero saved webhook subscriptions, because the plugin receives over the WebSocket. Stop Hermes before you connect.

## Connect

Run this in a terminal. Relay finds Hermes and creates an agent with a `.dev` handle. Then it prints what it will change before it changes anything. It installs the [Relay-Hermes](https://github.com/RelayMessenger/Relay-Hermes) plugin and writes `~/.hermes/.env`: the token, the API address, and a state folder. It asks `Continue?` and does the work. It ends with `Relay is ready for Hermes.` and the handle to message from your phone:

```bash
npx relaymessenger@staging connect hermes
```

Connect then offers to start the gateway with `hermes gateway run`. Say yes, or start it yourself later. On an always-on host, `hermes gateway install` and `hermes gateway start` run it as a service.

### Install the plugin yourself

If you would rather not let the CLI touch Hermes, install the Git-hosted plugin with Hermes's own command. It registers the Hermes platform id `relayapp`. The same repository installs as a Python package, and its `hermes_agent.plugins` entry point registers the identical adapter:

```bash
hermes plugins install RelayMessenger/Relay-Hermes --enable
```

Then set four values in the active profile's environment. `RELAY_AGENT_TOKEN` is the token from your secret store. `RELAY_BASE_URL` is `https://api.staging.relayapp.im`. `RELAY_STATE_DIR` is an absolute folder for this one agent. `RELAY_ALLOWED_CONTACTS` is optional: the contact UUIDs that may start a turn, separated by commas. Hermes resolves these settings within the active profile. Keep each state folder paired with its token and API origin. The folder is bound to one agent, and changing the identity while reusing its SQLite state fails before startup.

## Send it a message

Open Relay on your phone and send a message to the handle connect printed. Hermes wakes up on its own. The plugin holds one acknowledged WebSocket connection, commits each event to its SQLite inbox before it acknowledges it, marks the chat read, and starts a Hermes turn. The reply appears in the same chat on your phone, and in the terminal while connect is waiting. Keep the gateway running; a stopped gateway receives nothing until it starts again, and then it catches up from the inbox.

## What it can do

The table says what the Relay plugin gives Hermes. It comes from the connection code for `hermes` and the plugin's adapter; anything not listed is not there.

| Relay feature | Hermes |
| --- | --- |
| Connect | The Relay-Hermes plugin, with its config in `~/.hermes/.env`. |
| Start | `hermes gateway run`; connect offers to start it for you. |
| Wakes when a message arrives | Yes, over the WebSocket. |
| Reply in the chat | Yes, text with a stable idempotency key; it quotes the message only when answering one that did not start the turn. |
| Send attachments | Yes. Local files upload through the attachments API, and inbound images land in the Hermes image cache. |
| Read chat history | No. It pages history only during a full sync, and those messages never start a turn. |
| Reactions, edits, typing | No. |

A second message during a reply is Hermes's decision, through its own `display.busy_input_mode` setting. `interrupt` folds it into the running reply, `queue` gives it its own reply afterwards, and `steer` hands it to the running turn after the next tool call. A folded message is settled in the inbox, so a restart does not answer it again. A message that begins with `/` is not a Hermes command. Relay slash commands are withheld from Hermes, and operator commands run only through a trusted local CLI or an authenticated dashboard.

## When it fails

Every failure prints one line, and nothing else changes. `Relay cannot ask which agent to connect.` means you ran connect without a terminal and without a token; pipe one in with `--with-token`, or run it in a terminal. `Relay cannot ask you to confirm this plan.` means the same for the plan; add `--yes`. `Relay would not accept that token, so nothing was changed.` means the token and `RELAY_API_URL` come from different environments. `Hermes was not found on this computer; you named it, so Relay will try anyway` is a notice, not an error: install Hermes and run connect again. If a step stops with `did not finish`, your agent and its token are saved; fix what it said and run the same command again. If the gateway starts but the plugin refuses to connect, the agent has a saved webhook subscription. A Relay agent has one delivery path, and the plugin needs zero saved webhook subscriptions. If it fails before startup naming the state folder, that folder belongs to another token or API origin; give this agent its own `RELAY_STATE_DIR`. `No reply yet. Run: relay watch @<handle>` means the gateway is not running, or the sender is not in `RELAY_ALLOWED_CONTACTS`.
