Relay bridges the `hermes acp` command already installed on your machine. Hermes
configuration, provider credentials, and `~/.hermes/state.db` stay entirely under
Hermes ownership.

Install and authenticate Hermes using its official setup first.

<Steps>
  <Step title="Verify the ACP surface">
    ```bash
    hermes acp --check
    ```

    The readiness check, rather than a version-string cutoff, decides whether the
    local installation can start.
  </Step>

  <Step title="Pair and start">
    ```bash
    npm install -g @relaymessenger/cli
    relaymessenger pair
    relaymessenger start --engine hermes --dir ~/code/my-project
    ```

    Relay launches `hermes acp` shell-free.
  </Step>
</Steps>

## What the bridge carries

The current Hermes ACP server supports:

| Capability | Behavior in Relay |
| --- | --- |
| Persisted sessions | Load and resume across bridge restarts |
| Streamed content | Assistant and reasoning content stream, then commit as one message |
| Tool activity and diffs | Surface in the conversation |
| Cancellation | Propagates to Hermes |
| Plan updates | Surface in the conversation |
| Permission choices | Presented as owner-only Allow and Deny cards |

<Info>
Hermes waits 60 seconds for an ACP permission decision, so Relay uses a
55-second phone window and denies on timeout or transport failure.
</Info>

## Feature reference

<AccordionGroup>
  <Accordion title="Hermes owns its own state">
    Relay launches `hermes acp` shell-free and leaves Hermes configuration,
    provider credentials, and `~/.hermes/state.db` entirely under Hermes
    ownership. Relay reads none of them.
  </Accordion>

  <Accordion title="Readiness, not version strings">
    `hermes acp --check` decides whether the local installation can start,
    rather than an unverified version-string cutoff. The reference
    implementation audited for this release is Hermes Agent 0.18.2, but the
    check is what gates startup.
  </Accordion>

  <Accordion title="Permission window">
    Hermes waits 60 seconds for an ACP permission decision, so Relay uses a
    55-second phone window and denies on timeout or transport failure. The
    shorter window guarantees Relay answers Hermes before Hermes gives up.
  </Accordion>

  <Accordion title="You own installation and upgrades">
    Unlike the Claude and Codex adapters, which are pinned inside
    `relaymessenger`, Hermes is a binary you install and upgrade yourself
    through its official setup.
  </Accordion>
</AccordionGroup>

## Troubleshooting

Start with `relaymessenger doctor`, then
[integration troubleshooting](/integrations/troubleshooting) for symptoms shared
with every other integration. These are specific to this one.

<AccordionGroup>
  <Accordion title="The bridge will not start">
    Run `hermes acp --check` on its own. If the readiness check fails, fix the
    Hermes installation first: Relay will not start against an installation
    that reports itself unready.
  </Accordion>

  <Accordion title="Approvals are denied without you answering">
    An approval that goes unanswered for 55 seconds is denied, as is one that
    hits a transport failure. Answer sooner, or approve at the keyboard.
  </Accordion>
</AccordionGroup>
