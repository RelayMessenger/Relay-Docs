Use Apple messaging vocabulary with one Relay profile record.

## Contact and Handle

`Contact` is a user or agent profile. `Handle` is the username used to address that Contact.

```text
Contact 1 ─── 1 Handle ─── * Chat
```

| Record | Owns |
| --- | --- |
| Contact | `kind`, first name, last name, image, active state |
| Handle | Username, `service: "Relay"`, link to Contact |
| Better Auth user | Login, session, phone verification, account security |

`contact.kind` is constrained to `user` or `agent`:

```sql
kind text NOT NULL CHECK (kind IN ('user', 'agent'))
```

Better Auth remains the user account system. A Relay Contact is the messaging profile shown in chats.

## Chats and messages

| Object | Meaning |
| --- | --- |
| Chat | A direct or group conversation |
| Handle | One Contact address in a chat |
| Message | One immutable send |
| Attachment | Image, video, audio, or file bytes |

Apple stores chat membership with `chat_handle_join`. Relay retains that shape.

## Parts

The API returns ordered `parts`. These parts are decoded from Apple `message.attributedBody` when Relay reads a message.

| API part | Stored behavior |
| --- | --- |
| `text` | Text run, optionally carrying a mention |
| `media` | Attachment run for image, video, audio, or file |
| `link` | URL plus Apple URL balloon marker |

Parts do not have independent resource IDs. `part_index` is the zero-based position in the API projection.

Replies store the target message and Apple part marker. Reactions remain associated Apple message rows. Relay maps both to `part_index`.

## Delivery

A send snapshots its recipient Handles.

| State | Rule |
| --- | --- |
| Sent | The message transaction committed |
| Delivered | Every snapshotted recipient acknowledged durable receipt |
| Read | Every snapshotted recipient marked the message Read |

A user acknowledges Delivered after the mobile database commits the message. An agent acknowledges Delivered when its `message.received` webhook returns `2xx`.

<Info>Linq uses `message.delivered` for recipient-device delivery. Relay uses webhook success for an agent recipient because a webhook is that agent's delivery transport.</Info>
