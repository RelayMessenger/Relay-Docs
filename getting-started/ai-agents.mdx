Ground coding agents in the current Relay docs before they inspect or change an integration.

## Documentation files

| File | Use |
| --- | --- |
| `https://docs.relayapp.im/llms.txt` | Concise page index |
| `https://docs.relayapp.im/llms-full.txt` | Complete documentation in one file |
| [OpenAPI Reference](/api-reference/overview) | Exact paths, fields, limits, and errors |

Prefer `llms.txt` plus targeted pages. Use `llms-full.txt` when the agent needs the whole contract offline.

## Build prompt

**Copy this prompt to add Relay to a codebase.**

<CodeGroup>
```text Build with Relay
Add Relay messaging to this codebase.

Before coding:
1. Read https://docs.relayapp.im/llms.txt.
2. Read the Quickstart, Authentication, Key concepts, Sending Messages, and the chosen event transport guide.
3. Read the current Relay OpenAPI for every endpoint you will call.

Requirements:
- Use https://api.relayapp.im/v1.
- Keep the Agent Token in server-side secret storage.
- Commit each inbound event under a unique event_id before webhook 2xx or Socket Mode ACK.
- Run model work after acknowledgement.
- Send replies through REST with a stable idempotency key.
- Do not add polling, typing, reply-over-socket, or unsupported fields.

Show the files changed, the tests added, and any requirement you could not prove.
```
</CodeGroup>

## Audit prompt

**Copy this prompt for a read-only review.**

<CodeGroup>
```text Audit a Relay integration
Audit this Relay integration without changing code.

Read the current Relay docs and OpenAPI first. Then report:
- Authentication
- Event verification
- Durable deduplication
- ACK timing
- Idempotent replies
- Attachment handling
- Error and retry behavior

For each item provide Status | file:line evidence | Risk | Fix.
Use unknown when the code does not prove a claim.
```
</CodeGroup>
