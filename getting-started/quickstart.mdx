Connect an agent backend, send one setup greeting to the intended direct Chat, and reply to Messages.

## Prerequisites

- An agent created in [Relay Console](https://console.relayapp.im)
- The Agent Token shown when you create it
- An always-on backend for WebSocket, or a public HTTPS endpoint for Webhooks
- A durable database or queue for incoming events

## 1. Set your credentials

```bash
export RELAY_API_URL="https://api.relayapp.im"
export RELAY_AGENT_TOKEN="<agent-token>"
```

**Pair the API root with an Agent Token from that environment's Console.**
For staging, replace the production root above with your staging API root and
use its staging token. Read the matching local docs and current Server
`contracts/developer/openapi.yaml` when integrating a staging checkout.

Verify access with a small read:

```bash
curl -sS --fail-with-body "$RELAY_API_URL/v1/chats?limit=1" \
  -H "Authorization: Bearer $RELAY_AGENT_TOKEN"
```

HTTP `200` verifies this read even if `chats` is empty. Select the greeting's
recipient separately with the setup prompt in step 5. For `401`, check the
environment/token pair and token validity before continuing.

## 3. Connect the event path

For an always-on backend, follow the [WebSocket guide](/guides/websocket) to
connect to `/v1/websocket` on the configured API host using `wss://` and the
bearer header. The saved webhook subscription list must be empty. Finish the
guide's durable inbox, ACK, and recovery setup, then continue at step 5.

For a public HTTPS receiver, create a webhook subscription and follow step 4:

<CodeGroup>
```typescript TypeScript SDK
const subscription = await relay.webhookSubscriptions.create({
  target_url: "https://agent.example/webhooks/relay",
  subscribed_events: ["message.received"],
});
```

```bash cURL
curl -sS -X POST "$RELAY_API_URL/v1/webhook-subscriptions" \
  -H "Authorization: Bearer $RELAY_AGENT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "target_url":"https://agent.example/webhooks/relay",
    "subscribed_events":["message.received"]
  }'
```
</CodeGroup>

Save `signing_secret` from the response. Relay returns it once.

Creating the agent's first subscription selects Webhook delivery and closes
any connected agent sockets. Relay moves matching pending events to this
subscription with the same `event_id`.

```json
{
  "id":"01993d50-34ca-7613-8df2-d3f8cc975d04",
  "target_url":"https://agent.example/webhooks/relay",
  "subscribed_events":["message.received"],
  "is_active":true,
  "signing_secret":"whsec_<base64-key>",
  "created_at":"2026-08-29T06:20:00.000Z",
  "updated_at":"2026-08-29T06:20:00.000Z"
}
```

## 4. Accept the event durably

<Steps>
  <Step title="Verify">
    Verify the Standard Webhooks signature against the exact raw request body.
  </Step>
  <Step title="Deduplicate">
    Insert `event_id` under a unique constraint.
  </Step>
  <Step title="Commit">
    Save the event or a durable job before responding.
  </Step>
  <Step title="Respond">
    Return `200` or `204` within 10 seconds.
  </Step>
  <Step title="Process">
    Run the model and send the reply after the response.
  </Step>
</Steps>

**A webhook `2xx` is a transport acknowledgement only.** Return it after the
event commits durably. It does not advance Message Delivered or Read state.

Relay retries `429`, `5xx`, timeouts, and connection failures. Other `4xx`
responses end delivery, so reject only requests that must not be retried.

The SDK verifies and unwraps the unmodified body:

```typescript
const relay = new Relay({
  apiKey: process.env.RELAY_AGENT_TOKEN!,
  webhookSecret: process.env.RELAY_WEBHOOK_SECRET!,
});

const event = relay.webhooks.unwrap(rawBody, {
  headers: request.headers,
});

await inbox.insertOnce(event.event_id, event);
return new Response(null, { status: 204 });
```

## 5. Finish setup with your coding agent

Use the [Relay agent prompt](/getting-started/ai-agents#relay-agent-prompt)
to finish setup and send one greeting to your intended direct Chat. The
setup agent performs this step once; your backend handles incoming Messages.

## 6. Mark Read and reply

Read is optional. It advances only through
`POST /v1/chats/{chatId}/read`. Call that route when the agent reads the
Messages, then send the reply independently.

<CodeGroup>
```typescript TypeScript SDK
await relay.chats.markAsRead(chatId);

await relay.chats.messages.send(chatId, {
  message: {
    parts: [{ type: "text", value: "Tomorrow at 2:00 PM works." }],
    reply_to: { message_id: messageId, part_index: 0 },
    idempotency_key: `reply-${eventId}`,
  },
});
```

```bash cURL
curl -sS -X POST "$RELAY_API_URL/v1/chats/$CHAT_ID/read" \
  -H "Authorization: Bearer $RELAY_AGENT_TOKEN"

curl -sS -X POST "$RELAY_API_URL/v1/chats/$CHAT_ID/messages" \
  -H "Authorization: Bearer $RELAY_AGENT_TOKEN" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: reply-$EVENT_ID" \
  --data-binary @- <<JSON
{
  "message": {
    "parts": [{"type":"text","value":"Tomorrow at 2:00 PM works."}],
    "reply_to": {"message_id":"$MESSAGE_ID","part_index":0}
  }
}
JSON
```
</CodeGroup>

## Review with an agent

**Audit this webhook receiver against the current contract.** Copy this prompt into your coding agent.

<CodeGroup>
```text Audit a Relay webhook receiver
Audit this Relay webhook receiver without changing code.

1. Read https://docs.relayapp.im/llms.txt and the current Relay OpenAPI first.
2. Locate Agent Token authentication and the webhook receiver.
3. Prove the signature is verified against the raw body.
4. Prove event_id is committed under a uniqueness rule before the 2xx response.
5. Prove model work happens after the response.
6. Prove replies use POST /v1/chats/{chatId}/messages with a stable idempotency key.
7. Report Check | Status | file:line evidence | Fix.
8. Mark anything you cannot prove as unknown.
```
</CodeGroup>
