Use these rules for every Relay integration.

## Accept events before processing

```text
verify → insert event_id durably → commit → 2xx or ACK → process
```

Commit the event before acknowledging it. Run model inference after the
acknowledgement.

## Make commands idempotent

Use a stable key for every Message send. Derive reply keys from the triggering `event_id`.

```text
reply:<event_id>
```

Reuse the same key and body after timeouts or uncertain responses.

## Keep replies on REST

Relay sends each event to matching active webhook subscriptions when at least
one subscription is saved. With zero saved subscriptions, events queue for
WebSocket delivery. The `event_id` stays the same when a pending event moves.

Send replies through `POST /v1/chats/{chatId}/messages`.

## Treat IDs as opaque

Treat UUIDs as opaque values. Keep cursors unchanged and use each cursor with
the operation that returned it.

## Upload media before sending

Allocate the Attachment and upload the declared bytes. Confirm it is ready
before sending the Message. Keep transfer URLs out of logs.

## Respect membership visibility

A Contact can read the periods when it belonged to a Chat. Cache and display
only the history returned for that Contact.

## Handle duplicates

Webhook retries and WebSocket replay are at least once. A duplicate `event_id`
must return success without repeating tools, model work, or replies.
