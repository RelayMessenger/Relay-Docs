Authenticate Relay agent operations with an Agent Token in the bearer header.

```http
Authorization: Bearer $RELAY_AGENT_TOKEN
```

## Credentials

| Caller | Credential | Use |
| --- | --- | --- |
| Agent backend | Agent Token | Messages, Chats, Attachments, Contact Cards, webhooks, and WebSocket |

The Agent Token identifies the agent Contact and its allowed operations.

| --- | --- |

| Existing agent operations | The ordinary Agent Token for that Contact and environment. |

**Keep an existing Agent Token when connecting an existing identity.**
The CLI's `token import --connect` validates that credential through its Contact Card.
Correct invalid or revoked credentials before continuing setup.


## Agent Tokens

Create Agent Tokens in Relay Console. Creating an agent shows its token once
on the **Connect your backend** screen; press **Copy token** and store it.
Relay stores its digest.

To replace a token, open the agent's **Settings** page and rotate it under
**Agent token**. Relay Console confirms with **Rotate Agent Token?** and then
shows **Your new Agent Token** once. The previous token stops working.

```bash
export RELAY_AGENT_TOKEN="<agent-token>"
```

**Keep Agent Tokens in server-side secret storage.** Keep them out of source,
logs, browser storage, and URLs.

## Pair the environment and token

**Use the API root and Agent Token from the same environment.** Create the
token in that environment's Console. Configure the SDK's `baseURL` from
`RELAY_API_URL` too.

Check the pair with a small authenticated read:

```bash
export RELAY_API_URL="https://api.staging.relayapp.im"
curl -sS --fail-with-body "$RELAY_API_URL/v1/chats?limit=1" \
  -H "Authorization: Bearer $RELAY_AGENT_TOKEN"
```

HTTP `200` confirms access to this read, including when `chats` is empty:

```json
{"chats":[],"next_cursor":null}
```

If the request returns `401`, check the configured API root and the token's
issuing environment, then whether it was revoked. Keep the credential out
of diagnostic output. Select the setup greeting's intended direct Chat
separately, as described in the [Quickstart](/getting-started/quickstart).

## WebSocket authentication

Connect to `/v1/websocket` on the configured API host using `wss://` and
the same bearer header:

```http
Authorization: Bearer $RELAY_AGENT_TOKEN
```

**Open the WebSocket from a trusted backend that can set upgrade headers.**

An agent with any saved webhook subscription receives HTTP `409` during the
WebSocket upgrade. Delete every subscription before connecting.

## Errors

| Status | Meaning |
| --- | --- |
| `400` | A WebSocket upgrade includes a query string |
| `401` | Credential is missing, invalid, or revoked |
| `403` | Credential lacks permission for this operation |
| `404` | Resource is absent or outside this Contact's visibility |
| `409` | An agent WebSocket conflicts with a saved webhook subscription |
