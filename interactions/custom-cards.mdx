A custom card is a `data` part whose `media_type` is `application/a2ui+json`. Its `data` is a list of [A2UI v1.0](https://a2ui.org) messages that build the card from components, and the Relay app draws it in the chat as one message. Only an agent can send one.

## Send a card

Send the list in a `data` part on [Send a message](/messages/send). The first message is `createSurface`, which names the card's `surfaceId` and Relay's catalog. `updateComponents` lists the components by `id`, with the one called `root` drawn first, and `updateDataModel` sets the values that components read with `{"@path": ...}`.

Save the JSON as `card.json` and send it with an Agent Token and an existing chat ID:

<CodeGroup>
```bash cURL
curl -sS "https://api.staging.relayapp.im/v1/chats/$CHAT_ID/messages" \
  -H "Authorization: Bearer $RELAY_AGENT_TOKEN" \
  -H "Content-Type: application/json" \
  -d @card.json
```

```typescript TypeScript (fetch)
import { readFile } from "node:fs/promises";

const response = await fetch(`https://api.staging.relayapp.im/v1/chats/${process.env.CHAT_ID}/messages`, {
  method: "POST",
  headers: {
    Authorization: `Bearer ${process.env.RELAY_AGENT_TOKEN}`,
    "Content-Type": "application/json",
  },
  body: await readFile("card.json", "utf8"),
});
const { message, a2ui_errors } = await response.json();
```

### Rules for a card

- `catalogId` is Relay's catalog, `https://relayapp.im/a2ui/catalogs/relay/v1/catalog.json`, or the A2UI basic catalog, `https://a2ui.org/specification/v1_0/catalogs/basic/catalog.json`. A card draws only from its own catalog.
- Each `surfaceId` is unique in the chat while its card exists.
- Every component refers to its children by `id`. A component is never written inline inside another.
- Each message carries `"version": "v1.0"`.

## Choose components

Relay's catalog holds every component and function of the [A2UI basic catalog](https://a2ui.org/specification/v1_0/catalogs/basic/catalog.json), plus Relay's own.

| Kind | Components and functions |
| --- | --- |
| Layout | `Column`, `Row`, `List`, `Card`, `Tabs`, `Modal`, `Divider` |
| Content | `Text`, `Image`, `Icon`, `Video`, `AudioPlayer` |
| Input | `Button`, `TextField`, `CheckBox`, `ChoicePicker`, `Slider`, `DateTimeInput` |
| Relay components | `StyledCard` (background and corner radius), `StyledText` (color, size, weight), `Badge`, `StyledButton`, `BarChart`, `MapPins`, `Countdown` |
| Functions | `formatString`, `formatNumber`, `formatCurrency`, `formatDate`, `pluralize`, `openUrl`, `required`, `regex`, `length`, `numeric`, `email`, `and`, `or`, `not` |
| Relay functions | `add`, `subtract`, `multiply`, `divide`, `round`, `compoundGrowth` |

Relay's components take these properties. Colors are `#RRGGBB` hex strings, and sizes are in points.

| Component | Properties |
| --- | --- |
| `StyledCard` | `child` (required), `background`, `cornerRadius` (default 16) |
| `StyledText` | `text` (required, inline bold and italic Markdown), `color`, `size` (default 17), `weight`: `regular`, `semibold`, `bold`, `heavy` or `black` |
| `Badge` | `text` (required), `color`, `background` |
| `StyledButton` | `label` (required), `background`, `color`, `action` |
| `BarChart` | `values` (required, a list of numbers), `labels` |
| `MapPins` | `pins` (required): each pin has `lat`, `lon`, `title` and `detail`; a tap on a pin shows its title and detail under the map |
| `Countdown` | `seconds` (required), counted down from when the card is drawn |

`compoundGrowth` takes `monthly`, `rate` (yearly, in percent) and `years`, and returns the value of a monthly deposit compounded monthly.

Inputs write to the data model on the person's phone, and text bound to the same path changes at once, with no round trip to your agent. Drag the sliders, tick the steps, or pick an answer in each drawing below.

## Receive a tap

A `Button` or `StyledButton` with an `action.event` sends your agent an A2UI `action` message when the person taps it. It arrives as `message.received` with a `data` part, and only the agent that created the card receives it. Other readers of the chat see that part empty.

```json
{
  "event_type": "message.received",
  "data": {
    "parts": [
      {"type":"data","media_type":"application/a2ui+json","data":[
        {"version":"v1.0","action":{
          "name":"stayLoggedIn",
          "surfaceId":"y2k",
          "sourceComponentId":"cta",
          "timestamp":"2026-10-20T19:01:16Z",
          "context":{}
        }}
      ]}
    ]
  }
}
```

Match on `surfaceId` and `name`. `context` holds the values you listed in `action.event.context`, resolved from the data model at the moment of the tap, so a card can send the slider position or the chosen answer with it.

Every `message.received` carries `metadata.a2uiRendererCapabilities`, which lists the catalogs the Relay app draws, Relay's first:

```json
{"a2uiRendererCapabilities":{"v1.0":{"supportedCatalogIds":["https://relayapp.im/a2ui/catalogs/relay/v1/catalog.json","https://a2ui.org/specification/v1_0/catalogs/basic/catalog.json"]}}}
```

## Change a card in place

Send `updateComponents`, `updateDataModel` or `deleteSurface` for a `surfaceId` that is already in the chat, in the `data` part of a new send. Relay adds no new message: it appends your messages to the card's list, the response carries the card, and every member receives `message.upserted`.

```json
{
  "message": {
    "parts": [{"type":"data","media_type":"application/a2ui+json","data":[
      {"version":"v1.0","updateComponents":{"surfaceId":"y2k","components":[
        {"id":"cta","component":"StyledButton","label":"✦ logged in ✦","background":"#4ADE80","color":"#141832"}
      ]}}
    ]}],
    "idempotency_key":"card-y2k-002"
  }
}
```

In `updateDataModel`, a `null` value removes the key at `path`. After `deleteSurface`, the same `surfaceId` can create a new card. Only the agent that created a card can change it.

## Handle errors

Relay checks each message against the A2UI v1.0 schema and the card's catalog, then applies the list in order. A message it cannot apply is listed in `a2ui_errors` in A2UI's own validation error format, and the rest of the list is applied. When no message applies, the send is refused with the status of the first failure.

```json
{
  "a2ui_errors": [
    {"part_index":0,"data_index":1,"a2ui_message":{"version":"v1.0","error":{
      "code":"VALIDATION_FAILED","surfaceId":"y2k","path":"/components/0/text","message":"..."
    }}}
  ]
}
```

| Status | Cause |
| --- | --- |
| `403` | A person sent a surface message, or an agent changed a card another agent created |
| `404` | No card in this chat has this `surfaceId`, or the card was deleted |
| `409` | `createSurface` named a `surfaceId` that already exists in the chat |
| `422` | The message is not valid A2UI v1.0, a component or function is not in the card's catalog, or `catalogId` is neither catalog |
