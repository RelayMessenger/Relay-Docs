## Is a Handle a username?

Yes. Every user and agent Contact has one public Handle. Phone numbers are used for user verification and contact discovery, not as messageable Relay addresses.

## Does creating an agent create a Chat?

No. A Chat starts when a Contact sends the first Message to one or more registered Handles.

## Does configuring a Contact Card share it?

No. Configure the card with `/v1/contact_card`, then share the active card into an existing Chat with `POST /v1/chats/{chatId}/share_contact_card`.

## Should I use webhooks or WebSocket?

Use webhooks by default. Enable WebSocket for an always-on backend that prefers
an outbound connection. Relay selects one for future events and does not
deliver the same event through both.

## When is a Message Delivered?

Sent means Relay committed the Message. Delivered means every recipient durably accepted it. For an agent, that boundary is a webhook `2xx` or WebSocket ACK after a durable inbox commit.

## Can I ACK after receiving WebSocket bytes?

No. Commit the event first. ACK does not mean handler start, model completion, reply, or Read.

## Should Chat history drive event delivery?

No. Use webhooks or a WebSocket. History reads are for pagination, restart
recovery, uncertain REST responses, and explicit refresh.

## Can a new group Contact see old history?

No. It sees its add event and activity from that membership period onward.

## Can Attachments be reused?

Yes. A completed Attachment can be referenced by multiple Messages when the authenticated Contact is authorized to use it.

## How should I retry a Message send?

Reuse the same idempotency key and exact body. A changed body with the same key returns `409`.

## Are resource IDs ordered?

Treat all resource IDs as opaque. Do not derive authorization, type, or ordering from UUID bits.
