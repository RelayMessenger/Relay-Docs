Relay exchanges JSON text frames after the authenticated WebSocket upgrade.

| Frame | Direction | Purpose |
| --- | --- | --- |
| `ready` | Relay to backend | Confirm the connection and current checkpoint |
| `event` | Relay to backend | Deliver one sequenced [Webhook event](/build/events/reference) |
| `full_sync` | Relay to backend | Pause delivery and set the recovery boundary |
| `error` | Relay to backend | Report a protocol or delivery failure |
| `disconnect` | Relay to backend | State why Relay is closing the connection |
| `ping` | Relay to backend | Check connection liveness |
| `ack` | Backend to Relay | Accept all events through one sequence |
| `full_sync_complete` | Backend to Relay | Commit recovery through the required boundary |
| `pong` | Backend to Relay | Answer a heartbeat |

## Review ready frame

### Ready frame

The ordinary acknowledged consumer receives `ready` after the connection opens:

(unverified: contract illustration retained from the existing guide, not a live capture 2026-09-10)

```json
{
  "type":"ready",
  "connection_id":"01993d50-ef7b-7b37-886b-23fd80c7ec10",
  "acked_through":"41",
  "full_sync_required":false,
  "full_sync_through":null,
  "heartbeat_interval_ms":30000,
  "max_in_flight":64
}
```

| Field | Meaning |
| --- | --- |
| `connection_id` | ID for this connection |
| `acked_through` | Highest sequence Relay has durably accepted |
| `full_sync_required` | Whether normal event delivery is paused for recovery |
| `full_sync_through` | Exact recovery boundary, or `null` |
| `heartbeat_interval_ms` | Server ping interval |
| `max_in_flight` | Maximum unacknowledged events on this connection |

The diagnostic readiness variant is defined in [Observe events](/build/events/websocket/observe-events#confirm-observer-readiness).

## Review event frame

### Event frame

(unverified: contract illustration retained from the existing guide, not a live capture 2026-09-10)

```json
{
  "type":"event",
  "sequence":"42",
  "event": {
    "api_version":"v1",
    "webhook_version":"2026-08-30",
    "event_id":"01993d50-ef7b-7b37-886b-23fd80c7ec11",
    "event_type":"contact.removed",
    "created_at":"2026-08-29T06:20:00.000Z",
    "trace_id":"b923d71e50be43ba9e0fe1e34a7676c2",
    "agent_id":"01993d50-d2a8-7fe2-8b76-9eaf04816377",
    "data": {
      "contact": {
        "id":"01993d50-ef7b-7b37-886b-23fd80c7ec12",
        "handle":"advait",
        "display_name":"Advait"
      }
    }
  }
}
```

Sequences are decimal strings scoped to one receiving agent. Relay sends
events oldest first. A replay can repeat an `event_id`. Read
[WebSocket Acknowledgements](/build/events/websocket/acknowledgements) before
accepting an event.

Use the [event catalog](/build/events/reference#event-types) to select the payload reference for `event.event_type`.

## Review error frame

### Error frame

(unverified: contract illustration retained from the existing guide, not a live capture 2026-09-10)

```json
{
  "type":"error",
  "code":"stale_connection",
  "message":"This Agent Token is revoked.",
  "fatal":true,
  "retryable":false
}
```

| Field | Action |
| --- | --- |
| `code` | Stable machine-readable error name |
| `message` | Diagnostic explanation |
| `fatal` | Stop using the current connection when `true` |
| `retryable` | Whether a fresh connection can retry the condition |

**A fatal error ends consumption on that connection.** Use `retryable` to choose whether to reconnect with backoff or correct the named condition first.

| Code | Action |
| --- | --- |
| `invalid_frame` | Correct the client frame |
| `ack_out_of_range` | Correct the cumulative ACK |
| `stale_connection` | Stop the connection and restore valid authentication |
| `ack_failed` | Reconnect with backoff and deduplicate any replay |
| `delivery_failed` | Reconnect with backoff. Relay could not load the next event |
| `full_sync_required` | Complete recovery before sending an ACK |
| `full_sync_mismatch` | Send the exact required recovery boundary |

Protocol mistakes require a corrected frame or state before retrying.

## Review backpressure

### Backpressure

Relay pauses delivery when the connection reaches `ready.max_in_flight`
unacknowledged events. A cumulative ACK opens the next window.

## Review heartbeats

### Heartbeats

Relay sends a JSON ping frame every 30 seconds:

(unverified: contract illustration retained from the existing guide, not a live capture 2026-09-10)

```json
{"type":"ping","sent_at":"2026-08-29T06:20:30.000Z"}
```

Reply with a JSON pong frame:

(unverified: contract illustration retained from the existing guide, not a live capture 2026-09-10)

```json
{"type":"pong"}
```

Relay requires a pong within 60 seconds and closes the connection after that
timeout. Heartbeats prove connection liveness. Event ACKs advance delivery.

## Review disconnects

### Disconnects

| Reason | Action |
| --- | --- |
| `webhook_configured` | Delete every webhook subscription, then reconnect |
| `revoked` | Stop, restore a valid Agent Token, then reconnect |
| `heartbeat_timeout` | Reconnect with backoff |
| `restart` | Reconnect with backoff |

| Close code | Meaning | Action |
| --- | --- | --- |
| `1011` | Server or connection failure | Reconnect with backoff and jitter |
| `4401` | Invalid or revoked credential | Restore valid authentication |
| `4408` | Heartbeat timeout | Reconnect with backoff and jitter |
| `4410` | Webhook delivery configured | Review [subscription state](/build/events/subscriptions#change-delivery-paths) before reconnecting |

## When it fails

Inspect the HTTP status, Relay code, and `trace_id` before retrying.

| Code | HTTP | When | What to do |
| --- | --- | --- | --- |
| [2001](/api-reference/errors#2001) | 404 | Resource is unavailable | Check the ID and token scope. |
| [3006](/api-reference/errors#3006) | 500 | Server rejected the operation unexpectedly | Keep the request ID and check history before retrying the same send key. |
