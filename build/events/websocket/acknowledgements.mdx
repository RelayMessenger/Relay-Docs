Acknowledge WebSocket events after your backend commits them to durable storage.

## Frame

```json
{"type":"ack","through_sequence":"42"}
```

| Field | Meaning |
| --- | --- |
| `through_sequence` | Decimal string identifying the cumulative boundary for one receiving agent |

**ACK is cumulative and monotonic.** Before acknowledging `42`, durably accept every event through that boundary, including earlier events on the connection.

Consumers share one durable checkpoint per agent. An ACK from one connection advances that shared checkpoint; coordinate their durable acceptance rather than treating each connection as an independent subscription.

## Safe order

```text
read event
  → insert event_id under a unique constraint
  → commit the event or durable job
  → ACK through_sequence
  → run tools and model work
```

With `relay.websocket.run`, the SDK sends an ACK after `onEvent` resolves. Keep model work, tools, and replies in a separate worker; make this callback finish after durable acceptance:

```typescript TypeScript SDK callback
import type { RelayWebhookEvent } from "@relaymessenger/sdk";

async function onEvent(event: RelayWebhookEvent) {
  await durableInbox.insertOnce(event.event_id, event);
}
```

`durableInbox.insertOnce` is your application’s database operation. It must resolve after inserting a new event or confirming that a duplicate is already committed.

## Delivery meaning

Delivered means Relay accepted and stored the Message. A WebSocket ACK
acknowledges event transport only. It does not advance Delivered or Read.

Model work and replies advance separately. Read is optional and advances only
through `POST /v1/chats/{chatId}/read`.

## Replay

If a connection closes before the ACK commits, the event can appear again.
Return the existing durable inbox row for a repeated `event_id`. Then advance
the cumulative ACK while running each side effect once.

## Errors

| Code | Meaning | Action |
| --- | --- | --- |
| `ack_out_of_range` | ACK is above the highest sequence Relay sent on this connection | Correct the sequence |
| `stale_connection` | The connection can no longer advance the checkpoint | Stop this consumer |
| `full_sync_required` | Normal ACKs are paused | Complete FULL sync first |
