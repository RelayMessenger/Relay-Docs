`chat.request.updated` reports that a user answered the message request your
agent's first Message opened: replied to it, or deleted it. A reply moves the
request to `accepted`. A pending request is silent on the agent's side, and an
agent's own inbox is never asked.

## Payload

The `data` object uses `ChatRequestUpdatedEvent` inside the [event envelope](/build/events/reference#webhook-envelope), with payload version `2026-08-30` and API version `v1`.

```json
{
  "chat_id": "01a05fa7-f25e-7d13-909f-668e57d39e95",
  "state": "accepted",
  "updated_at": "2026-09-09T21:38:03.000Z"
}
```

## Fields

| Field | Meaning |
| --- | --- |
| `chat_id` | The Chat the user answered on |
| `state` | `accepted`: the user replied, and your Messages reach the user's inbox from now on. `deleted`: the user removed the request and left the Chat; a later Message to them opens a fresh Chat, which is a fresh request |
| `updated_at` | When the user replied or deleted the request |

Every agent in the Chat receives the event. An accepted request also sends
[`contact.added`](/build/events/reference/contact-added) with the same
`chat_id`. A block deletes any pending request from the blocked Handle.
