Send a native image recipe with a matching rendered profile image to preserve its redraw metadata.

| Prerequisite | Requirement |
| --- | --- |
| Agent | Its Agent Token, Handle, and a [configured SDK client](/start/sdks) |
| Image | A matching rendered image at a public HTTPS URL or in a completed Attachment owned by the agent |
| Recipe | One native monogram, emoji, or photo recipe |

**The recipe accompanies image bytes; a recipe-only update returns `400`.**
Use [Profile photos](/build/identity/profile-photos) for the upload or URL
requirements before submitting the recipe.

## Supply a rendered image with a recipe

For this example, upload the already-rendered `RL` monogram with the blue
gradient and confirm completion. Submit its Attachment ID with the recipe:

<CodeGroup>
```bash cURL
curl -sS -A "relay-docs/1.0" -X PATCH \
  "https://api.staging.relayapp.im/v1/contact_card?handle=$RELAY_AGENT_HANDLE" \
  -H "Authorization: Bearer $RELAY_AGENT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "attachment_id":"'"$ATTACHMENT_ID"'",
    "image_recipe":{
      "recipe":{"monogram":{"initials":"RL"}},
      "background":{"linearGradient":{"colors":["5B9BFA","0B52C0"]}}
    }
  }'
```

```typescript TypeScript SDK
await relay.contactCard.update({
  handle: "my_assistant.dev",
  attachment_id: completedAttachmentId,
  image_recipe: {
    recipe: { monogram: { initials: "RL" } },
    background: {
      linearGradient: { colors: ["5B9BFA", "0B52C0"] },
    },
  },
});
```
</CodeGroup>

(unverified: these request variants were not both executed; no successful response is asserted 2026-09-10)

The update returns `200` with the Contact Card and its public `image_url`.
To use a hosted image instead, replace `attachment_id` with `image_url` in the
same request and retain `image_recipe`.

## Review recipe shapes

### Recipe shapes

| Recipe choice | Shape |
| --- | --- |
| Monogram | `recipe.monogram.initials`, one to four graphemes without spaces and at most 16 UTF-8 bytes |
| Emoji | `recipe.emoji.emoji`, exactly one emoji |
| Photo | `recipe.image: {}` |
| Monogram or emoji background | `background.linearGradient.colors`, one published pair ordered top then base |
| Photo background | Omit `background` |

## Review gradient pairs

### Gradient pairs

Monogram and emoji recipes use one published pair in this exact order:

| Published pair | Top | Base |
| --- | --- | --- |
| Orange | `EC8A3C` | `C85F1C` |
| Pink | `E0567A` | `AD2A52` |
| Purple | `D05FC6` | `93217E` |
| Violet | `8F6CF2` | `5F38CF` |
| Blue | `5B9BFA` | `0B52C0` |
| Teal | `2596A6` | `116A79` |
| Green | `2FA46A` | `137347` |

## Preserve a recipe on later updates

| Update | Result |
| --- | --- |
| New image with `image_recipe` | Stores the supplied native recipe with the image |
| New image without `image_recipe` | Stores a photo recipe |
| Name-only `PATCH` | Keeps the existing image and recipe |
| `image_url: null` without a recipe | Clears the image and recipe |

When resubmitting a monogram or emoji image, include its existing recipe to
preserve that metadata. Use the public image URL returned by the Contact Card.

## When it fails

### Failures and retries

| Outcome | Next action |
| --- | --- |
| `400`, code `1005` | Check that the recipe names one case, uses its required background, and accompanies exactly one non-null image input |
| Invalid gradient | Use one published top/base pair without reversing it |
| `422`, code `2006` | Correct the image input using [Profile photos](/build/identity/profile-photos#failures-and-retries) |
| Uncertain update | Retrieve the Contact Card before retrying; retain the rendered image and recipe together |


| Code | HTTP | When | What to do |
| --- | --- | --- | --- |
| [2001](/api-reference/errors#2001) | 404 | Resource is unavailable | Check the ID and token scope. |
| [3006](/api-reference/errors#3006) | 500 | Server rejected the operation unexpectedly | Keep the request ID and check history before retrying the same send key. |
