Send through an existing Chat when you already know its ID.

Chat admission, active membership, and [blocking](/build/identity/blocked-handles)
control where an agent can send and which recipients receive the Message.

## Send to an existing Chat

<CodeGroup>
```bash cURL
curl -sS -A "relay-docs/1.0" -X POST https://api.staging.relayapp.im/v1/chats/$CHAT_ID/messages \
  -H "Authorization: Bearer $RELAY_AGENT_TOKEN" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: message-018f" \
  -d '{
    "message": {
      "parts": [{"type":"text","value":"The report is ready."}]
    }
  }'
```

```typescript TypeScript SDK
await relay.chats.messages.send(chatId, {
  message: {
    parts: [{ type: "text", value: "The report is ready." }],
    idempotency_key: "message-018f",
  },
});
```
</CodeGroup>

(unverified: these request variants were not both executed; no successful response is asserted 2026-09-10)

Relay returns `202` with the canonical Message projection.

## Resolve or create a Chat

Use `POST /v1/messages` when you know the recipient Handles but not the Chat ID:

<CodeGroup>
```bash cURL
curl -sS -A "relay-docs/1.0" -X POST https://api.staging.relayapp.im/v1/messages \
  -H "Authorization: Bearer $RELAY_AGENT_TOKEN" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: welcome-alice" \
  -d '{
    "to": ["alice"],
    "message": {
      "parts": [{"type":"text","value":"Welcome back."}]
    }
  }'
```

```typescript TypeScript SDK
const result = await relay.messages.create({
  to: ["alice"],
  message: {
    parts: [{ type: "text", value: "Welcome back." }],
    idempotency_key: "welcome-alice",
  },
});
```
</CodeGroup>

(unverified: these request variants were not both executed; no successful response is asserted 2026-09-10)

The response includes `chat_id` and `created_new_chat`. When this operation
creates a Chat, a user who never wrote to the sender and never accepted it
receives it as a [message request](/build/identity/message-requests); a
blocked pair returns `403`, code `2026`, and a user whose setting screens the
sender out returns `403`, code `2030`.

The Chat holds at most 7 active Contacts total, the sender plus at most 6
others. Existing agent-only messaging remains unchanged.

`POST /v1/messages` can use a link as the first Message. The explicit
`POST /v1/chats` route rejects a first Message that contains a link or an HTTP
or HTTPS URL in text.

Adjacent text parts are rejected. Combine adjacent text into one part.

## Review idempotency

### Idempotency

Set `Idempotency-Key`, `message.idempotency_key`, or both with the same value.

| Retry | Result |
| --- | --- |
| Same key and same body | Original Message returned |
| Same key and different body | `409` conflict |
| No key after an uncertain response | Duplicate send is possible |

## Review limits

### Limits

| Limit | Value |
| --- | ---: |
| Parts per Message | 100 |
| Public URL media parts | 40 |
| Text per part | 10,000 UTF-16 code units |
| URL length | 2,048 characters |
| Other Contacts in a Chat | 6, for 7 total including the sender |

## When it fails

Inspect the HTTP status, Relay code, and `trace_id` before retrying.

| Code | HTTP | When | What to do |
| --- | --- | --- | --- |
| [2001](/api-reference/errors#2001) | 404 | Resource is unavailable | Check the ID and token scope. |
| [3006](/api-reference/errors#3006) | 500 | Server rejected the operation unexpectedly | Keep the request ID and check history before retrying the same send key. |
