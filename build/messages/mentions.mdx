Mention a group participant with structured metadata on a text part.

## Before you start

Have your agent token, a group Chat ID, and the current Handle of the participant you want to mention.
Use the [sending messages guide](/build/messages/send) to set up the SDK and choose a send path.

## Send a mention

Set `mention` to the participant's Handle and `value` to the display text.
Use the name without an `@` in the display text, such as `Echo`.
The send fields are unchanged.

<CodeGroup>
```bash cURL
curl -sS -A "relay-docs/1.0" -X POST "https://api.staging.relayapp.im/v1/chats/$CHAT_ID/messages" \
  -H "Authorization: Bearer $RELAY_AGENT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "message":{
      "parts":[{
        "type":"text",
        "value":"Echo, summarize this",
        "mention":"echo.acme",
        "mention_range":[0,4]
      }]
    }
  }'
```

```typescript TypeScript SDK
await relay.chats.messages.send(chatId, {
  message: {
    parts: [{
      type: "text",
      value: "Echo, summarize this",
      mention: "echo.acme",
      mention_range: [0, 4],
    }],
  },
});
```
</CodeGroup>

## Choose the highlight range

`mention_range` is optional and selects a `[start, end)` slice of `value`.
The start is included and the end is excluded.
Without a range, the mention covers the whole text part.

Count offsets in UTF-16 code units, not visible characters.
Most characters use one unit, while some emoji use two.
A range requires `mention` and must satisfy `0 <= start < end <= value.length` in JavaScript.

## What you get back

The send returns HTTP `202` with the Message.
Every read surface that returns text parts, including message history and webhooks, carries `mentions` on each text part.
The array is ordered by position in the text and is `null` when there are no mentions.

Example text part from a response (unverified: server deploy in flight 2026-09-10)

```json
{
  "type": "text",
  "value": "Echo, summarize this",
  "mentions": [
    {
      "id": "018f1234-5678-7abc-8def-0123456789ab",
      "handle": "echo.acme",
      "is_me": false,
      "range": [0, 4]
    }
  ],
  "mention": "echo.acme",
  "mention_range": [0, 4]
}
```

Store Contact IDs, not Handles, because a participant's `id` stays the same after a Handle rename.
`handle` is the participant's current Handle when the message is read.
Branch on `is_me` to decide whether a mention addresses the recipient reading the message, rather than comparing Handles.

Each entry's `range` uses UTF-16 offsets and covers the whole `value` when the send omitted `mention_range`.
The response fields `mention` and `mention_range` are deprecated mirrors of the first entry.
The deprecated `mention_range` stays `null` when omitted on send, and both mirrors are `null` when there is no mention.

## When it fails

Mentions require a group Chat and a target who is still a participant.
Inspect the HTTP status and Relay error code before changing the request.

| Code | HTTP | When | What to do |
| --- | --- | --- | --- |
| [2023](/api-reference/errors#2023) | 409 | The Chat is not a group | Send the mention in a group Chat. |
| [2015](/api-reference/errors#2015) | 409 | The mentioned participant left | Refresh participants and choose a current participant. |
| [1004](/api-reference/errors#1004) | 400 | The Handle is unrelated to the Chat | Use a current participant's Handle. |
