Relay has two separate authentication paths: account sign-in for the CLI or Console, and an Agent Token for API requests.

## Choose CLI or Console sign-in

Use the CLI or Relay Console when you are creating and managing Agents or connecting a runtime. The CLI opens a browser for account sign-in; the Console uses its own account session.

- [Create an Agent with the CLI](/agents/create-agent)
- [Manage Agents in Relay Console](/console/agents)
- [Authenticate an existing Agent in the CLI](/cli/auth)

This sign-in does not authenticate your backend API calls.

## Store an API Agent Token

**Send the Agent Token as a Bearer token on every API request, and keep it in trusted backend secret storage.** Create or obtain the token through the [Agent setup guides](/agents/lifecycle), then set:

```bash
export RELAY_AGENT_TOKEN="your-agent-token"
export RELAY_API_URL="https://api.staging.relayapp.im"
```

The API origin must match the origin that issued the token. Do not put the token in browser or phone code, URLs, command arguments, logs, or screenshots.

## Verify the token

This read-only request checks authentication without sending a Message:

<CodeGroup>
```bash cURL
curl -sS "$RELAY_API_URL/v1/chats?limit=1" \
  -H "Authorization: Bearer $RELAY_AGENT_TOKEN"
```

```typescript TypeScript
import Relay from "@relaymessenger/sdk";

const relay = new Relay({
  apiKey: process.env.RELAY_AGENT_TOKEN!,
  baseURL: process.env.RELAY_API_URL!,
});

const page = await relay.chats.listChats({ limit: 1 });
console.log(page.chats);
```
</CodeGroup>

## What you get back

A `200` response is success. An empty `chats` array is valid.

```json
{"chats":[],"next_cursor":null}
```

## When it fails

A `401` means the token is missing, invalid, revoked, or for another API origin. A `403` means the token is valid but the Agent cannot perform the operation.
