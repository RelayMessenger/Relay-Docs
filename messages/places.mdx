A place is one point on the map, sent once, with an optional name and address. Your agent sends a place to show where something is, and a person sends one to show where they are or where they dropped a pin.

A place does not move. To follow a person while they move, use [location sharing](/chats/location).

## Send a place

Add a `place` part to the message. It can be the only part, or sit beside text:

          {"type":"text","value":"Here is the coffee shop."},

  </Tab>

| Field | Rule |
| --- | --- |
| `latitude` | Required number from -90 to 90, in degrees (WGS 84) |
| `longitude` | Required number from -180 to 180, in degrees (WGS 84) |
| `name` | Optional. 1 to 256 characters after Relay trims it |
| `address` | Optional. 1 to 256 characters after Relay trims it |

The app draws the place as a map card with the name, the address, and **Maps**. With no name, the card says **Dropped Pin**. A tap opens Apple Maps at the point.

Send the body to `POST /v1/chats/{chatId}/messages` ([reference](/api-reference/messages/send-a-message-to-an-existing-chat)). The SDK method is `relay.chats.messages.send`:

<CodeGroup>
```bash cURL
curl -sS -X POST "https://api.staging.relayapp.im/v1/chats/$CHAT_ID/messages" \
  -H "Authorization: Bearer $RELAY_AGENT_TOKEN" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: place-philz-1" \
  -d '{
    "message": {
      "parts": [
        {"type": "text", "value": "Here is the coffee shop."},
        {"type": "place", "latitude": 37.44216251868683, "longitude": -122.16153582049394, "name": "Philz Coffee", "address": "101 Forest Ave, Palo Alto, CA 94301"}
      ]
    }
  }'
```

```typescript TypeScript
import Relay from "@relaymessenger/sdk";

const relay = new Relay({
  apiKey: process.env.RELAY_AGENT_TOKEN!,
  baseURL: "https://api.staging.relayapp.im",
});

const sent = await relay.chats.messages.send(process.env.CHAT_ID!, {
  message: {
    parts: [
      { type: "text", value: "Here is the coffee shop." },
      {
        type: "place",
        latitude: 37.44216251868683,
        longitude: -122.16153582049394,
        name: "Philz Coffee",
        address: "101 Forest Ave, Palo Alto, CA 94301",
      },
    ],
    idempotency_key: "place-philz-1",
  },
});
console.log(sent.message.id);
```
</CodeGroup>

Reuse the same `Idempotency-Key` and body after an uncertain send.

## Receive a place

A person sends a place from the app in two ways:

- **Once**, in the **Share My Location** menu of your agent's [location request](/chats/location), sends where the person is now. No share starts.
- **Location** in the **+** menu of a one-to-one chat with your agent opens a map. The person drops a pin and taps **Send Pin**.

Both arrive as [`message.received`](/events/message-received) with a `place` part. The app adds the address the phone finds for the point, and no name:

      "reactions": null

  </Tab>

The address is Apple's own for the point, as the phone received it. It is absent when the phone finds none, so read `name` and `address` only when they are present.

## What you get back

Relay answers `202` with the stored message. Its `place` part comes back as you sent it, with `reactions`:

```json
{
  "type": "place",
  "latitude": 37.44216251868683,
  "longitude": -122.16153582049394,
  "name": "Philz Coffee",
  "address": "101 Forest Ave, Palo Alto, CA 94301",
  "reactions": null
}
```

A reader that does not draw places, and the push notification, show the place's name, else its address, else `Dropped Pin`. Beside text, those words go on their own line.

## When it fails

| Status | Code | Cause | Next action |
| --- | --- | --- | --- |
| `400` | [`1005`](/error/codes/1xxx/1005) | `latitude` or `longitude` is missing or out of range, `name` or `address` is empty after trimming or over 256 characters, or the part has another field. | Correct the part. |
