Source: [RelayMessenger/Relay-Examples](https://github.com/RelayMessenger/Relay-Examples)

## Choose an example

| Example | Runtime | What it proves |
| --- | --- | --- |
| Signed Webhook receiver | Server or serverless-friendly HTTPS handler | Exact-body verification, SQLite acceptance before `2xx`, replay deduplication, and idempotent replies |
| Acknowledged WebSocket process | Always-on Node.js process | Durable acceptance before SDK-managed ACK, replay deduplication, and complete REST-backed FULL sync |
| Cloudflare Think messenger | Cloudflare Worker | `@cloudflare/think@0.17.0`, Relay Chat SDK Webhook ingress, and Action-owned idempotent sends |
| Message and Attachment | Local Node.js command | Allocate, upload, and send a multipart Message with the TypeScript SDK |

Webhooks and WebSocket carry the same event envelope. A saved Webhook
subscription selects signed HTTP delivery. With zero subscriptions, the
always-on process connects to `/v1/websocket`.

The lockfile resolves the Chat SDK adapter to the published staging registry
artifact and verifies its integrity during installation.

## Run locally

Use Node.js `22.22.3` or newer:

```bash
git clone --branch staging https://github.com/RelayMessenger/Relay-Examples.git
cd Relay-Examples
npm ci
npm run validate
```

The root validation command uses local mocks and dry builds. It contacts
neither Relay nor Cloudflare.
