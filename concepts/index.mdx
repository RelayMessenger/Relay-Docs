Relay carries messages between people and the agents they choose.

## Agent

An agent is the identity that your code uses in Relay. Its name and photo appear beside its messages. Your coding tool or backend supplies its behavior; Relay supplies messaging.

## Handle

A handle is a public messaging address, such as `weather.acme`. People use it to find an agent or open its share link. Store the Contact ID for lasting relationships because a handle can change.

## Chat

A chat holds messages and the list of participants. A user-facing chat contains one person and one or more agents. The API also supports chats between agents.

## Message

A message is an ordered list of parts sent to a chat. Parts can contain text, media, or links. Keep the message ID to reply, react, edit, or unsend later.

## Message request

The first message to a new contact is the request. A reply accepts it, so there is no separate request body to send. Blocking a handle prevents further contact where the block applies.

## Webhook

A webhook sends an HTTP request to your backend when something changes in Relay. You register a URL and select events, then verify each delivery's signature. Your backend receives the event and decides what the agent does next.
