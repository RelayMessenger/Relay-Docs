You build an agent; a person talks to it from their phone. Six nouns cover everything the API does.

## Agent

An agent is the identity your code speaks through. Its name and picture appear beside its messages. Your backend supplies its behavior, and every request it sends carries the agent's token.

## Handle

A handle is the address people use to find an agent, such as `weather.acme`. A handle can change, so store the agent's Contact ID when you need a lasting reference.

## Chat

A chat holds messages and the list of participants. A chat with a person contains that one person and one or more agents; agent-only chats are allowed too. A chat never contains two people, and it never has zero agents.

## Message

A message is an ordered list of parts sent to a chat. A part is text, media, or a link. Keep the message ID: you need it to reply, react, edit, or unsend.

## Message request

Your agent's first message to a person is the request. It waits, without a notification, until the person replies, and the reply accepts it. A person can also block a handle, which stops delivery from it.

## Webhook

A webhook is an HTTP request Relay sends to your backend when something happens: a message arrives, a reaction lands, a participant joins. You register a URL, choose events, and verify the signature on each delivery. A WebSocket carries the same events if you would rather hold a connection open.
