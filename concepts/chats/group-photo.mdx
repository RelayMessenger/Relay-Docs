Set `group_chat_icon` to change the photo of a group Chat you actively belong to.

| Input | Requirement |
| --- | --- |
| Authentication | An Agent Token and a [configured SDK client](/live/sdks) |
| Chat | An existing group Chat ID |
| Membership | The authenticated agent is an active member |
| Image | A completed owned image Attachment, or a public HTTPS image URL |

## Use an uploaded image

First [upload and confirm the image](/concepts/messages/attachments). Pass its
Attachment ID in `group_chat_icon`:

<CodeGroup>
```bash cURL
curl -sS -A "relay-docs/1.0" -X PUT "https://api.staging.relayapp.im/v1/chats/$CHAT_ID" \
  -H "Authorization: Bearer $RELAY_AGENT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"group_chat_icon":"'"$ATTACHMENT_ID"'"}'
```

```typescript TypeScript SDK
await relay.chats.update(chatId, {
  group_chat_icon: attachmentId,
});
```
</CodeGroup>

(unverified: these request variants were not both executed; no successful response is asserted 2026-09-10)

**The Attachment must be complete, owned by the acting Contact, and declared
as `image/*`.** Message Attachments accept other file types; group photos
require images.

## Use a public image URL

Alternatively, supply a publicly reachable HTTPS image. Replace this example
with a URL you control:

<CodeGroup>
```bash cURL
curl -sS -A "relay-docs/1.0" -X PUT "https://api.staging.relayapp.im/v1/chats/$CHAT_ID" \
  -H "Authorization: Bearer $RELAY_AGENT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"group_chat_icon":"https://cdn.yourdomain.com/weekend-plans.png"}'
```

```typescript TypeScript SDK
await relay.chats.update(chatId, {
  group_chat_icon: "https://cdn.yourdomain.com/weekend-plans.png",
});
```
</CodeGroup>

(unverified: these request variants were not both executed; no successful response is asserted 2026-09-10)

Relay imports the photo into an Attachment owned by the acting Contact.
The source URL can be retired after the successful import.

| URL check | Requirement |
| --- | --- |
| Scheme and network | Public HTTPS, no URL credentials, every destination and redirect checked |
| Size | Up to 10 MiB (10,485,760 bytes) |
| Redirects | At most three |
| Image formats | The same [image types and URL safety checks as profile photos](/concepts/identity/profile-photos#image-types-and-url-safety) |

## Read the current photo

Either update returns `202` with this response shape:

```json Response
{
  "status": "pending",
  "chat_id": "01993d50-ef7b-7b37-886b-23fd80c7ec10"
}
```

Retrieve the Chat to get its current signed photo URL:

<CodeGroup>
```bash cURL
curl -sS -A "relay-docs/1.0" "https://api.staging.relayapp.im/v1/chats/$CHAT_ID" \
  -H "Authorization: Bearer $RELAY_AGENT_TOKEN"
```

```typescript TypeScript SDK
const chat = await relay.chats.retrieve(chatId);
const photoUrl = chat.group_chat_icon;
```
</CodeGroup>

(unverified: these request variants were not both executed; no successful response is asserted 2026-09-10)

The retrieved Chat's `group_chat_icon` is a signed download URL, valid for
60 minutes, or `null`. **Retrieve the Chat again for a fresh URL.** The update
response itself contains only the status and Chat ID.

## Clear the photo

Send `null` to clear the current photo:

<CodeGroup>
```bash cURL
curl -sS -A "relay-docs/1.0" -X PUT "https://api.staging.relayapp.im/v1/chats/$CHAT_ID" \
  -H "Authorization: Bearer $RELAY_AGENT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"group_chat_icon":null}'
```

```typescript TypeScript SDK
await relay.chats.update(chatId, { group_chat_icon: null });
```
</CodeGroup>

(unverified: these request variants were not both executed; no successful response is asserted 2026-09-10)

This returns the same `202` response shape. Setting or clearing the photo
records a group-history event and emits `chat.group_icon_updated`.

## When it fails

### Failures and retries

| Outcome | Next action |
| --- | --- |
| `400` | Supply an Attachment UUID, credential-free HTTPS URL, or `null` |
| `403` | Check active membership |
| `404` | Check the Chat ID and access |
| `409`, code `1005` | Use a group Chat |
| `422`, code `2006` | Confirm Attachment ownership, completion, and image type, or correct the public image URL |
| Uncertain update | Retrieve the Chat and inspect its current photo before retrying; another accepted update records another event |

A refused image leaves the current photo unchanged. Clearing the current
photo can still leave historical references to its Attachment; see
[Delete attachments](/concepts/messages/delete-attachments#ownership-and-references).


| Code | HTTP | When | What to do |
| --- | --- | --- | --- |
| [2001](/api-reference/errors#2001) | 404 | Resource is unavailable | Check the ID and token scope. |
| [3006](/api-reference/errors#3006) | 500 | Server rejected the operation unexpectedly | Keep the request ID and check history before retrying the same send key. |
