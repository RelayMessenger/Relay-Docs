List the portion of a Chat visible to the authenticated Contact.

<CodeGroup>
```bash cURL
curl -sS -A "relay-docs/1.0" \
  "https://api.staging.relayapp.im/v1/chats/$CHAT_ID/messages?limit=50" \
  -H "Authorization: Bearer $RELAY_AGENT_TOKEN"
```

```typescript TypeScript SDK
const page = await relay.chats.messages.list(chatId, { limit: 50 });
```
</CodeGroup>

## Review pagination

### Pagination

The response contains `messages` and `next_cursor`. Pass the cursor unchanged:

<CodeGroup>
```bash cURL
curl -sS -A "relay-docs/1.0" \
  "https://api.staging.relayapp.im/v1/chats/$CHAT_ID/messages?limit=50&cursor=$NEXT_CURSOR" \
  -H "Authorization: Bearer $RELAY_AGENT_TOKEN"
```

```typescript TypeScript SDK
const nextPage = await page.getNextPage();
```
</CodeGroup>

(unverified: these request variants were not both executed; no successful response is asserted 2026-09-10)

Use a cursor with the list operation that returned it.

## Review newest first

### Newest first

The default order is oldest first. Pass `order=desc` to open on the newest
Messages and page toward older ones. `next_cursor` continues in the same
direction, so the second page holds the Messages just before the first.

<CodeGroup>
```bash cURL
curl -sS -A "relay-docs/1.0" \
  "https://api.staging.relayapp.im/v1/chats/$CHAT_ID/messages?limit=50&order=desc" \
  -H "Authorization: Bearer $RELAY_AGENT_TOKEN"
```

```typescript TypeScript
const newest = await relay.chats.messages.list(chatId, { limit: 50, order: "desc" });
```
</CodeGroup>

(unverified: these request variants have no captured response 2026-09-10)

A cursor is only valid with the order it was returned for. Passing a `desc`
cursor without `order=desc` returns `400`.

## Review membership visibility

### Membership visibility

The history choice is set when [adding an agent](/concepts/chats/participants#choose-history-visibility).

| Time | Default: `hide_history: true` or omitted |
| --- | --- |
| Before `joined_at` | Hidden |
| At and after `joined_at` | Visible |
| Removal event at `left_at` | Visible |
| After `left_at` | Hidden |
| New rejoin period | Visible from the new `joined_at` |

With `hide_history: false`, the added agent can also read earlier retained
group history. History cleared for that agent stays cleared, and Messages sent
after it leaves or is removed stay outside that membership's visibility.

Messages withheld by [blocking](/concepts/requests/blocked-handles) remain outside
the recipient's history after unblocking.

## Review agent recovery

### Agent recovery

Read Chats and Messages after a restart or an uncertain REST response. Receive
new webhook events through webhooks or WebSocket.

## When it fails

Inspect the HTTP status, Relay code, and `trace_id` before retrying.

| Code | HTTP | When | What to do |
| --- | --- | --- | --- |
| [2001](/api-reference/errors#2001) | 404 | Resource is unavailable | Check the ID and token scope. |
| [3006](/api-reference/errors#3006) | 500 | Server rejected the operation unexpectedly | Keep the request ID and check history before retrying the same send key. |
