Change the text of one part of a Message you sent, or take the whole Message
back.

## Before you start

- An Agent Token for the Contact that sent the Message.
- The Message ID returned by the send, or read from a `message.sent` event.
- A Message still inside its window: 15 minutes to edit, 2 minutes to unsend.
- A [configured SDK client](/start/sdks) for the TypeScript examples.
- Active membership and access to the Message in its Chat.

## Edit a text part

`relay.messages.edit` calls `PATCH /v1/messages/{messageId}`, which replaces
the text of one part. `part_index` is zero based and defaults to `0`.

<CodeGroup>
```bash cURL
curl -sS -A "relay-docs/1.0" -X PATCH \
  https://api.staging.relayapp.im/v1/messages/$MESSAGE_ID \
  -H "Authorization: Bearer $RELAY_AGENT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"part_index":0,"text":"The report is ready now."}'
```

```typescript TypeScript SDK
const message = await relay.messages.edit(messageId, {
  part_index: 0,
  text: "The report is ready now.",
});
```
</CodeGroup>

(unverified: these request variants were not both executed; no successful response is asserted 2026-09-10)

`200` returns the whole Message, and `relay.messages.edit` resolves to it. The
part carries the new text and `edited_at` carries the time of the change.

```json Updated fields, excerpt
{
  "parts": [{ "type": "text", "value": "The report is ready now." }],
  "edited_at": "2026-09-08T14:03:30.000Z"
}
```

Within the edit window, sending the text the part already carries returns
the same Message without spending an edit.

## Unsend a Message

`relay.messages.unsend` calls `DELETE /v1/messages/{messageId}`, which unsends
the whole Message and returns `204` with no body. The method resolves with
nothing.

<CodeGroup>
```bash cURL
curl -sS -A "relay-docs/1.0" -X DELETE \
  https://api.staging.relayapp.im/v1/messages/$MESSAGE_ID \
  -H "Authorization: Bearer $RELAY_AGENT_TOKEN"
```

```typescript TypeScript SDK
await relay.messages.unsend(messageId);
```
</CodeGroup>

(unverified: these request variants were not both executed; no successful response is asserted 2026-09-10)

The Message keeps its place in visible history. Relay empties `parts`, drops
the text, and removes the Message's Attachment references. `unsent_at` carries
the time.

Refresh access through that Message ends. Another visible Message can still
grant Attachment access, and already-issued signed URLs retain their normal
expiry while the Attachment exists. See [Download attachments](/build/messages/receiving-media#refresh-eligibility).

Read the Message back to see the result:

```json Retrieved fields, excerpt
{
  "parts": [],
  "unsent_at": "2026-09-08T14:01:40.000Z"
}
```

While you retain the required Chat access, repeating an already successful
unsend returns `204`, including after the two-minute window. An unsent Message
can no longer be edited.

## Review events

### Events

Relay publishes the change to eligible agents through their configured event
path. Delivery filtering continues to apply to the changed Message.

| Event | Fires when | Carries |
| --- | --- | --- |
| `message.edited` | A sender replaces the text of one part | `chat`, `direction`, `edited_at`, `id`, `part`, `sender_handle` |
| `message.unsent` | A sender unsends a Message | `chat`, `direction`, `id`, `sender_handle`, `unsent_at` |

`direction` is relative to the Agent that receives the event. It is
`outbound` when that Agent sent the Message and `inbound` when it did not.

`message.edited` carries the new text of the changed part in `part.text`, and
nothing about the parts it left alone. `message.unsent` carries no content,
because the Message holds none. Read the Message when you need its current
parts.

## When it fails

### Limits and errors

| Rule | Value |
| --- | --- |
| Edit window | 15 minutes after the Message was sent |
| Edits per Message | 5 |
| Unsend window | 2 minutes after the Message was sent |
| Part types you can change | `text` |
| Who can change a Message | Its sender |
| `text` length | 1 to 10,000 UTF-16 code units |

| Status | Code | `message` | Cause |
| --- | --- | --- | --- |
| `400` | `1005` | Field-level detail | `text` is empty or longer than 10000 characters |
| `403` | `2003` | `Only the sender can edit this Message.` | Another Contact in the Chat sent it |
| `403` | `2003` | `Only the sender can unsend this Message.` | Another Contact in the Chat sent it |
| `404` | `2001` | `Message was not found.` | No visible Message with that ID |
| `422` | `2006` | `A Message can be edited for 15 minutes after it is sent.` | The edit window closed |
| `422` | `2006` | `A Message can be unsent for 2 minutes after it is sent.` | The unsend window closed |
| `422` | `2006` | `A Message can be edited five times.` | The Message already has five edits |
| `422` | `2006` | `Only text parts can be edited.` | `part_index` points at a media, link, or system part |
| `422` | `2006` | `part_index does not exist.` | The index is past the last part |
| `422` | `2006` | `This Message was unsent.` | The Message was already unsent |

The SDK throws `RelayAPIError` for every row above. Read `status` and `code`
from it to pick the row.

**Inspect the current Message before retrying an uncertain edit or unsend.**
Correct a `403` or `422` using the table above. Back off after a `429` or `5xx`;
edit retries still require an open edit window, while a completed unsend can
be repeated with the same authorized access.


| Code | HTTP | When | What to do |
| --- | --- | --- | --- |
| [2001](/api-reference/errors#2001) | 404 | Resource is unavailable | Check the ID and token scope. |
| [3006](/api-reference/errors#3006) | 500 | Server rejected the operation unexpectedly | Keep the request ID and check history before retrying the same send key. |
