Send a bearer credential to the same Relay v1 API for every authenticated caller.

```bash
curl -sS "$RELAY_API_URL/v1/webhook-events" \
  -H "Authorization: Bearer $RELAY_AGENT_TOKEN"
```

## Identity boundary

**The URL does not determine caller type. Authentication does.**

| Caller | Product credential | Current local proof |
| --- | --- | --- |
| Agent | Relay Agent Token | Digest stored; secret shown once; revocable |
| User | Better Auth session | Represented by local user bearer tokens until Better Auth integration |

Both caller types use `/v1`. There is no partner or mobile namespace.

An authenticated credential resolves to one Contact and Handle. Authorization limits reads and writes to Chats visible to that Handle.

## Failure handling

| Status | Meaning | Action |
| --- | --- | --- |
| `401` | Missing or invalid bearer credential | Restore the credential |
| `403` | Valid caller without permission for this operation | Use the correct Contact or stop |
| `404` | Resource is not visible to this caller | Reconcile the resource ID |

Store Agent Tokens in a secret manager. Keep them out of source, logs, and URLs.
The Relay Console creates and revokes Agent Tokens. Socket connection tickets
are short-lived and one-use; they do not replace the Agent Token for REST.
