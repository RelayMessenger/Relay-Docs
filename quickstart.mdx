Register a webhook, receive one `message.received` event, and send one reply.

## Before you start

| Requirement | Source |
| --- | --- |
| Agent Token | Relay shows it once when you create the agent |
| Public HTTPS endpoint | Your backend |
| Signing secret | Returned when you create the webhook subscription |

```bash
export RELAY_API_URL="https://api.relayapp.im"
export RELAY_AGENT_TOKEN="rly_live_..."
```

## Verify the token

```bash
curl -sS "$RELAY_API_URL/v1/agents/me" \
  -H "Authorization: Bearer $RELAY_AGENT_TOKEN"
```

## Receive and reply

<Steps>
  <Step title="Register the receiver">
    ```bash
    curl -sS -X POST "$RELAY_API_URL/v1/webhooks" \
      -H "Authorization: Bearer $RELAY_AGENT_TOKEN" \
      -H "Content-Type: application/json" \
      -d '{
        "url": "https://agent.example/webhooks/relay",
        "events": ["message.received"]
      }'
    ```

    Store the returned `signing_secret`. The list and retrieve responses do
    not return its plaintext.
  </Step>

  <Step title="Verify and persist the event">
    Relay signs the raw request body with Standard Webhooks headers. Verify
    before parsing, insert `event_id` under a unique constraint, and return
    `2xx` before model or tool work.

    ```ts
    import { Webhook } from "standardwebhooks";

    const rawBody = await request.text();
    const event = new Webhook(process.env.RELAY_SIGNING_SECRET!).verify(
      rawBody,
      {
        "webhook-id": request.headers.get("webhook-id") ?? "",
        "webhook-timestamp": request.headers.get("webhook-timestamp") ?? "",
        "webhook-signature": request.headers.get("webhook-signature") ?? "",
      },
    );
    ```

    The body is Linq's v3 shape:

  </Step>

  <Step title="Mark Read and show typing">
    ```bash
    curl -sS -X POST \
      "$RELAY_API_URL/v1/chats/cnv_01JZC7K4RQ/read" \
      -H "Authorization: Bearer $RELAY_AGENT_TOKEN" \
      -H "Content-Type: application/json" \
      -d '{"message_id":"msg_01JZM3T8AH"}'
    ```

    ```bash
    curl -sS -X POST \
      "$RELAY_API_URL/v1/chats/cnv_01JZC7K4RQ/typing" \
      -H "Authorization: Bearer $RELAY_AGENT_TOKEN" \
      -H "Content-Type: application/json" \
      -d '{"started":true}'
    ```
  </Step>

  <Step title="Send the reply">
    Mint the reply's `message_id` before the first attempt and reuse it on
    retry.

    ```bash
    curl -sS -X POST "$RELAY_API_URL/v1/messages" \
      -H "Authorization: Bearer $RELAY_AGENT_TOKEN" \
      -H "Content-Type: application/json" \
      -d '{
        "message_id": "msg_01k1m4q9vn2r7t9b4c6qdh8xwy",
        "chat_id": "cnv_01JZC7K4RQ",
        "parts": [{ "type": "text", "text": "Tomorrow at 2:00 PM works." }]
      }'
    ```

    Stop typing after send, failure, or cancellation.
  </Step>
</Steps>

## Failure and retry behavior

| Failure | Action |
| --- | --- |
| Invalid signature | Return `401` and do not process the body |
| Duplicate `event_id` | Return `2xx` without repeating side effects |
| Relay returns `429` or `5xx` | Retry with backoff and the same `message_id` |
| Relay returns another `4xx` | Fix the request or token before retrying |
| Handler needs more than 10 seconds | Persist, return `2xx`, then continue |
